# Локальная база знаний DnD Share

Документация проекта живёт в `README.md` и `.contextshare/wiki/`. ContextShare читает их
из текущего worktree и возвращает относительный путь, строки и связи. Страницы
редактируются через `write_wiki_document` по SHA-256 из `get_wiki_document`. Отчёты
из `.contextshare/wiki/reports/` относятся к истории. Актуальность установленной сборки
проверяется по источнику выпуска.

- `project.json` задаёт секции, границы путей и идентификатор проекта.
- `notes/` хранит самостоятельные заметки и подтверждения по платформам.
- `links.json` хранит связи между заметками и страницами документации.
- `requests/` хранит заявки и отдельные части работы по платформам.

Подключение в локальном Codex запускает `contextshare.exe local --project <worktree>`
через stdio. SQLite-индекс размещается в Git-каталоге этого worktree и
перестраивается при изменении источников.

Для продолжения работы вызови `select_worktree` с абсолютным путём копии задачи
и передавай возвращённый `project_id` в последующие команды. Затем вызови `get_project_overview`,
для поиска используй `search` и раскрывай нужную ноду через `get_node`.
Вложения доступны через `get_wiki_attachment`, типизированные связи через
`set_wiki_link`. Перед коммитом запусти `validate_wiki`.
Поля `source_path` и `code_paths` связывают знание с исходниками.
Определения и использования ищи через `rg`, а сигнатуры и связи сверяй
с исходниками.

Путь, ветка, commit и локальные изменения указаны в `workspace` ответа.
Поиск показывает действующие материалы выбранной копии по умолчанию.
Историю открывай с `status=historical` или `status=all`.

Журналы производства фиксируют дату, объект, подготовку, приёмку и результат
публикации. Прикладывай манифест, контрольную сумму или подтверждённые UUID и
версию. Очередь и записи проверяются при слиянии веток.
