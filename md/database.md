PostgreSQL принадлежит Go-бэкенду. Источник структуры — файлы
`internal/store/schema/*.sql`, встроенные в бинарь и упорядоченные по имени.
Они содержат только DDL: таблицы, колонки, ограничения, индексы, расширения и
определения runtime-функций/триггеров. Системы, редакции, роли, шаблоны,
метаданные полей и содержимое справочника являются данными и не создаются
миграциями.

## Выполнение и переход

`schema.go` выполняет отсутствующие в `dndshare.schema_migration` определения
одной транзакцией до запуска HTTP. PostgreSQL advisory lock сериализует
параллельные старты; checksum защищает уже применённый SQL. `schema_sql.go`
проверяет DDL до обращения к БД: DML, CTE с данными, COPY, TRUNCATE, DO/CALL,
CREATE TABLE AS и materialized view без WITH NO DATA не допускаются.
Лексер учитывает строки, комментарии и тела функций, поэтому определение
триггера отделяется от исполнения операций с данными.

База `000_*.sql` снята с актуальной структуры PostgreSQL 18.6 и не содержит
строк каталогов или преобразований прежних форматов. Она создаёт пустую схему;
наполнение новой БД выполняется отдельно через MCP или явный импорт данных.
Расширение `pg_trgm` необходимо для существующих индексов поиска.

У существующей БД проверяется маркер `static-media-s3` с зафиксированным checksum
последнего прежнего выпуска. `schema_baseline.go` записывает только служебные
маркеры `000_` без выполнения определений поверх имеющихся таблиц. Старые записи
журнала сохраняются. Неполная или неподтверждённая база останавливает запуск.
Следующие старты проверяют checksum структурных файлов. Исторические seed,
исправления записей и Go-конвертеры не входят в приложение.

## Правила изменения

1. Добавить следующий файл `001_<name>.sql`, затем `002_...` и далее; порядок
   зависимостей задаётся именем файла. `000_` и применённые файлы не менять.
2. В SQL включать только структурные определения. Изменения `item.data`,
   `item_type.fields`, описаний, медиа, каталогов и форматов документов выполнять
   отдельной явно запускаемой операцией с данными, до перехода потребителей.
3. Runtime читает только текущий формат. Согласовать отдельное преобразование
   данных и структурный deploy; затем удалить прежние поля и runtime fallback.
4. Обновить документацию и тестовые фикстуры текущего контракта. Фикстуры тестов
   содержат собственные данные и не запускают исторические миграции.
5. Выполнить проверки из README. `DNDSHARE_TEST_DSN` включает тесты
   создания пустой структуры, принятия существующей БД с сохранением всех строк,
   checksum, параллельных стартов и отказа от DML. Допускается только локальная
   изолированная база с префиксом `dndshare_test_`.
6. Readiness должен подтвердить выпущенный commit. Регистрация migrator меняет
   только `schema_migration`; пользовательские данные не заполняются и не
   исправляются при применении схемы.

Миграция `013_item_models.sql` добавляет таблицу-связку `item_model`
между `item` и `map_model`: несколько вариантов, один основной, общие файлы.
См. [модели итемов](features/item-models.md). Данные через MCP, без startup seed.
