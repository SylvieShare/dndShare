# Производительность frontend

## Единая production-сборка — 1 октября 2026

После частых deploy открытая вкладка могла запрашивать JS страницы из прежней
сборки и получать `Failed to fetch dynamically imported module`. Production
теперь отключает `rolldownOptions.output.codeSplitting` и `cssCodeSplit`:
все страницы, редакторы, галерея UI и PixiJS входят в один JS и один CSS.
Динамические импорты в исходниках сохраняются, но в выходном JS нет сетевых
`import()`. Монтирование компонентов при открытии и перерисовка карты по
изменениям сохраняются.

Сравнение с чистой сборкой `2e42c0f4` на тех же зависимостях:

| Метрика | Разделённая сборка | Единая сборка |
|---|---:|---:|
| Стартовый JS + CSS, gzip | 158 784 Б | 1 172 003 Б |
| Все JS + CSS, gzip | 1 218 759 Б | 1 172 003 Б |

Начальная загрузка выросла примерно в 7,4 раза; общий gzip снизился на 3,8%.
Это сознательная плата за отсутствие запросов дополнительных чанков во время
навигации. Общий бюджет остаётся 1 250 000 Б; начальный теперь равен ему,
поскольку весь JS/CSS загружается сразу. `check:bundle` также проверяет ровно
один JS и один CSS, отсутствие ссылок на другие чанки в manifest и равенство
начального и полного размеров. Self-reference `dynamicImports` на тот же
выходной файл допустим: Vite сохраняет его в manifest после inlining.

Бюджеты измеряются через `gzipSync` с уровнем по умолчанию; сервер отдаёт
sidecar с уровнем 9 (единый JS + CSS вместе — 1 167 514 Б).
Предупреждение Vite о размере JS больше 500 КБ ожидаемо и не скрывается.
HTML остаётся `no-cache`, файлы с хэшем — `immutable`; deploy сохраняет архив
старых ресурсов. Вкладкам, открытым до изменения, нужна одна перезагрузка.

Проверки: 359 файлов / 1589 frontend-тестов, production build и Go test/build/vet.

## 3D-карты — 4 октября 2026

PixiJS заменён на Three.js и встроенный Meshopt-декодер. Бюджет единого JS + CSS
остаётся 1 250 000 Б gzip; разделение кода выключено. Файлы моделей, текстур и
превью загружаются из S3 через API по необходимости и в bundle не входят.
Рендер по изменениям, InstancedMesh по моделям/пространственным чанкам и
облегчённая геометрия при небольшом масштабе ограничивают нагрузку сцены.
Кеш моделей разделяется между открытыми canvas с подсчётом владельцев ресурсов.
