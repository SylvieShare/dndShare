Главный эффект дают загрузка страниц по запросу, ограниченное окно DOM длинного списка и отложенная запись снимков. Сокращение отдельных обёрток и очистка CSS дают меньший выигрыш, но упрощают оформление. Общий gzip всей сборки вырос: отдельные chunks сжимаются независимо и добавились общие компоненты. Стартовый граф не равен полной загрузке страницы персонажа; строка персонажа включает её статические зависимости вместе со стартовыми. Картинки, шрифты, API и открываемые позже редакторы в эти размеры не входят.

## Методика и границы

Одинаковая production-фикстура, Chromium 153.0.8010.12, CPU slowdown ×4, viewport списка 1000×850, сам список 800×640; мобильный лист 390×844. По пять повторов после прогрева, времена — медианы. Отрисовка включает Vue nextTick и два requestAnimationFrame, поэтому имеет нижнюю границу около двух кадров. Это синтетический замер на одном компьютере, а не FPS, LCP, INP или время реальной сетевой загрузки.

Для снимков меняется имя в объекте 272 344 Б: 50 изменений с паузой 5ms. Измеряется CPU реальных функций записи/планирования и финального flush, без времени пауз и без всей реактивной цепочки редактора. В каждом повторе обе версии сохраняют последнее имя «Персонаж 49». Мобильный лист получает минимальный фиксированный набор данных; в реальном листе абсолютное число DOM-элементов зависит от содержимого. В результатах нет pageerror.

Размеры получены из production-файлов и Vite manifest: начальные script/stylesheet из HTML плюс транзитивные статические imports/CSS. Для маршрутов добавляется их граф зависимостей без повторного учёта общих файлов. До изменения весь JS/CSS загружался единым набором. Gzip рассчитан тем же алгоритмом, которым создаются sidecar-файлы для Go-сервера.

Исходные результаты: [до](measurements/frontend-2026-09-14-before.json), [после](measurements/frontend-2026-09-14-after.json).

Повторный запуск из `frontend`: `npm run benchmark -- target/performance.json`. Требуется установленный Chromium Playwright (`npx playwright install chromium`); при отдельном каталоге браузеров задаётся `PLAYWRIGHT_BROWSERS_PATH`. Для сравнения с исходным commit нужна отдельная копия checkout с его зависимостями и одинаковыми `scripts/benchmark-frontend.mjs`, `tests/performance/fixture.html`, `fixture.js` из итогового изменения. Старый snapshot API вызывается только сравнительной фикстурой через Reflect; production использует новый recorder.

## Реализованные изменения

- Удалены 65 подтверждённых CSS-правил исходного аудита, пять неприменимых правил анимации заклинаний, устаревшие селекторы заголовков и orphan stylesheet AdminErrorReports. Стили DndItems больше не компилируются трижды: у строки и skeleton свои необходимые правила.
- Убраны внешние слои пяти CoverSummary, InputSuggest, IconPicker, строки справочника и EncounterRowMenu. Корни плиток принимают нужные attrs; пустые стили и лишние vars не передаются. Неработавшие директивы на Fragment заменены передачей display видимому корню. Контейнеры, нужные для scroll, morph, ширины и позиционирования, сохранены.
- В share-ui добавлены StatBar, IconPicker, DetailSection, ContentRow, OptionList, SearchMultiSelect, FloatingTooltip и useVirtualList. Доменные данные, HTTP, права и сохранение остаются в приложении; новые компоненты имеют типы, документацию и галерею. Кнопки добавления и поля копирования используют существующие примитивы.
- Списки более 80 строк используют окно с запасом и измеряемыми высотами. Все данные, группы и пагинация доступны; сфокусированная строка сохраняется при прокрутке. Индексы suggest разделяются между строками и обновляются при реактивных изменениях.
- Мобильные вкладки монтируются при первом посещении и сохраняются. Снимки и черновик объединяют изменения за 300ms, максимум ожидания 1000ms; pagehide/visibility hidden/unmount выполняют flush, очистка черновика отменяет pending запись.
- Router использует lazy imports, CSS разделён по chunks, JS/CSS имеют gzip sidecar. Deploy сохраняет старые hashed assets для уже открытых вкладок. HTML использует no-cache, static — immutable. Missing static возвращает 404.
- Крупные wizard, graph и CSS/layout-файлы разделены по ответственности. Во всём проверенном наборе handwritten JS/Vue/CSS/JSON frontend/src больше нет файлов длиннее 600 строк.
- Build проверяет бюджеты: initial gzip ≤160000 Б, total gzip ≤1005000 Б. Предупреждение Vite о chunk >500 КБ остаётся у общих зависимостей редактора; оно не скрыто увеличением лимита.

## Проверки

1436 frontend-тестов; 47 Playwright-сценариев персонажа, передачи предметов, morph, бросков и обучения; четыре новых сценария выбора/tooltip/виртуализации. После удаления неработавшего TransitionGroup повторно пройдены 18 сценариев заклинаний без предупреждений Vue. Backend: go test, build и vet; отдельные тесты current/retained static, gzip, MIME, cache и 404. Share-ui: 124 теста, build/check, gallery coverage и npm pack --dry-run. Проверены изолированные сборки HavenShare и TrenchShare, 170 тестов TrenchShare; их рабочие проекты не изменены.

Не измерялись GPU, потребление памяти длительной сессии и реальные пользовательские web-vitals. Кэш старых файлов на сервере сохраняется без автоматического удаления и требует контроля объёма при обслуживании.
