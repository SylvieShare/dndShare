# Производительность frontend

## Единая production-сборка — 1 октября 2026

После частых deploy открытая вкладка могла запрашивать JS страницы из прежней
сборки и получать `Failed to fetch dynamically imported module`. Production
теперь отключает `rolldownOptions.output.codeSplitting` и `cssCodeSplit`:
все страницы, редакторы, галерея UI и PixiJS входят в один JS и один CSS.
Динамические импорты в исходниках сохраняются, но в выходном JS нет сетевых
`import()`. Монтирование компонентов при открытии и перерисовка карты по
изменениям сохраняются.

Сравнение с чистой сборкой `2e42c0f4` на тех же зависимостях:

| Метрика | Разделённая сборка | Единая сборка |
|---|---:|---:|
| Стартовый JS + CSS, gzip | 158 784 Б | 1 172 003 Б |
| Все JS + CSS, gzip | 1 218 759 Б | 1 172 003 Б |

Начальная загрузка выросла примерно в 7,4 раза; общий gzip снизился на 3,8%.
Это сознательная плата за отсутствие запросов дополнительных чанков во время
навигации. Общий бюджет остаётся 1 250 000 Б; начальный теперь равен ему,
поскольку весь JS/CSS загружается сразу. `check:bundle` также проверяет ровно
один JS и один CSS, отсутствие ссылок на другие чанки в manifest и равенство
начального и полного размеров. Self-reference `dynamicImports` на тот же
выходной файл допустим: Vite сохраняет его в manifest после inlining.

Бюджеты измеряются через `gzipSync` с уровнем по умолчанию; сервер отдаёт
sidecar с уровнем 9 (единый JS + CSS вместе — 1 167 514 Б).
Предупреждение Vite о размере JS больше 500 КБ ожидаемо и не скрывается.
HTML остаётся `no-cache`, файлы с хэшем — `immutable`; deploy сохраняет архив
старых ресурсов. Вкладкам, открытым до изменения, нужна одна перезагрузка.

Проверки: 359 файлов / 1589 frontend-тестов, production build и Go test/build/vet.

## 3D-карты — 4 октября 2026

PixiJS заменён на Three.js и встроенный Meshopt-декодер. Бюджет единого JS + CSS
остаётся 1 250 000 Б gzip; разделение кода выключено. Файлы моделей, текстур и
превью загружаются из S3 через API по необходимости и в bundle не входят.
Рендер по изменениям, InstancedMesh по моделям/пространственным чанкам и
облегчённая геометрия при небольшом масштабе ограничивают нагрузку сцены.
Кеш моделей разделяется между открытыми canvas с подсчётом владельцев ресурсов.

## Справочник параметров тайлов — 6 октября 2026

3D-превью параметров в справочнике переиспользует загрузчик GLB и Three.js редактора
карты. Дополнение измерено без новых vendor-библиотек: около 7 КиБ gzip,
общий JS + CSS — 1 250 445 Б. После разбора состава bundle лимит увеличен
до 1 260 000 Б; схема одной начальной загрузки сохраняется.

## Источники света и солнце — 6 октября 2026

Точечные источники и солнце используют существующий WebGLRenderer и PBR-материалы
Three.js. Новых vendor-библиотек нет. Первичная версия с ExtrudeGeometry дала
1 273 469 Б gzip; замена общего extrusion/bevel pipeline на закрытые призмы
контуров снизила размер до 1 267 674 Б. Новая вкладка, поля, привязки и управление
светом требуют около 8,4 КиБ относительно предыдущей сборки. Бюджет единого JS/CSS
увеличен до 1 275 000 Б после разбора импортов; разделение кода остаётся выключенным.

Дополнительные проходы работают только при `lightingEnabled=true`. В выключенном
режиме восстановлен прежний постоянный свет: локальные источники удалены из сцены,
shadow map выключена, мерцание не запускает перерисовку.
Модели принимают тени; отдельная геометрия assets.shadow выступает как shadow
caster. Она загружается только при включённом освещении и группируется по моделям
в InstancedMesh. Геометрия разделяется между экземплярами и canvas; её текстуры
не используются. При совпадении shadow и LOD API возвращает один URL.
Контуры препятствий и bounding boxes для теней не используются: они перекрывали
свет внутри ступеней, чаш и скруглённых объектов.
Солнце использует карту 1024², до двух локальных источников — cube maps 512².
Перемещение моделей/света и изменение солнца обновляют тени; мерцание меняет только
яркость. Без движения сцены обновление мерцания ограничено 10 кадрами/с, а обычный
рендер остаётся по изменениям. Число активных локальных источников ограничено восемью,
выбор отдаёт приоритет выделенному, источникам с тенями и близости к центру обзора.

Проверка `lightingBenchmark.spec.js` загружает 324 настоящие GLB-плитки Lost Cave.
Headless Chromium в этом окружении использует ANGLE/SwiftShader: программный GPU
LLVM/Vulkan. Начальный непрерывный вариант дал медиану интервала около 1,42 с;
это выявляет дорогую программную отрисовку, но не является оценкой FPS аппаратного
браузера пользователя. Замер фиксирует renderer, число кадров и p95; тест проверяет
ошибки загрузки/шейдеров и не обещает универсальную частоту кадров.

## Геометрия теней — 6 октября 2026

Подготовлены 337 отдельных shadow GLB из локальных LOD: 10 922 184 Б вместе
вместо 334 317 668 Б файлов LOD с текстурами. Треугольники сохраняются, удаляются
материалы, текстуры, UV и нормали; Meshopt сжимает позиции и индексы. Пакет не
загружается целиком: запрашиваются только модели открытой карты с освещением.
Теневые экземпляры объединяются по модели и чанкам 8×8; normal color pass
пропускает их геометрию. Shadow maps сохраняются между изменениями сцены.

Browser-проверка настоящих UD-022, UD-042 и сундука сравнивает освещённые
поверхности с тенями и без них при четырёх направлениях высокого солнца и
точечном свете. Коробчатая контрольная геометрия снижает яркость выбранных
поверхностей до 34–49% эталона; настоящий shadow GLB сохраняет 97–100%.
Это проверка ложного перекрытия свету, а не запрет естественных теней.
Тест требует локальных моделей и пропускается в checkout без models/.

## KTX2 — 6 октября 2026

Общий загрузчик карты и превью добавляет KTX2Loader. Начальный JS + CSS
составляет 1 292 182 Б gzip: около 24 КиБ сверх версии без KTX2. Лимит
приложения — 1 310 000 Б; один JS и CSS, без чанков страниц, сохраняются.
Basis transcoder worker JS и WASM — отдельные хешированные файлы,
259 653 Б gzip вместе. Они запрашиваются только при загрузке KTX2-модели;
для них установлен отдельный бюджет 270 000 Б. Проверка разрешает только
эти два vendor-ресурса с ожидаемыми src в manifest и продолжает отклонять
другие JS chunks.

[MH-001](features/majestic-highlands.md) проверен в обеих версиях:
KTX2 транскодируется в сжатые GPU-текстуры с mipmaps, albedo — sRGB.
Общий декодер переиспользуется canvas с одинаковыми GPU-возможностями.
Подсчёт владельцев и ожидающих загрузок сохраняет worker до завершения
очереди, даже если исходный canvas закрыт.
