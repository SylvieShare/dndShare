# Аудит магии при мультиклассировании

Проверка относится к D&D 5e 2014. Автоматика даёт короткий путь по правилам,
но владелец может отключить расчёт ячеек, создать пользовательскую вкладку и
вручную изменить её параметры.

## Реализовано

- Обычные ячейки образуют один общий пул. Уровни барда, жреца, друида,
  чародея и волшебника складываются полностью; паладина и следопыта — по
  половине с округлением вниз; Мистического рыцаря и Мистического ловкача — по
  трети с округлением вниз. Вклад изобретателя округляется вверх.
- Единственный класс с `Spellcasting` использует собственную таблицу ячеек,
  даже если рядом есть немагический класс или колдун с `Pact Magic`.
- Все ячейки находятся над вкладками и разделены только по восстановлению:
  `long_rest` восстанавливается после долгого отдыха, `short_rest` — после
  короткого или долгого. Магия договора автоматически наполняет короткий пул,
  но любое заклинание можно сотворить ячейкой из любого подходящего пула.
- Доступный круг выбора считается по уровню конкретного класса, не по общему
  пулу. Следопыт 4 / волшебник 3 имеет ячейки 3 круга, но не изучает
  заклинания 3 круга ни от одного из этих классов.
- Интерфейс всегда использует вкладки — при одном классе, нескольких классах и
  полностью ручной магии. Владелец может создать вкладку, задать имя,
  характеристику, режим `known` / `prepared` / `spellbook`, бонусы СЛ и атаки,
  а также связать её с item базового класса. Непустая связь класса уникальна.
- Заклинания принадлежат вкладке как отдельные записи с устойчивым `key`.
  Поэтому один item заклинания можно независимо знать от нескольких классов,
  с разной подготовкой и без переключения скрытого источника.
- Дарованные особенностями, расами и чертами заклинания хранятся в отдельном
  readonly-списке `grants` под ячейками. Каждый дар сохраняет источник,
  необязательную собственную характеристику, фиксированный круг и признак
  применения без ячейки; связь с вкладкой нужна только для наследования её
  параметров.
- При повышении уровня вкладка ищется по `class_item_id`. Если класс начинает
  колдовать на этом уровне и вкладки ещё нет, она создаётся из справочных
  правил. В том же сценарии можно изучать, заменять или подготавливать
  заклинания; для книги волшебника учитывается число новых заклинаний.
- Паладин и следопыт имеют `spellcasting.start_level = 2`: на первом уровне
  вкладка не создаётся, на втором появляется через общий level-up flow.
- Печатный лист выводит параметры каждой вкладки и оба пула ячеек. Событие
  применения сохраняет круг и выбранный пул.
- Заговоры масштабируются по суммарному уровню персонажа.

## Контракт данных

```text
spells: {
  schema_version: 2,
  slots_auto: boolean,
  slot_pools: {
    long_rest: [{ level, total, used }],
    short_rest: [{ level, total, used }]
  },
  tabs: [{
    key,
    name,
    class_item_id: itemId | null,
    casting_ability: suggest16Id | "",
    mode: "known" | "prepared" | "spellbook",
    save_bonus: number,
    attack_bonus: number,
    spells: [{ key, id, prepared }]
  }],
  grants: [{
    key,
    id,
    source: { kind, item_id?, label },
    tab_key?,
    casting_ability?,
    cast_level?,
    slotless?,
    counts_as_known?
  }]
}
```

Пулы не принадлежат классу. Вкладка отвечает за список и математику
сотворения, а `class_item_id` — за автоматическое обновление при level-up.
Дар использует собственную `casting_ability`, если она задана, иначе —
параметры связанной вкладки. Несвязанный дар без характеристики остаётся
рабочим для домашнего правила, но его СЛ и атака считаются без модификатора.

`61_spellbook_tabs.sql` один раз переводит старые `source_settings`, общий
массив `spells`, `slots`, `slots_rest` и `pact_slots`. Однозначные записи
попадают во вкладку базового класса, неоднозначные — в редактируемую вкладку
«Без источника», внешние источники — в `grants`. Runtime старый формат не
читает и не записывает.

## Оставшиеся пробелы

1. Полная `known_progression` заполнена не для всех классов. Пока таблица
   неполна, лист фильтрует класс и доступный круг, но не вводит ложный лимит.
2. Формулы максимума подготовленных заклинаний ещё не проверяются. Для
   волшебника также не автоматизированы копирование заклинаний и стоимость
   расширения книги.
3. Ритуальное сотворение и фокус зависят от класса, но лист пока не проверяет
   книгу, подготовку ритуала и подходящий фокус.
4. Таинственный арканум колдуна 6–9 кругов должен быть отдельным ресурсом
   «раз за долгий отдых», а не ячейкой Магии договора.
5. Восстановление волшебника, создание ячеек из очков чародейства и другие
   способности, меняющие пулы, должны явно выбирать `long_rest` или
   `short_rest`.

## Проверенные сценарии

- следопыт 4 / волшебник 3: уровень заклинателя 5, обычные ячейки `4/3/2`,
  доступные заклинания следопыта до 1 круга и волшебника до 2 круга;
- паладин 3 / колдун 1: три обычные ячейки 1 круга и одна короткая ячейка 1
  круга;
- волшебник 3 / колдун 5: обычные `4/2` плюс две короткие ячейки 3 круга;
- одинаковое заклинание в двух классовых вкладках остаётся двумя независимыми
  записями;
- короткий отдых восстанавливает только `short_rest`, долгий — оба пула.
