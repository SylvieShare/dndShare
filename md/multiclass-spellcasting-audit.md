# Аудит магии при мультиклассировании

Проверка относится к правилам D&D 5e 2014. Лист остаётся редактируемым:
автоматический расчёт ячеек можно отключить в настройках блока магии и вести
общий пул вручную.

## Реализовано

- Обычные ячейки образуют один общий пул. Уровни барда, жреца, друида,
  чародея и волшебника складываются полностью; паладина и следопыта — по
  половине с округлением вниз; Мистического рыцаря и Мистического ловкача — по
  трети с округлением вниз. Вклад изобретателя округляется вверх.
- Если у персонажа только один класс с `Spellcasting`, он использует таблицу
  этого класса, даже если рядом есть немагический класс или колдун с
  `Pact Magic`.
- Все ячейки отображаются в одном блоке и разделяются по восстановлению. Пул
  `long_rest` восстанавливается после долгого отдыха, пул `short_rest` — после
  короткого или долгого. Автоматика Магии договора заполняет короткий пул, но
  хранилище и UI не называют его колдовским и допускают домашние источники.
- При сотворении одного заклинания можно выбрать обычную ячейку или ячейку
  договора. В событие сессии записываются круг и пул потраченной ячейки.
- Доступный для выбора круг считается по уровню конкретного класса, а не по
  максимальному кругу общего пула. Поэтому, например, следопыт 4 / волшебник 3
  имеет ячейки 3 круга, но не может изучить заклинание 3 круга.
- У записи заклинания есть `spellcasting_source`. Он определяет класс,
  заклинательную характеристику и режим подготовки. Для старых
  мультиклассовых записей без источника лист показывает предупреждение и
  предлагает выбрать класс в меню заклинания.
- Книга заклинаний имеет вкладки «Все», по одной на каждый магический класс и
  «Другие» для расовых, дарованных, предметных и ручных записей. Добавление во
  вкладке класса сразу назначает правильный источник; общий список остаётся
  удобным режимом во время игры.
- Панель параметров находится внутри вкладки источника. Каждый магический
  класс и вкладка «Другие» независимо хранят базовую характеристику, режим
  подготовки, дополнительный бонус СЛ и бонус атаки. Во вкладке «Все» панель
  сводит классовые значения без неоднозначного общего редактора.
- Печатный лист выводит отдельные характеристику, СЛ и бонус атаки для каждого
  источника. Расход и печать различают ячейки долгого и короткого отдыха
  внутри одного общего блока.
- Заговоры масштабируются по суммарному уровню персонажа; это уже было
  реализовано корректно и не менялось.

## Контракт данных

```text
spells: {
  slots_auto: boolean,
  source_settings: {
    "class:<classId>:<subclassId>": {
      stat_path: suggest16Id,
      save_bonus: number,
      attack_bonus: number,
      preparation: boolean
    },
    other: { ... }
  },
  slot_pools: {
    long_rest: [{ level, total, used }],
    short_rest: [{ level, total, used }]
  },
  spells: [{
    id,
    spellcasting_source?: "class:<classId>:<subclassId>",
    casting_ability?: suggest16Id,
    prepared?: boolean
  }]
}
```

`source_settings` разделяет параметры сотворения и подготовки, но не ячейки.
Справочная характеристика и режим подготовки класса служат начальными
значениями; владелец листа может переопределить их для домашних правил. Старые
глобальные `stat_path`, `save_bonus`, `attack_bonus` и `preparation`
преобразуются в настройки источников при открытии листа.

Пулы разделены по восстановлению, а не по классу или источнику. Совпадающий
круг не объединяет их остатки, но при сотворении заклинания доступны оба.
`casting_ability` у записи используется только для собственного параметра
дарованного заклинания; обычная классовая запись разрешает характеристику
через `spellcasting_source`. Старые `slots`, `slots_rest` и `pact_slots`
читаются и мигрируют в `slot_pools`.

## Оставшиеся пробелы

Эти пункты требуют отдельной модели данных или продуктового решения, поэтому
не маскируются приблизительной автоматизацией.

1. В справочнике полная `known_progression` сейчас есть только у Мистического
   ловкача. Для барда, чародея, колдуна и следопыта нельзя надёжно проверять
   число известных заговоров/заклинаний на каждом уровне. До заполнения таблиц
   лист фильтрует список и круг класса, но не блокирует количество.
2. Подготовка жреца, друида, паладина, изобретателя и волшебника требует формул
   вида «уровень класса + модификатор характеристики». У волшебника отдельно
   нужны вместимость книги, подготовленный список, копирование и замена
   заклинаний. Сейчас подготовка хранится на записи, но лимит не проверяется.
3. Одно справочное заклинание хранится в блоке один раз. Если персонаж знает
   одно и то же заклинание от двух классов, он может выбрать только один
   активный класс-источник. Для полного случая нужен массив ассоциаций и выбор
   источника при каждом сотворении.
4. Ритуальное сотворение и фокус зависят от класса-источника, но наличие книги,
   подготовка ритуала и подходящий фокус пока не валидируются.
5. Таинственный арканум колдуна (6–9 круги) — не ячейки Магии договора. Его
   следует хранить как отдельные способности «раз за длинный отдых», а не
   добавлять в пул коротко восстанавливаемых ячеек.
6. Восстановление волшебника, создание ячеек из очков чародейства и другие
   способности, меняющие пул, должны явно выбирать пул восстановления, а не
   напрямую менять совместимый зеркальный `slots`.

## Проверенные сценарии

- следопыт 4 / волшебник 3: уровень заклинателя 5, ячейки `4/3/2`, доступные
  заклинания следопыта до 1 круга и волшебника до 2 круга;
- паладин 3 / колдун 1: три обычные ячейки 1 круга и одна отдельная ячейка
  договора 1 круга;
- волшебник 3 / колдун 5: обычные `4/2` плюс две ячейки договора 3 круга;
- два частичных заклинателя: вклад каждого округляется отдельно до сложения;
- короткий отдых восстанавливает только `short_rest`, долгий — оба пула.
