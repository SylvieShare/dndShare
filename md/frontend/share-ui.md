# Сопровождение share-ui

Разрешённый межрепозиторный workflow и обновление фиксированного release tag.

← [Frontend: архитектура и разработка](../frontend.md)

## Межрепозиторное сопровождение

Задача в DnD Share является разрешением без дополнительного согласования
изменить соседний `../share-ui`, когда существующий общий API содержит баг или
не позволяет корректно завершить задачу. В рамках задачи разрешены изменения
исходников, тестов, галереи и документации библиотеки, release commit/tag/push,
а затем обновление точной версии и lock-файла DnD Share.

Изменение обязано оставаться нейтральным: `share-ui` не получает router, Pinia,
HTTP API, permissions, локализованные DnD-тексты и доменные модели. Такая логика
остаётся в локальном adapter/controller. Нехватку общего API не обходят копией
компонента, deep import, правкой `node_modules` или постоянным переопределением
его базовой геометрии. Если безопасное решение требует незапланированной
breaking-миграции других продуктов, перед выпуском нужно завершить их миграцию
либо запросить решение пользователя.

Канонический порядок работы, матрица проверок, versioning и Definition of Done
описаны в
[share-ui/MAINTAINING.md](https://github.com/SylvieShare/share-ui/blob/main/MAINTAINING.md).

DnD Share использует точный HTTPS-архив release tag; floating branch и локальная
`file:` dependency не допускаются. Обновление выполняется после выпуска новой
версии в `SylvieShare/share-ui`:

```bash
cd frontend
npm install --save-exact \
  "https://github.com/SylvieShare/share-ui/archive/refs/tags/vX.Y.Z.tar.gz"
npm test -- --run
npm run build
```

Изменения межпроектного примитива сначала делаются и документируются в
`share-ui`, затем consumer обновляет tag. Файлы внутри `node_modules` не меняют.


## Установленная версия и история

С v0.82.1 подключены `installPointerInput` и CSS-обработка наведения через
PostCSS. Общие меню разделяют наведение, нажатие, фокус и открытое состояние.

В v0.81.0 общий переход `action-menu` применяется к `BasePopover` по умолчанию,
а также к меню действий, подменю и `ValueSelect`. Появление сочетает прозрачность
с масштабированием от точки привязки. `transitionPreset="none"` сохраняет
возможность показать `BasePopover` сразу.


С v0.79.0 выбор элемента, захват контекста и форма багрепорта входят в общий `PageReport`.
Приложение задаёт способ отправки, снимок WebView и локализованные подписи.

С v0.78.0 `AppDrawer` поддерживает открытие с левого края и движение за пальцем.
`AppNavigationShell` включает этот жест и закрытие свайпом в компактном формате.

С v0.77.0 публичный `FitContent` уменьшает живое содержимое до заданного
`minScale` (по умолчанию 0.5) перед переносом. Он учитывает изменения ширины,
шрифтов, содержимого и возврат скрытой вкладки; резервирует уменьшенную высоту.
Вложенные экземпляры используют внешний масштаб. Формулы потребителя объявляют
перенос через `--fit-content-wrap`; игровых моделей в библиотеке нет.

С v0.76.0 `CompactCheckbox` поддерживает `indeterminate` и независимый `hitSize`;
сессия использует их для постоянного выбора и mixed-состояния вкладки.
`useSortable` допускает один UID в нескольких списках-представлениях и не
дублирует существующий элемент целевой группы в preview.


С v0.75.0 корни слота `ActionMenu` могут объявить `data-action-menu-size="content"`.
Меню из одних таких групп оборачивает содержимое без лишней минимальной ширины;
обычные строки, summary и явный `width` сохраняют прежние правила. Группа
`CharacterMenuActions` объявляет этот режим, когда в ней только кнопки.

С v0.74.0 публичный `AvatarFrame` задаёт квадрат, обрезку, небольшой радиус,
режим вписывания и fallback при ошибке изображения. Продуктовый `CharacterAvatar`
передаёт ему радиус Input, верхний центр кадра и инициал персонажа. Выбор иконки
или портрета принадлежит адаптерам DnD Share; API, загрузки и stores библиотека
не получает. Новая рамка не меняет defaults других компонентов.

Точный установленный tag и integrity задают [package.json](../../frontend/package.json) и lock-файл. [История обновлений](../reports/share-ui-consumer-history-2026-10.md) хранится отдельно от текущего workflow.

DnD Share — основной потребитель и визуальный ориентир defaults библиотеки.
Начиная с v0.47.2 заполненные безрамочные формы/вторичные кнопки и подсветка
фокуса заливкой являются стандартом share-ui. Пунктирные add-actions сохраняются.
Для числовых полей листа используется публичный live-режим: валидный ввод
обновляет модель немедленно, промежуточный текст остаётся в буфере. Другие
сайты получают новые defaults при обновлении своей фиксированной версии.


## Общий эффект blur

Начиная с v0.48.0 библиотека экспортирует `BlurBackdrop`, `backdropBlurStyle`,
`applyBackdropBlur` и `blurFilter`. Шапки workspace и создания персонажа
используют общий декоративный слой; существующие поверхности и анимируемые
окна получают тот же фильтр через style/imperative API. Сила, затемнение,
границы и маска затухания остаются параметрами потребителя.
Декларации задаются inline: production CSS-минификация не может удалить
стандартный backdrop-filter, сохранив только vendor-prefix. Механика морфа,
которая размывает сам фон через filter, сохраняет свой lifecycle и владельцев.
Проверка совместимости выполняется на точном установленном release tag и
минифицированном frontend, а не только в dev-server.

## Меню рядом с прокручиваемыми панелями

Начиная с v0.54.1 прокрутка соседней полосы вкладок не закрывает ActionMenu.
Меню закрывается, когда прокрутка затрагивает документ или предка его якоря.
Это сохраняет меню фотографий при автоматическом позиционировании навигации.

## Общая навигация листа

С v0.57.0 `IconNavigation` поддерживает stacked, inline и compact и внешний массив
весов выбора для свайпа. `CharacterSheetTabs` выбирает представление по формату,
а `useTabSwipe` владеет выбранным разделом и жестом. Размеры, подписи и индикатор
при жесте рассчитывает библиотека; отдельной копии телефонного tabbar в приложении нет.
Публичные свойства описаны в [каталоге share-ui](https://github.com/SylvieShare/share-ui/blob/main/docs/components.md).

С v0.58.0 планшетный вариант использует `contentSized`: подписи сохраняют
продуктовый размер 12/14, а ширина кнопок следует содержимому с заданным минимумом.

## Ширина меню персонажа

С v0.70.0 публичный `ActionMenu.width` задаёт ширину в CSS px с ограничением
visual viewport. Меню персонажа использует этот API для сетки показателей;
локальных переопределений геометрии popover нет.

## Меню в строках состояний

С v0.71.0 `ActionMenu.followAnchor` позволяет сохранять меню при прокрутке
внутреннего контейнера, обновляя позицию по его видимому якорю. Уход якоря
за край контейнера и прокрутка документа закрывают меню. Строки состояний
листа и игроков используют этот API: автоматическая прокрутка при фокусе
или выборе соседнего эффекта не закрывает только что открытое меню.
