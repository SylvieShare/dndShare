# Общие UI-компоненты

Основной каталог выбора стандартного компонента и граница между share-ui и предметной композицией DnD Share.

← [Frontend: архитектура и разработка](../frontend.md)

## Стандартные компоненты: что и когда использовать

Компоненты ниже — не локальные удобства отдельных экранов, а стандарт проекта.
Перед созданием нового оверлея, поля или drag-and-drop нужно сначала выбрать
подходящий примитив отсюда.

| Задача | Стандарт | Когда использовать |
|---|---|---|
| Низкоуровневое модальное окно | `share-ui/AppModal` | Инфраструктура backdrop, Escape, focus/слоёв, анимации и `role=dialog`. Напрямую используется только специализированными fullscreen-workspace; Escape закрывает только верхнее окно стека. |
| Стандартное окно с шапкой | `share-ui/AppModalFrame` | Единая оболочка формы, просмотра или picker поверх `AppModal`: шапка `--surface`, тело и footer `--bg`, одинаковая рамка, увеличенный заголовок и закреплённые title/крестик/мобильный handle. Тело прокручивается отдельно, footer с действиями также может быть закреплён. |
| Подтверждение | `share-ui/ConfirmDialog` | Удаление, отмена операции, сброс формы и любое решение «подтвердить/отменить». Поддерживает `loading`; не собирать собственный overlay. |
| Ввод одного текста | `share-ui/TextPromptDialog` | Создать/переименовать альбом, сцену, сущность. Заменяет `window.prompt` и локальные формы из одного input. |
| Морф-переход из элемента | `share-ui/MorphSheet` + `share-ui/useContainerMorph` | Только когда окно должно анимированно раскрываться из конкретной плитки/кнопки. На desktop фон размывается, на mobile полноэкранный sheet оставляет фон без blur. Вложенный morph задаёт `zIndex` выше родительского overlay; редакторы листа используют `3100` поверх fullscreen-листа на `3000`. Поля внутри не получают автофокус при открытии; фокус допустим после явного действия пользователя. Обычный диалог строится на `AppModalFrame`. |
| Поле формы | `share-ui/FormField` | Label, hint и горизонтальная/вертикальная раскладка одного поля. |
| Календарная дата | `share-ui/DatePicker` | Дата без времени в `YYYY-MM-DD`: выбор месяца/года, клавиатура, локализация через props. Для встреч кампании используется `locale="ru-RU"`; свободная дата вымышленного мира остаётся текстом в личном дневнике. |
| Текст/число/select/многострочный текст | `FormTextInput`, `FormNumberInput`, `FormSelect`, `FormTextarea` | Любой универсальный ввод соответствующего типа. Не вводить новые локальные классы input/select без отдельной UX-причины. |
| Удаление записей | `share-ui/RemoveButton` с `icon="trash"` | Корзинка у действий, ресурсов, защит, эффектов, бонусов и других пунктов листа. Обязательный `label` задаёт доступное имя; подтверждение и удаление данных остаются в feature. Крестик используется для закрытия и снятия выбора. |
| Кнопки формы | `share-ui/FormActionButtons` | Стандартная пара отмена/сохранение и loading/disabled состояния. |
| Выбор значения | `share-ui/ValueSelect`, `SuggestPicker`, `SuggestAdd`, `SuggestMultiSelect` | Обычный select либо одиночный/множественный выбор из серверного справочника; компоненты сами отвечают за desktop dropdown и mobile sheet. `ValueSelect` открывается вниз по умолчанию, а внутри ограниченного снизу scroll-контейнера может явно использовать `drop-up`. Серверные suggest-компоненты остаются в приложении. |
| Расширенное описание | `shared/ui/InputDescription.vue` → `share-ui/RichTextEditor` | Тонкий DnD-адаптер задаёт русские подписи и owner-mode; toolbar, редактирование, очистка paste/drop и базовый HTML-контракт принадлежат пакету. |
| Отображение описания | `share-ui/RichContent` | Безопасный единообразный вывод HTML через allowlist sanitizer. Не использовать собственный `v-html` для сохранённого пользовательского контента. |
| Расчёт в описании | `shared/ui/RichCalculationNode.vue`, `RichCalculationNodeModal.vue` | Предметный узел `calculation` внутри общего rich HTML. Формула и результат для переданного контекста; редактор использует общие `AppModalFrame`, `FormField`, `FormTextInput`. |
| Перевод денег из листа | `CharacterMoneyDialog`, `useCharacterMoneyTransfer` | Окно на `AppModalFrame`, валюта на `FormSelect`, сумма на `FormTextInput type="number"`: полноширинный ввод без шаговых кнопок, с проверкой целой суммы и баланса. Контроллер использует сохранение/обновление листа из `useCharacterTransfers`, сохраняет ключ повтора при сетевой ошибке. |
| Общение игроков из листа | `CharacterInteractionPlayers`, `CharacterInteractionDialog`, `CharacterInteractionInbox` | Строка игрока использует `TransferPerson` с размером 48 px и слотом для `SessionHpBar`; класс, раса и троеточие скрыты. Меню на `RowActionMenu` с пометкой связанного поповера, отдельные `CharacterChatDialog` и `CharacterRpsDialog` на `AppModalFrame`, ввод на `FormTextarea`. `RpsChoices` использует `ActionButton`, а общий `RpsResult` на `BaseTile` показывает полный и компактный результат в игре, чате, уведомлении и хронике: зелёный победитель или обе жёлтые карточки при ничьей. Контроллер хранит переписку и вызовы через API сессии; базовые оболочки не дублируются. |
| Группа событий ленты | `share-ui/TimelineGroup` | Извлечённая из хроники общая геометрия: слот identity слева от цветного соединителя, содержимое справа и footer на обе колонки. Используется хроникой и всеми записями дневника; типы, авторы, API и редакторы остаются в feature-коде. |
| Заголовок группы со счётчиком | `share-ui/SectionLabel line` | Горизонтальная линия соединяет название с actions-slot. Список встреч использует его для групп прошедших, следующей и будущих сессий. |
| Встречи на странице просмотра | `SessionMeetingsCard` + `SessionJournalNavigation readOnly` | Третья колонка рядом с главой и группой. Статические строки даты/номера/названия, без выбора, picker и счётчиков записей; API дневника не читается. Хронология и оформление групп общие с рабочим дневником мастера. |
| Сессии и дневник кампании | `SessionJournalWorkspace`, `SessionJournalNavigation`, `JournalTimeline` | Единая доменная композиция: два отдельных `BaseTile` с непрозрачным фоном для списка встреч и ленты; до 620px общего контейнера — `ValueSelect` с поиском. Создание на `AddButton`, правка/удаление на `RowActionMenu`, права на `BasePopover`/`ToggleSwitch`; базовые поля и оверлеи не копируются. |
| Фильтры хроники сессии | `BasePopover` + `MultiToggle` + `FormSelect` | Локальный `SessionEventsPanel` задаёт доменные категории и чипы активного состояния; базовые popover/form controls не дублируются. |
| Аватар субъекта хроники | `SessionEventActorAvatar` | Локальная проекция character/bestiary media и тематический DM fallback относятся только к семантике журнала сессии. |
| Морф-плитка и заголовок | `share-ui/MorphTile`, `MorphTileHeader` | Опциональные title/карандаш и слот `aside` справа. `embedded` для общего представления внутри morph-панели, `padding` для композиции. Заголовки не переопределяются локальным CSS; `SheetBlockTitle` только задаёт русский текст действия. |
| Плитка/карточка контента | `share-ui/BaseTile` | Общая поверхность с фоном, скруглением и тихой рамкой. Поддерживает цветовой акцент, tint, framed- и interactive-состояния; декоративная полоса добавляется отдельным `TileAccentStrip`; не создавать локальный базовый класс плитки. |
| Popover/контекстное меню | `share-ui/BasePopover`, `ActionMenu`, `ActionMenuItem`, `ActionMenuSubmenu` | Неблокирующий контент, привязанный к управляющему элементу. Меню поддерживает стандартный trigger, feature-trigger через slot и внешний DOM-элемент через `anchor` для программного открытия `open`/`toggle`; меню плиток боя использует этот внешний anchor. Программно привязанный action popover выбирает `transitionPreset="action-menu"`; вложенное меню остаётся внутри visual viewport, не закрывает родителя и корректно работает на mobile. Поскольку `BasePopover` телепортируется в `body`, popover внутри модального окна обязан получить `zIndex` выше слоя своего окна; item picker прокидывает это значение через list controls. Локальный `RowActionItem.vue` сопоставляет DnD action names с Lucide-иконками, а `RowActionSeparator.vue` разделяет смысловые группы действий. Карточка-trigger использует slot-параметр `open` и общий класс `action-menu-source--open`, чтобы оставаться слегка подсвеченной всё время, пока её телепортированное меню открыто. |
| Классы персонажа в окне «Персонаж» | `DndClassList` → `ObjectListItem` | Общая строчная оболочка справочника показывает иконку, название, подкласс и уровень персонажа в metric-slot. Отдельная доменная композиция нужна для фактического уровня и выбранного подкласса вместо каталожного описания; редактирование открывается общей кнопкой. |
| Повышение уровня | `LevelUpItemRow` → `HandbookListItem`, `LevelUpHitPoints`, `ClassLevelGains` | Окно 960 px собирает списки умений и заклинаний из существующих отображений справочника. `LevelUpItemRow` объединяет просмотр строки и отдельные действия выбора на `BaseTile`; хиты используют общие контролы и `SystemDie`, прирост ячеек — тот же `SpellSlotSphere`, что в прогрессии класса. |
| Описание при наведении | `features/character-editor/components/ItemTooltip.vue` | Единая телепортированная подсказка терминов, предметов и свойств. Она проявляется коротким fade/scale-переходом с движением от элемента, отключает анимацию при `prefers-reduced-motion`, отделяет крупный display-заголовок от более спокойного prose-описания и принимает доменные данные через details-slot. |
| Перетаскивание | `share-ui/useSortable` | Сортировка и перенос между группами. `layout: grid` выбирает точный `data-sortable-slot` по двум координатам без preview-перестановки; consumer сохраняет перенос/обмен. `reorderByDrop` выполняет чистую перестановку списка. |
| Перенос 3D-плиток карты | `features/maps/useCatalogueDrag`, `editorTileDrag` | Предметный перенос из каталога в мировые координаты Three.js: canvas не содержит sortable DOM-слотов. Общие карточки остаются `BaseTile`; локальная композиция владеет ray projection, предварительными экземплярами, переносом группы, заполнением замкнутой области и отменой. |
| Разделы инструментов карты | `share-ui/SlidingTabs` | Штатный icon-slot показывает Lucide-иконки; доступные названия и title сохраняются, текстовая подпись не занимает ширину панели. |
| Переключатели | `share-ui/MultiToggle`, `share-ui/ToggleSwitch`, `share-ui/CompactCheckbox` | Выбор режима, boolean и компактный checkbox соответственно. |
| Прибавки характеристик D&D | `shared/ui/AbilityBonusPicker` | Один доменный компонент для расы 2014, предыстории 2024 и повышения уровня: схемы распределения, разные характеристики, ограничения количества и максимума. Режим переключается общим `MultiToggle`; базовые формы не дублируются. |
| Кольцевая разбивка | `share-ui/SegmentDonutChart` | Нейтральный donut с легендой, форматтером значений и центральным slot. Доменные категории, цвета и данные остаются в приложении. |
| Каркас и левое меню | `share-ui/AppShell`, `share-ui/AppSidebar`, `share-ui/Sidebar*`, `share-ui/AccountMenu` | Единая геометрия приложения, DnD-стиль rail и trigger аккаунта с выпадающими действиями. Во всех разделах adapter включает `elevated`: фон `--surface`, контрастная граница и короткая тень отделяют меню от canvas. Router, права, поиск, данные профиля и сами account-actions передаёт локальный adapter. |
| Каталог страницы сессии | `features/sessions/components/SessionLibraryWorkspace.vue` | Общий dotted workspace, safe-area от игроков и геометрия sidebar/detail для локаций, NPC, материалов и заданий. Предметные компоненты передают внутрь собственные список, detail и окна. |
| Музыкальная библиотека сессии | `features/sessions/components/SessionMusicWorkspace.vue` | Центральное содержимое вкладки `Музыка` с safe-area страницы сессии, альбомами, тегами, треками, очередью и загрузкой. Это не modal; вложенные точечные редакторы продолжают использовать общие dialog-компоненты. |
| Карточка выбранного объекта сессии | `features/sessions/components/SessionEntityDetail.vue`, `SessionEntityForm.vue`, `SessionEntityFormHeader.vue`, `SessionEntityFormVisual.vue`, `SessionEntityFormBody.vue`, `SessionEditableField.vue` | `SessionEntityForm` предоставляет общий черновик шапке, визуалу и содержимому через context. Тип локации, раса/роль NPC, статус задания, тип/оформление материала и название редактируются в шапке карандашами без рамки и фона. Текст и enum используют общий `InlineEdit` из `share-ui`: высота строки фиксирована, ширина следует содержимому от минимума 120px до ширины контейнера с запасом под подтверждение/отмену внутри справа. Пустые поля создания показывают содержательные плейсхолдеры. Цвет NPC — общий `ColorPresetPicker` в шапке. В полном режиме эти значения раскрываются в инпуты на том же месте; общей кнопки `Редактировать` нет. Клик по визуалу НПС/локации открывает меню добавления/замены (сразу каталог) и очистки; пустое изображение хранится как `null`. Бестиарий под описанием использует `HandbookListItem` и открывает `ItemViewModal`; вложенные локации тоже идут под описанием. отдельные карточки портрета/изображения локации и поле родителя убраны. При ошибке сохранения черновик остаётся открытым. Шапка сохраняет возврат по истории связей. |
| Объект сессии на холсте сценария | `features/sessions/components/SceneBlockNode.vue`, `SceneEntityBlockPreview.vue`, `SceneReferenceCreateModal.vue` | Общий заголовок каждого типа блока показывает семантическую иконку, тип и имя; материал использует иконку конкретного подвида. Типизированный live-preview ссылки на локацию, NPC, задание или материал начинается ниже без повторного заголовка. Создание блока начинается с закреплённого по типу picker; новый объект создаётся каноническим предметным редактором. Каждый тип показывает свои содержательные поля, текущие универсальные связи и локальную заметку; название и данные объекта не дублируются в UI-модели блока. |
| Универсальные связи сущностей сессии | `features/sessions/components/UniversalRelationPickerModal.vue`, `UniversalRelationList.vue` | Один типизированный каталог для локаций, NPC, материалов и заданий. Picker поддерживает общий поиск, фильтр или закреплённый тип и опциональные пунктирные create-actions в заголовках групп. Общий список сортирует и группирует связи по типу в обоих режимах: пунктирный `AddButton` стоит непосредственно рядом с заголовком «Связи», `RemoveButton` с корзиной — в углу каждой связи, заметка раскрывается карандашом или сразу при полном редактировании. Сценарии не являются targets универсальных связей. |
| Использование объекта на холстах | `features/sessions/components/ScenarioUsageList.vue` | Read-only список сценариев для локации, NPC, задания или материала строится из `scenarioUsages`, показывает контекст арки/главы и число блоков. Клик открывает соответствующий холст; добавление и удаление выполняются только на самом холсте. |

Дневник использует `JournalInlineForm` для общего черновика записи в полноширинном footer общего `TimelineGroup`
в вертикальной ленте, а не `SessionEditableField`: нужны составные реплики,
участники боя и rich-text, сохранение черновика при ошибке и проверка версии.
`JournalEventFields` редактирует название, описание и составные списки, которые
сохраняются одной операцией. Формы используют общие `Form*`, `FormActionButtons`
и `InputDescription`; `FormField vertical` располагает подписи над полями во всех
типах записей. Числовые поля участников переносятся по доступной ширине, пункты
заданий и награда многострочные. В просмотре отдельных карандашей у строк нет.
`JournalEditButton` задаёт тихий карандаш и увеличенную touch-область.

`JournalWorkspace` / `JournalTimeline` — единые компоненты вкладок персонажа
и сессии. Название, настройки и горизонтальный выбор разделов объединены в
шапку `BaseTile`. В листе персонажа лог, фильтры и действия находятся во втором
`BaseTile` под шапкой, включая пустое состояние. Показывается один раздел, записи имеют естественную высоту;
добавление и действия находятся справа сверху области событий. `useSortable`
из share-ui отвечает за desktop-перестановку за заголовок. На устройствах
с coarse pointer drag отключён: обычная прокрутка и явные кнопки порядка.
ELK, отдельное окно и canvas-preview дневника удалены из frontend.

`features/narrative-graph` остаётся предметной реализацией холста сюжета сессии:
русские действия нарратива, сохранение камеры по ключу workspace, безопасные
отступы сессии, spotlight и редактирование связей. Геометрия узлов, связи и
камера разделены на composables. Оболочки, формы, popover, карточки и модальные
окна принадлежат share-ui. Дневник этот холст не использует.

`features/maps/components/MapTilePalette.vue` использует BaseTile для карточек
готовых 3D-компонентов, FormSelect для коллекции, уровня и фильтров и ActionButton для инструментов.
Клавиатура Enter/Space начинает размещение; исходный код и название показываются
отдельно. Three.js-сцена остаётся вне реактивного состояния Vue; редактор,
сохранение, жесты, загрузка моделей и renderer разделены по ответственности.

Категории модальных окон:

- подтверждение — `ConfirmDialog`;
- один текстовый ответ — `TextPromptDialog`;
- сложная предметная форма — feature-компонент, но его оболочка всегда
  `share-ui/AppModalFrame`, если окну нужны заголовок и прокручиваемое содержимое;
- детальная карточка справочника — `features/handbook/components/ItemViewModal`;
  она использует `share-ui/AppModal` без отдельной полосы заголовка, поскольку
  единственной шапкой служит `ItemDetailHeader` внутри содержимого;
- серверный поиск и выбор элемента —
  `features/handbook/components/ItemPickerModal`;
- раскрытие из плитки — `MorphSheet`.

Fullscreen-карточка `AppModal` ограничивает высоту по `visualViewport`, поэтому
фиксированная шапка и поля остаются в видимой области при открытой мобильной
клавиатуре; `dvh` используется как CSS fallback.

Предметные действия не встраиваются в renderer карточки: владелец передаёт их
в footer-slot `ItemViewModal`. Поэтому одно и то же окно описания поддерживает,
например, подготовку/удаление заклинания или количество/удаление предмета, не
получая зависимостей от листа персонажа.

Все типы item используют `features/handbook/components/ItemDetailHeader.vue`.
Компонент владеет общей геометрией имени и действий, показывает панорамный
`coverImageUrl` через центрированный `object-fit: cover` и затемнение под
текстом. Для способностей (типы 3/4) и черт (тип 7), как и для профилей с
summary бестиария и заклинаний, затемняется только компактная подложка названия,
а сама обложка остаётся без общего затемнения. Справа в одной строке для любого типа справочника находятся источник
(крайний справа, полное название доступно через tooltip) и кнопка
«Редактировать» с иконкой карандаша слева от него; renderer не дублирует
источник внутри содержимого. Обложка является единственным изображением шапки:
компактная иконка в ней не дублируется и не используется как missing-cover
fallback. При отсутствии item-level обложки используется
`itemType.coverImageUrl`; production fallback cover назначен 15 системным типам:
прежним 1–13 и новым 16–17.
Ошибка изображения сохраняет cover-компоновку и нейтральный фон, не переключая
геометрию карточки. Item-level обложка всегда имеет приоритет над типовой.
Типы 1/6/12 резервируют `4:3`, типы 2/8/9/11/13/14/16/17 — `3:2`, а типы
3/4/5/7/10 — `5:2` ещё до загрузки файла. Контейнер не ограничивается
по ширине, после загрузки использует фактическое соотношение файла и не имеет
общего ограничения максимальной высоты. `ItemDetailHeader` принимает тип
справочника и хранит расширяемую таблицу CSS-переменных минимальной высоты для
типов, которым требуется другая композиция. Обычная обложка поэтому сохраняет
своё соотношение сторон, а содержимое detail-карточки остаётся доступным через
вертикальную прокрутку. При смене URL обложки старое изображение сразу скрывается:
до загрузки и декодирования нового виден нейтральный фон с индикатором загрузки
по центру. Это же состояние используется при первом открытии. Готовая обложка
проявляется за `160ms`; при ошибке остаётся фон без индикатора. Поздние ответы
для уже сменившихся обложек игнорируются. Системная настройка
`prefers-reduced-motion` отключает анимации.

Заклинание использует отдельный summary-профиль с минимальной
высотой `300px`. Уровень и школа образуют компактный вертикальный блок под
названием. Над нижней зоной справа располагается компактная обычная карточка
компонентов, а под ней время накладывания, дистанция и длительность занимают
три равные колонки. Эти краткие параметры не повторяются в содержимом ниже; для
материального компонента там остаётся только его полное описание. На узком
экране сетка остаётся трёхколоночной и уменьшает внутренние отступы и шрифт.
Для типа заклинаний назначена типовая обложка-заглушка, поэтому все заклинания
используют эту единственную summary-компоновку; персональная обложка только
заменяет изображение. Вещи типа 2 аналогично всегда держат стоимость и вес в
summary-карточках шапки, когда эти значения заданы, и не повторяют их ниже.
Плитки поверх обложек стандартизированы локальными примитивами
`features/items/components/cover`: `CoverStatCard` владеет стеклянной
поверхностью, типографикой, tone/size-вариантами и увеличенным полупрозрачным
декоративным знаком по центру справа; `CoverSummaryLayout` задаёт боковые
колонки и безопасный центр изображения; `CoverSummaryRail` с `CoverSummaryRailItem`
задаёт нижнюю сегментированную полосу и её мобильное складывание. Типовые
summary-компоненты отвечают только за выбор данных, подписей, иконок и
композиционных параметров этих примитивов.
На экранах до 520 px боковые колонки `CoverSummaryLayout` ограничены 124 px,
между ними остаётся свободный центр обложки. `CoverStatCard` уменьшает внутренние
отступы и декоративную иконку; длинные подписи переносятся, размеры значений
сохраняются. Нижняя полоса параметров по-прежнему занимает всю ширину.

Поиск, schema-фильтры и фильтр по публикациям принадлежат левой колонке
`HandbookItemList` и закреплены над её собственной прокручиваемой областью.
Landing справочника сразу занимает итоговую ширину до загрузки систем и
коллекций, поэтому появление данных не меняет геометрию страницы. Карточка
коллекции и вкладка модального picker используют
`itemType.iconImageUrl`; прежний `itemType.svg` не является frontend-контрактом.
`itemType.parentTypeId` связывает специализированные каталоги с родительским:
landing помечает подразделы и перечисляет их у «Вещей», «Рас» и «Классов», а
picker может рекурсивно включить дочерние типы без хардкода их идентификаторов.
Типы 16 «Подрасы» и 17 «Подклассы» используют schema item-поля `race`/`class`;
общие формы и фильтры умеют работать с такими ссылками напрямую.
`ItemIcon` применяет эту растровую эмблему только после отсутствующих item-level
`iconImageUrl` и `svg` в списках, picker и глобальном поиске. Detail-шапка
всегда использует независимый cover-контракт.

Саджесты используют тот же `ItemIcon` с `fallbackToType=false`: сначала
`iconImageUrl` из общего хранилища, затем inline `svg`. `color`/`filter`
применяются только к SVG, сохраняя исходные цвета растровых иконок.
Словарь, поиск, общие одиночные/множественные picker и денежный блок
принимают обе формы; `resolveSuggestIcon` отделяет URL локальной опции
от SVG-разметки, чтобы не передавать разметку в `img.src`.
В кошельке иконки имеют размер 24 px, как и в выборе валюты. Балансы
перечислены через запятую: число с разрядами и tabular nums, затем монета
справа. У записей нет рамок, подложек и видимых сокращений валют; запятая
переносится вместе с предыдущей записью. Валюта остаётся в доступном имени
группы и tooltip. Цветной отклик использует свечение числа и иконки, без
возврата рамки или подложки.
`useMoneyFeedback` наблюдает реальные изменения сумм: положительная дельта
даёт один плавный зелёный импульс, отрицательная — красный; рядом временно видна дельта.
Повторное изменение перезапускает отклик, списание до нуля удерживает группу
на 1,1 секунды перед скрытием. Первая загрузка не анимируется; reduced motion
оставляет временную цветную подсветку без пульсации и масштабирования.

`CalcPad` предоставляет `display-trailing` внутри общего дисплея справа от
выражения. Денежный редактор вставляет туда `MoneyCurrencyPicker`; backspace
остаётся справа от дисплея. Picker собирается из `ActionButton quiet`,
`BasePopover` и `OptionList`, с общими hover/focus и управлением стрелками,
Enter/Escape. Локальная композиция нужна для растровых/SVG-иконок в trigger
и вариантах, которых нет у текстового `ValueSelect`. Остальные калькуляторы
не передают слот и сохраняют обычный дисплей.

Полоса
группировки списка отделена левой и нижней границами без правой рамки.
Collection bar страницы содержит название, счётчик и добавление объекта на
всех ширинах; счётчик не дублируется в главной шапке. Landing использует общий
игровой контекст без собственного выбора системы. На ширине до 760 px список
и detail сменяют друг друга на всю доступную ширину; внешних отступов и рамки
у detail нет. Непрерывная цепочка flex-контейнеров с ограниченной высотой и
`min-height: 0` сохраняет независимую прокрутку списка и карточки.
Тот же list-owned паттерн используется в picker-модалках,
поэтому фильтры не меняют положение между справочником и сценариями выбора.
`ItemPickerModal.fixedFilters` задаёт обязательные условия предметного выбора:
они сразу участвуют в серверном запросе, видны в общей панели фильтров и
заблокированы для изменения или сброса пользователем.
`ItemPickerModal.defaultFilters` задаёт изменяемые начальные значения при
открытии или смене типа. Они участвуют в запросе наравне с обычными фильтрами:
сброс снимает их, а варианты сохраняют подсветку и подпись «По умолчанию»,
даже когда не выбраны. Повторное открытие восстанавливает начальные значения.
Ручной поиск заклинаний в листе использует этот режим для класса и кругов.
Бестиарий использует отдельный профиль с нижней границей `440px`. Фактическое
соотношение обложки задаёт предпочтительную геометрию, но портретный файл
ограничивается квадратным окном 1:1: изображение само по себе никогда не делает
шапку выше своей ширины. Production-файл `1536×1152` по-прежнему раскрывает
шапку до 4:3, а более объёмная сводка при необходимости может увеличить её
высоту, чтобы характеристики не обрезались. При смене существа профиль
сразу резервирует 4:3, не меняя соотношение на время загрузки, поэтому
переход между подготовленными обложками не меняет высоту. Формат рассчитан на высокую
композицию и боковое кадрирование на мобильном. У такой шапки нет общего
затемнения изображения: название получает компактную тёмную подложку по
содержимому, а источник, теги, основные боевые параметры, скорости и все шесть
модификаторов характеристик выводятся через summary-slot в собственных
полупрозрачных блоках. На desktop CSS Grid оставляет центральную область
обложки свободной: CR и КД стоят слева, хиты, мастерство и скорости — справа,
мировоззрение остаётся справа над сводкой, а остальные теги
стоят слева между именем и CR. Шесть характеристик образуют нижнюю полосу.
Сводка занимает всю свободную
высоту шапки, поэтому при коротких боковых группах полоса характеристик всегда
прижата к нижнему краю. На экранах до `520px` боковые группы переходят в две
колонки, характеристики — в сетку `3×2`. Навыки и
последующие разделы начинаются уже под изображением. Если содержимое сводки не
помещается на узком экране, шапка растёт по высоте, а не обрезает данные.
Оставшееся содержимое detail-карточки прокручивается по вертикали, в том числе
внутри модального окна и на узких экранах.
Типовые detail renderer получают `showTitle=false` и отвечают только за
содержимое ниже общей шапки. Технический ID объекта не занимает место на
обложке: `HandbookItemDetail` выводит его приглушённой строкой в самом низу
detail-содержимого. Рядом выводится общий `ItemAutomationBadge` — степень
поддержки механик, отдельная отметка взаимодействия с другими игроками и
пояснение через `BasePopover`. Редактирование метаданных всех типов использует
`ItemAutomationEditor`; контракт и критерии описаны в
[поддержке механик](../features/item-automation.md).

Полноценные смысловые блоки специализированных detail renderer оформляются
через общий `share-ui/DetailSection`: тематическая иконка, контрастный
uppercase-заголовок и затухающая линия связывают оружие, предметы, способности,
заклинания, существ, черты и доспехи в одну визуальную систему. Боевые блоки
используют `tone="combat"`, а повторяемые карточки с собственным названием и
описанием — `shared/ui/DetailEntryCard`. Специализированные hero/stat-блоки
типов сохраняют собственную композицию.

`window.alert`, `window.confirm`, `window.prompt` и вручную собранные во feature-коде
`position: fixed` backdrop-оверлеи запрещены. Shared picker/reporting primitives
могут владеть специализированным sheet/highlight слоем. Ошибка поля показывается рядом с
полем; ошибка операции — в состоянии формы/экрана. Если требуется новая
повторяемая категория диалога, сначала добавляется обобщённый компонент в
`shared/ui`, затем он используется фичами.

## Кармические шкалы

`SessionKarmicDiceSettings` использует общие `BaseTile`, `FormField`,
`ToggleSwitch` и `ValueSelect`. Локальный `KarmicDiceScale` — доменная
двунаправленная read-only шкала вероятности с нейтральной точкой, именем,
подписями краёв и доступным `role="meter"`/`aria-valuetext`; это визуализация состояния,
а не отдельный универсальный ввод или интерактивный slider.
Идентичность шкалы использует существующий `TransferPerson` с размером 48 px,
портретом и нейтральным avatar-slot для значков группы/мастера/NPC.
`KarmicDiceDistribution` — доменная SVG-диаграмма вероятностей d20: адаптивный
viewBox по реальной ширине, 20 столбцов, линия/заливка и эталон 5%, точный
процент по указателю, касанию или стрелкам. Она получает серверные вероятности
и не реализует повторно roller. Это график данных, а не новый базовый контрол.


`shared/ui/DiceRollResult` принимает необязательный `outcome` из события.
Он добавляет рамку и подпись критического успеха/провала, сохраняя кубики и
общий итог. Хроника и уведомления используют этот общий компонент; сам виджет
не определяет крит по выпавшему числу.

## Общие композиции рабочих мест

`shared/ui/WorkspaceHeader.vue` объединяет шапки сессии и редактора карт:
слоты identity/navigation/actions, высота 64px и ResizeObserver для dock-layout.
`WorkspaceToolsRail.vue` размещает доменные действия плавающей колонкой справа
над рабочей областью. Это композиции layout DnD Share; они не заменяют кнопки,
формы или tabs библиотеки share-ui. Управление и данные остаются в адаптерах
SessionToolsRail, ChapterGraphToolbar и MapEditorHeader/MapEditorActions.
Режимы редактора карт показывают иконки с небольшими подписями в icon-slot SlidingTabs;
название и размеры карты редактируются на отдельной странице настроек. Слева от
canvas расположен сворачиваемый MapTileSidebar с отдельной иконковой полосой
«Плитки / Объекты»; MapObjectPalette показывает только модели tileType=object; MapTilePalette показывает карточки BaseTile одной сеткой выбранной категории
без повторного заголовка и раскрываемого раздела. Полноэкранный выбор доступен и в режиме предметов.
ADMIN видит MapTileReference: MapModelFields и MapModelSlots составлены из общих
FormField/FormTextInput/FormSelect/ToggleSwitch/DetailSection; сохранение параметров
создаёт новую версию каталога. MapTileCategoryPicker использует интерактивный BaseTile с
общими для всех паков WebP-иконками TileCategoryIcon: типы тайлов и формы стен выбираются одним
набором иконок. Выбранное имя показано выразительным заголовком над иконками.
Палитра передаёт только категории с моделями текущей коллекции; поле типа в
справочнике сохраняет полный список. Начальная категория — пол или первый доступный тип коллекции.
TileCategoryIcon загружает растровые ассеты из `frontend/src/assets/maps/tile-types/`: без текста и рамки,
с прозрачным фоном. Blender-скрипт воспроизводит непрозрачные объёмные силуэты.
MapTileReference доступен ADMIN через кнопку общей шапки и открывается в AppModalFrame. Несохранённый черновик блокирует закрытие; закрывающий ActionButton проходит проверку доменного контроллера.
Справочник использует тот же MapTileCategoryPicker для выбора типа и общий
MapWallModePicker с тремя WebP-иконками расположения стен. MapModelSize сочетает
BaseTile, FormTextInput и предметную SVG-сетку 8×8: клик задаёт занимаемый
прямоугольник, стрелки меняют его стороны. MapModelPreview показывает полный
GLB через общий кэш modelAssets, свет и материалы карты; камера вращается ЛКМ.
MapModelGeometryFields связывает цветные отметки высот/смещения с общими полями.
Стыки переключаются по сферам или широким сторонам на поднятой плоскости;
клавиатурные альтернативы внутри превью используют ActionButton. Пазы показывают
зелёные сферы по каждой занимаемой клетке; выбор подсвечивает соответствующую
карточку BaseTile в MapModelSlots. Все изменения относятся к черновику параметров. MapModelPlacementPoints хранит
общие точки для предметов и персонажей; голубые сферы отличают их от опорных пазов.
Список категорий включает мосты, проходы и колонны; наполнение выбирается общим MultiToggle «Свободные / С предметами».
Он виден только при наличии обоих вариантов в выбранной категории; иначе
палитра показывает единственный доступный вариант. Последний явный выбор
пользователя сохраняется при переходах между категориями. hasDecor описывает
встроенную обстановку, независимо от canStand и точек размещения.

MapCollectionPicker размещён над левым каталогом и доступен в свёрнутом виде;
он составляет выбор пака из общих ActionButton/BasePopover/BaseTile. Доменная
композиция нужна для тематических SVG-эмблем MapPackIcon и количества тайлов
в вариантах; обычный ValueSelect показывает только текст. Выбор поддерживает
стрелки, Home/End, Enter, Escape и клик вне списка. Справочник и фильтр разделяют
один перечень TILE_TYPES, включая конкретные формы стен.
Выделение тайла на холсте подсвечивает контур и показывает действия
в плавающем баре.
Имена tutorial-целей сессии сохранены, пройденное обучение не перезапускается.

Кнопки возврата рабочего места карты и сессии используют `share-ui/ActionButton`
со слотом `icon` для стрелки и обычным текстовым слотом. `SessionBackButton` —
доменный адаптер перехода в список сессий, общий для мастера, игрока и загрузки;
базовая геометрия кнопки остаётся в библиотеке.

`SessionTabWorkspace` предоставляет два режима доменной раскладки: `full`
для всей рабочей области и `column` для центральных колонок. Панель
`SessionMapInspector` повторяет композицию боковых вкладок редактора на общих
`ActionButton`, `ToggleSwitch`, `DetailSection` и `AppSlider`; логика областей
и света вынесена в отдельные панели сессионной карты. Это доменные композиции,
общие базовые примитивы остаются в share-ui.

## Связанные страницы

[Оглавление wiki](../README.md) · [Frontend: архитектура и разработка](../frontend.md) · [Сопровождение share-ui](share-ui.md) · [CSS variables](../css-variables.md)

Заглушка ожидающей GLB-модели в редакторе — доменная Three.js-плоскость с
процедурной клетчатой текстурой и кольцом загрузки; она должна следовать координатам
3D-превью. Текстовый статус использует общий LoadingState. Цвета сфер и контуров
заданы в mapAccents: синий для тайлов, зелёный для объектов. Визуальный поворот
rotationMotion не меняет сохранённые координаты и угол документа.

Вкладка «Области» редактора — доменная композиция MapAreasPanel/MapAreaCard на
BaseTile, AddButton, FormField/FormTextInput, ToggleSwitch, ActionButton и
RemoveButton. Карточка не выводит состав: кнопка выделяет тайлы и предметы целиком.
editorAreas считает добавляемые/убираемые элементы отдельно и управляет членством
с обычной историей документа;
mapAreas задаёт скрытие в редакторе/трансляции и прозрачность в сессии.

MapPropertiesPanel открывается боковой иконкой; карта остаётся видимой.
Инструменты зон и кисть стен удалены из редактора. MapEditorActions содержит
кнопки шапки; MapSaveErrorDialog использует AppModalFrame только при ошибке
автосохранения. Настройки показывают последнее changedAt.
MapSelectionPanel накладывается на холст через отдельный aside и BaseTile внутри,
поэтому базовая относительная позиция карточки не меняет размеры canvas.
MapEntityRow — общая предметная строка: миниатюра модели/лампочка, имя, код и
количество. Она используется списком источников, группами выделения и привязкой
света. MapSelectionActions составляет выбор области из ActionMenu/ActionMenuItem.
Выбранные плитка/объект показывают крупное превью и координаты; выбранный источник
редактируется той же правой панелью. Иконки категорий палитры находятся в
растягивающихся строках BaseTile 80px с изображениями 64px; поле типа справочника
сохраняет компактный вариант.
Освещение карты — MapLightingPanel/MapLightFields/MapSunSettings и MapEntityRow на BaseTile,
ActionButton, AppSlider, ColorPresetPicker, FormField/FormTextInput/FormSelect,
CompactCheckbox и ToggleSwitch. MapLightPresetMenu сочетает общий пунктирный
AddButton с BasePopover и ActionButton: доменная композиция нужна для выбора
пресета перед вставкой в координаты Three.js. editorLightBinding принимает
следующий клик по модели, строка привязки выделяет её и центрирует камеру.
editorLighting объединяет изменение
ползунка в один шаг истории; постановка из меню и повторная вставка скопированного
источника используют useCatalogueDrag. Галка режима восстанавливает прежний
постоянный свет; галка сферы управляет только маркером редактора. Маркеры источников — предметные
Three.js-сферы для ray picking; это координаты 3D-сцены. Геометрия shadow хранится отдельным GLB, загружается при включённом освещении
и разделяется между теневыми экземплярами.
