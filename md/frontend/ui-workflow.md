# Процесс разработки общего UI

Веб и Android используют один Vue/share-ui frontend. Правила — [README](../../README.md),
адаптивность — [общий дизайн](responsive-design.md), оболочка — [Android](../features/native-client.md).
Полный набор запускается только по прямой команде пользователя.

## Рабочая копия и кандидат

Для задачи используется отдельный worktree на C. Не смешивать staging и исходники
с параллельными чатами. Node/Gradle-кеши сохраняются. Во время браузерного прогона
исходники не меняются: HMR может исказить результат. После изменения исходников
повторяется только затронутая проверка.

## Короткий цикл

Из frontend:

~~~powershell
node node_modules/vitest/vitest.mjs run src/platform/journalBuffer.test.js
node node_modules/playwright/cli.js test -c playwright.suite.config.js --project=ui tests/offline/platform.spec.js
npm run build
~~~

Из корня:

~~~powershell
.\scripts\native\build.ps1 -Target Android
.\scripts\native\build.ps1 -Target DeviceTest -DeviceSerial emulator-5580 -TestClass ru.dndshare.client.HybridShellTest
python scripts/check-wiki.py --strict
~~~

DNDSHARE_BROWSER_EXECUTABLE выбирает установленный браузер. Общий UI проверяется
в браузере; Android дополнительно проверяет платформенный bridge, lifecycle,
insets, Back, файловый picker и WebGL2. Переносить один интерфейс на Compose
и проверять две реализации каждого поля больше не требуется.

## Окружение и изоляция

Автоматический Android AVD запускается headless, с аппаратным ускорением и своим
портом. Телефон не выбирается вместо эмулятора. Не перезапускать общий ADB server.
Данные тестов фиктивные, production-аккаунты не являются фикстурами.
Физический телефон получает готовый APK по команде пользователя через install.ps1.

## Разбор сбоев и завершение

После двух одинаковых сбоев нужен минимальный репро и журнал, а не повтор всего
набора. Проверяется фактическое число выполненных instrumentation-тестов.
Сетевая ошибка, ошибка диска, отказ доступа и конфликт различаются. Проверки
локальной очереди включают потерянное подтверждение, restart и однократный повтор.

## Покадровая проверка движения

Изменённый жест или переход проверяется на обычной скорости в затронутом формате.
При изменении адаптивной композиции проверяются телефон, планшет и широкое окно.
Системное отключение анимаций и быстрый обратный переход не должны ломать ввод.

## Парное сравнение

Оба клиента отображают общий компонент. Парные снимки нужны для изменений
интеграции Android: insets, клавиатура, файлы, масштаб и рендерер WebView.
Общий дизайн и поведение проверяются на одинаковых данных в одной реализации.
Старый runner сравнения Compose/Vue относится к историческим коммитам.

## Тёплый выпуск

Сайт и APK выпускаются из точного чистого commit. Один frontend dist встраивается
в Go и APK; native build не имеет своей версии экранов. Копии .gz/.br исключаются
из Android assets, сами HTML/CSS/JS совпадают. Публикация описана в [deploy](../deploy.md).
Перед установкой APK проверяется SHA-256 через release.json и install.ps1.
