# Работа над общим UI

Двигаемся небольшими законченными участками: одно состояние экрана или компонент
сразу в вебе и Android. До реализации определяем данные, три композиции окна
и ожидаемые действия. Общие величины меняем в
[токенах](../../design/README.md), примитивы — у их владельца, предметную
композицию — в приложении. Промежуточный узкий тест ускоряет обратную связь;
перед выпуском выполняется полный набор затронутых строк матрицы.

## Подготовка Windows/WSL

Точка входа из корня checkout на диске C — `python3 scripts/ui.py`.
Команды используют локально установленные Node, Go, PostgreSQL, Chromium,
Android SDK/JBR и Windows ADB. Пути хранятся в игнорируемом
`build/dev-tools/local-tools.json`; `doctor` проверяет версии, реальные запуски,
зависимости frontend и доступный эмулятор. Локальный файл путей переносить в Git
или использовать как список универсальных путей для другого ПК нельзя.

```bash
python3 scripts/ui.py doctor --emulator emulator-5554
python3 scripts/ui.py prepare
```

`prepare` печатает путь новой копии под `build/ui-workspaces/`. Ниже `$UI_WORKSPACE`
обозначает этот абсолютный путь. Копия содержит исходники, корневые ресурсы и
фикстуры с LF, собственные Linux npm dependencies. Windows `frontend/node_modules`
основного checkout не заменяется. Установки и артефакты находятся на C; горячие
временные кеши Vite/PostgreSQL используют Linux temp из-за семантики NTFS/WSL.

## Короткий цикл и полная проверка

```bash
python3 scripts/ui.py focus webunit --workspace "$UI_WORKSPACE" --file src/features/handbook/pages/ViewHandbook.test.js
python3 scripts/ui.py focus browser --workspace "$UI_WORKSPACE" --project ui --file tests/navigation/app-shell.spec.js
python3 scripts/ui.py focus native --workspace "$UI_WORKSPACE" --target Test
python3 scripts/ui.py verify --workspace "$UI_WORKSPACE" --tag backend
python3 scripts/ui.py review --workspace "$UI_WORKSPACE" --emulator emulator-5554
```

Имя браузерного файла выбирают из текущего `frontend/tests/`; пример заменяется
файлом затронутого сценария. Для UI-only задачи флаг `--tag backend` не нужен;
перед серверным runtime deploy Go test/vet/build обязательны. `verify` запускает
полные web unit/build/browser, native All/DeviceTest, проверку токенов, шрифтов,
палитры/иконок и wiki. Отдельные backend DB/API сценарии выбираются по
[матрице](../testing.md#матрица-проверок).

Копия сохраняет commit и отдельный хеш фактических исходников: незакоммиченные
изменения не выдаются за содержимое commit. По умолчанию runner отвергает устаревшую
копию. После правок выполняют новый `prepare`; явный `--snapshot` позволяет
проверить зафиксированный срез во время дальнейшей работы и помечает его так
в квитанции. Исходники проверяемой копии во время запуска менять нельзя.
Логи и JSON-квитанции находятся в `build/ui-runs/`; ошибки дают ненулевой код.
Лимит этапа — 3600 секунд, меняется через `--timeout`; лимиты отдельных
Playwright-сценариев остаются в их конфигурации. Тяжёлые браузерные прогоны
запускают последовательно, чтобы конкуренция за CPU/GPU не искажала таймауты.
Параллельный доступ к копии и эмулятору блокируется.

## Парный отчёт

`review` поднимает изолированный PostgreSQL и настоящий Go API, использует
фиктивный аккаунт и один набор данных для браузера и APK `.smoke` на эмуляторе.
Телефон пользователя и production-данные не участвуют. Временные настройки
размера/плотности эмулятора восстанавливаются после запуска.

Набор включает справочник: коллекции, открытое меню, список коллекции, запись; размеры 390×900,
834×1100 и 1920×1000 CSS px / dp. В набор входят также D&D «База»/«Статы»,
открытый морф характеристики и VTM «База»; всего 48 снимков и HTML с парами рядом.
Нативный прогон проверяет свайпы трёх форматов, раскрытие окна с открытой формой
и восстановление после системного завершения фонового процесса. Конфликтная
правка на сайте не должна затираться восстановленным вводом. После проверки
фиктивные данные возвращаются к исходному состоянию.
Отчёт фиксирует хеш исходников и фикстуры, API-свидетельства, размеры и системные
отступы Android, зарегистрированные исключения. При переносе следующего участка
в набор добавляют его состояния и соответствующие фикстуры.

Проверяем иерархию, отступы, плотность, переносы текста, состояния и отсутствие
обрезания. Шрифты загружаются локально до снимка. Системные панели Android
видны отдельно от содержимого. Автоматическая проверка целостности снимков
не доказывает визуальное совпадение: пары просматривают, исправляют необъяснённые
расхождения и предъявляют пользователю для приёмки. Новые намеренные различия
предварительно обсуждают и фиксируют в
[реестре](../../design/visual-exceptions.json). Обычная правка общего UI не требует
дополнительного согласования самого запуска проверок или штатного выпуска.
