# Миниатюры: очередь и исходные архивы

## Очередь производства

[production-queue.py](../../scripts/creatures/production-queue.py) выполняет
постоянную очередь из JSON-манифеста. Один процесс владеет блокировкой рабочей
папки; модели и их этапы обрабатываются последовательно. Статус можно читать
параллельно без ключа и сети:

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/production-queue.py scripts/creatures/pilot-production.json --workdir models/creatures/pilot-20261024
```

Рабочий пример — восемь видов MM с [принятыми рецептами](../../scripts/creatures/pilot-recipes/).
Состав, визуальные ограничения и замер поля описаны в
[отчёте пилота](../reports/creature-miniatures-pilot-2026-10-25.md).

Запуск генерации добавляет `--run --until native --token-stdin --server-token`. Это скрытый
ввод личного HF-ключа; автоматизация может передать его через наследуемый pipe
`--token-fd`. Содержимое ключа не должно попадать в аргументы процесса или файлы.
`--watch` ждёт появления проверенных референсов в рамках текущего запуска;
это не фоновый планировщик и не автоматическое согласие на новый расход квоты.
`--only wolf-1692,boar-1745` ограничивает выбранные задания.
Режим native включает создание архива; с `--server-token` его загрузка и проверка
в S3 завершаются **до следующей генерации**. Без флага архив остаётся локальным.
Ошибка раннего резервирования останавливает весь набор. Повтор использует уже
полученный native и повторяет резервирование, не GPU. Полностью кешированный
повтор не читает ключи и не обращается к MCP.

Для каждого slug перед генерацией подготовить:

- `recipe.json`: идентификатор итема/модели, калибровка, профиль материалов,
  `artProfile`, `supportKind`, измеренный `reviewBase`, метаданные и имена файлов
  по общему контракту миниатюр; правила выбора — [качество](creature-model-quality.md);
- `handbook-item.json` и `handbook-reference.jpg`: прочитанный публичный итем и
  иллюстрацию; `reference-prompt.txt`: фактически принятый промпт;
- `miniature-reference.png`: принятый результат imagegen;
- `reference-review.json`: `approved:true`, `imageSHA256` и замечания осмотра.

Ключи, cookie, env-файлы и приватные ответы авторизации в эти файлы не входят.
Изменившаяся картинка требует нового осмотра. Изображения не создаются очередью.

`production-state.json` записывается атомарно с режимом 0600. Каждый этап хранит
хеш входов, попытки, время, состояние и SHA выходных файлов. Повтор пропускает
точно совпавший завершённый этап. Новые параметры пересчитывают производные
этапы; изменение/утрата завершённого файла останавливает обработку вместо
незаметной новой генерации. Ошибка одной модели не отменяет локальные результаты
остальных. Текст исключений с потенциальными секретами в state не сохраняется.

Порядок: native → архив native → geometry → bake → optimize → render → placement →
silhouette → verify → **осмотр** → ready → архив ready → published.
`trellis-native`, `geometry`, `baked`, `final` разделены: оптимизация каждый раз
копирует свежий bake, поэтому повторный запуск не пережимает уже готовый JPEG.
Подробные локальные журналы команд находятся в `logs/`.

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/production-queue.py scripts/creatures/pilot-production.json --workdir models/creatures/pilot-20261024 --run --until ready
```

Готовый native не требует HF-ключа. Рендеры включают перед, спину, оба бока,
верх, LOD и серый материал. Placement дополнительно создаёт on-base/on-base-top
с фактическими размером, диаметром опоры и подъёмом ног. Рецепт задаёт:

```json
{"artProfile":"painted","supportKind":"grounded","reviewBase":{"modelId":"3c506a01-f906-5627-a53e-e1198a33968a","file":"models/creatures/separated-bases-20261024/3c506a01-f906-5627-a53e-e1198a33968a.glb","referenceDiameter":0.9,"surfaceHeight":0.06}}
```

`placement-review.json` связывает картинки с GLB, размером, калибровкой,
материалами, политикой текстур и SHA/метаданными основания. Изменение этих входов
перестраивает примерку. При успешной технической проверке очередь ждёт
`final/model-review.json` schema 2: `approved:true`, полный `context`, его
`contextSHA256` и замечания. Контекст включает четыре GLB, текущие ракурсы и
доказательство примерки. Одних прежних render/lod SHA недостаточно.

После визуального осмотра сформировать запись инструментом:

```bash
python3 scripts/creatures/review-miniature.py models/creatures/SLUG/final models/creatures/SLUG/recipe.json
python3 scripts/creatures/review-miniature.py models/creatures/SLUG/final models/creatures/SLUG/recipe.json --approve --notes-file models/creatures/SLUG/review-notes.txt
```

Первая команда только показывает контекст. Вторая требует реальных замечаний
оператора; passed verifier не является визуальным осмотром. Только действующий
осмотр разрешает упаковку и прямую публикацию. Отсутствие/устаревание осмотра возвращает
ненулевой код завершения для цели ready/published, но сохраняет все результаты.
Нельзя выставлять approved по одному passed verifier.

Манифест задаёт бюджеты `maxGenerations`, `maxGpuCalls`,
`minRemainingGpuSeconds`; paid overquota очередь не поддерживает. Перед каждой
GPU-задачей перечитывается личная квота сервиса. Резерв записывается **до** POST,
включая неудавшиеся/неподтверждённые отправки. Исчерпание лимита останавливает
весь набор. Нет автоматического нового seed, нового каталога или повторного
расчёта после неизвестного POST. Правила продолжения сессии — на
[странице восстановления](creature-model-checks.md).
Новая намеренная генерация задаётся явно: `nativeAttempt:2`, новый `seed` в
манифесте. Она использует отдельную `trellis-native-2`, не удаляет первую попытку
и расходует общий бюджет набора. Очередь сама не увеличивает номер попытки.

Параметры QEM и калибровку принимают после осмотра. `dropComponentsBelow` —
явное удаление мелких несвязных островов после сварки; `fillSmallHoles` —
заполнение треугольных/четырёхугольных дыр. Это локальные исправления производной
геометрии; оригинал сервиса сохраняется. QEM сохраняет нижнюю точку контакта
в исходных координатах, без отдельного смещения роли. Все изменения требуют
повторного bake, LOD-проверки и осмотра.
`lodAggression`, `shadowTriangles`, `shadowAggression` задают явный компромисс
упрощения. Если QEM не достиг бюджета, проверка останавливает модель; лимиты
не повышаются молча.
Для мелких полостей генератора доступен явный `surfaceClosure:{pitch,radius}`:
`close-native-surface.py` строит геометрию через voxel closing/fill, затем QEM
и bake используют её в исходных координатах. Оригинальный подробный GLB и его
материалы сохраняются для переноса текстур и архива. Обработка ограничена
64 млн вокселей; может потерять тонкие детали, поэтому назначается конкретной
модели после осмотра. `closed-source.glb/json` сохраняют исправление и параметры.
Проверка watertight и LOD не заменяет пересчёт конечностей и проверку окраски.

## Архивы в S3

Это отдельные исходники, не ресурсы рендера карты. Добавочной таблицы БД нет:
неизменяемый S3-ключ содержит item ID, запланированный/зарегистрированный UUID
модели, этап и SHA сжатого архива:

`creature-model-archives/<itemId>/<modelId>/<native|ready>/<sha256>.tar.gz`.

`native` сохраняет оригинальный GLB сразу после экспорта, референсы, промпт,
рецепт и исходники инструментов. `ready` дополнительно содержит геометрию,
упакованный `.blend`, полные bake-карты, окончательные GLB, виды, принятый
осмотр, отчёты, каталог и `review/base.glb` для воспроизводимой примерки.
Каждый архив содержит manifest с per-file SHA/size,
Git commit и признаком незакоммиченных изменений workflow. Конкретные версии
скриптов вложены и проверяются по SHA, включая случай dirty commit.
Список файлов явный: checkpoint с session ID, временные service URL, env,
логи и publication receipts не архивируются.

MCP требует действующую авторизацию, а prepare/complete — `MCP_WRITE_ENABLED`:

| Инструмент | Назначение |
| --- | --- |
| `creature_model_archive_prepare_upload` | Подписанный PUT во временный S3-объект на 15 минут. |
| `creature_model_archive_complete_upload` | Проверка и перенос в неизменяемый ключ; повтор безопасен. |
| `creature_model_archive_list` | Список по itemId, включая ещё не опубликованные модели; nextCursor. |
| `creature_model_archive_get` | Подписанный GET известного архива на 15 минут. |

Prepare/get/complete получают `itemId`, `modelId`, `stage`, `sha256`, `size`.
Complete дополнительно получает `uploadKey`; list — `itemId` и необязательный
`cursor`. Сервер проверяет полный SHA/размер gzip, первый manifest, допустимые
пути, регулярные файлы без ссылок, состав и хеш каждого файла. Лимиты: 512 MiB
сжатого, 2 GiB распакованного, 256 файлов. Неполный ready архив отвергается.
Завершённый объект также проверяется при повторном complete. Временный объект
удаляется после переноса; незавершённые загрузки не становятся опубликованными.

Добавление `--server-token` к очереди ready/published включает отправку архивов
через ранее разрешённый MCP-ключ проекта. Без этого флага архивы только локальные.
Для отдельной операции:

```bash
python3 scripts/creatures/model-source-archive.py models/creatures/SLUG --stage native
python3 scripts/creatures/model-source-archive.py models/creatures/SLUG --stage ready --publish --server-token
python3 scripts/creatures/model-source-archive.py --restore-receipt models/creatures/SLUG/archives/ready-publication.json --destination models/creatures/restored-SLUG --server-token
```

Локальный `--restore ПУТЬ.tar.gz` работает без сети. Распаковка потоковая,
с ограничением объёма, проверкой состава и SHA; пишет во временную папку и
переименовывает только после успешной проверки. Папка назначения должна быть
новой. Восстановление ничего не запускает и не меняет реестр.

Из восстановленной папки доступны `native/generated-original.glb`, `recipe.json`
с `calibration`/`build`, исходники workflow и принятые outputs. Для повторной
обработки использовать `prepare-native-geometry.py --source` и
`bake-native-miniature.py --source --geometry-dir`; для прямого исправления —
упакованный `baked/model.blend`. История серверной HF-сессии не восстанавливается
из архива: законченный native больше не нуждается в этой сессии.
При переносе создать рабочую копию рецепта и направить `reviewBase.file` на
восстановленный `review/base.glb`. Локальный путь не входит в визуальный контекст;
SHA и физические параметры основания входят. Сами архивные файлы не менять.
Автоматический импорт всей очереди из архива не реализован: это восстановление
исходников для локальной обработки, не восстановление приватного HF checkpoint.

## Публикация

`--run --until published --server-token` отправляет только проверенный bundle,
читает обратно модель/связи и сохраняет подтверждённый receipt. Повтор использует
существующий receipt как guard от перезаписи чужих ресурсов. Состояние очереди
и архив не заменяют проверку текущего реестра.
