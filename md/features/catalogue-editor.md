# Редактирование справочников

Схема задаёт хранение данных; `catalogueProfiles.js` — композицию фиксированных
коллекций, `catalogueFields.js` — подписи, единицы, условную видимость и контролы.
Неизвестное профилю поле схемы остаётся в дополнительных настройках. Общие поля
используют `AbilityRuleField` и примитивы share-ui, без второй реализации инпутов.

## Результат проверки

Проверены схемы и реальные публичные записи всех 18 типов. Основные недостатки
были в редакторах: плоские формы, числовые ссылки, неподдержанные вложенные типы,
отсутствующие в схеме поля работающих механик. Специализированные списки и карточки
большинства типов сохранены; предыстории получили собственную карточку, предыстории
и эффекты — содержательную подпись строки. Карточка вещи показывает её правило КД.

| Справочник | Композиция и поведение |
| --- | --- |
| Оружие | Свойства и владения, составляющие урона, дистанции, цена и вес. Урон двумя руками доступен для универсального оружия; дистанции — в том числе для метательного. |
| Вещи | Назначение, редкость, контейнер/расходование и учёт длины. Содержимое набора и правило защиты добавляются отдельно. |
| Заклинания | Круг, школа, описание и классы слева; сотворение и компоненты справа. Урон, лечение и эффекты добавляются по необходимости. Спасбросок и рост выбираются по названиям. |
| Бестиарий | Вид существа, описание, параметры боя и характеристики. Спасброски, защиты, чувства, особенности, действия и реакции — отдельные разделы. Скорости редактируются строками, действия — rich editor. |
| Черты | Общий редактор зависимостей способностей, включая все требования, повторное получение, бонусы характеристик и связанные выборы заклинаний. |
| Расы / подрасы | Размер, скорость, бонусы, владения, выборы и именованные варианты расы. Подраса выбирает родителя; обратный список подрас не редактируется вручную. |
| Классы / подклассы | Основы класса, владения и стартовое снаряжение. Заклинательство, прогрессии и ресурсы добавляются отдельно. Уровни ASI выбираются переключателями. Подкласс выбирает родителя. |
| Зелья | Редкость, цвет, описание, цена и дробный вес. |
| Предыстории | Особенность, владения, языки, снаряжение, монеты и выборы предметов. Ссылки выбираются по названиям. Карточка показывает эти правила и кликабельное снаряжение. |
| Доспехи | Категория, владение, формула КД, ограничения, цена и вес. Щит показывает прибавку; доспех — основу, Ловкость и её предел. |
| Транспорт | Категория определяет доступные настройки: скакун ссылается на бестиарий, транспорт получает вместимость и прочность, седло — свои свойства. |
| Инструменты | Назначение, владения, редкость, контейнер, цена и вес. |
| Эффекты | Автоматический ключ, описание, тезисы, длительность и наложение. Изменения показателей и защиты используют редакторы способностей без лишнего уровня персонажа. |

Расовые, классовые и сюжетные способности сохраняют общий редактор,
описанный в [манифесте способностей](ability-editor-manifest.md).

## Правила интерфейса

- Две независимо прокручиваемые колонки на широком экране, общая прокрутка на узком.
  Название, иконка, обложка и компактный выбор публикации общие для всех типов.
- У личных объектов публикация не запрашивается. Сокращение источника бестиария
  не дублирует управление публикацией в форме.
- Заполненные необязательные разделы видны сразу; пустые добавляются через
  «Добавить настройки». Для раздела из одного списка первая запись появляется сразу.
- Подписи и единицы находятся у полей, пояснения — при наведении. Вложенные группы
  отмечены отступом и линией. Удаление раздела/записи — корзина у заголовка
  с подтверждением; отключение заполненной необязательной настройки также подтверждается.
- Смена щита, Ловкости, роста заклинания или длительности очищает несовместимые
  значения. Простое открытие не очищает неизвестные свойства. Новые ключи получаются
  из названия, ручные остаются стабильными.
- Выбранные значения словаря показываются строками. Выбор снаряжения поддерживает
  дочерние коллекции вещей; переход между коллекциями не сбрасывает общий выбор.
- Сохранение проверяет числовые границы, дистанции, ключи повторяемых записей,
  кости и варианты выбора. Игровые расчёты остаются общими с листом персонажа.

## Хранение и проверки

Миграция `84_catalogue_editing.sql` меняет только схемы `item_type.fields`,
не содержимое предметов. Она добавляет используемые поля рас и заклинаний, ключ
эффекта и рост ячеек класса, исправляет ссылки предысторий и дробный вес.
`item_array` хранит числовые ID; простой `object_array` ссылок сохраняет `[{id}]`.
Снимки схем находятся в `resources/items`.

`CatalogueEditor.test.js` проверяет охват типов, формы, условную видимость,
сохранение ссылок, рост урона и заклинательство по уровню класса.
`useItemMultiSelect.test.js` проверяет общий выбор между коллекциями и поздние ответы.
`TestCatalogueEditingMigration` через `DNDSHARE_CATALOGUE_TEST_DSN` на отдельной
локальной базе `dndshare_test_*` проверяет слияние схем, новые поля, сохранность
остальных типов и повторное применение без дубликатов.

Магические предметы выделены из вещей в коллекцию 19. Их свойства, общий редактор зависимостей и правила экземпляров описаны в [«Магические предметы»](magic-items.md).
