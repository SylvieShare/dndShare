# Toxic Sewer

Индивидуальная обработка моделей редактора по
[общему порядку](maps-model-pipeline.md). Исходники — неподдержанные STL из
локального авторского пакета; PDF используется для палитры и разделения
поверхностей. Файлы остаются в игнорируемом `models/collections/toxic-sewer/`.

Первичная индивидуальная обработка и MCP-публикация выполнены для всех 105
моделей. Итоговая проверка набора продолжается: UV-аудит выявил пересечения
в 81 модели. Исправлено 26, осталось 55.
Таблица ниже подтверждает текущие ресурсы, но не завершение этой
дополнительной проверки всего набора.

## Рецепт и проверки

[Рецепты](../../scripts/maps/toxic-sewer-recipes.json) задают бюджет геометрии,
карт и веса отдельно для каждой принятой модели. Подготовка одной модели:

```bash
go run ./cmd/map-model-upload -snapshot models/collections/toxic-sewer/registry-snapshot.json
node scripts/maps/prepare-toxic-sewer.mjs TS-001
```

`toxic_sewer_bake.py -- --report <report.json>` запускается локальным Blender:
строит корпус из исходного скульпта, упрощает render и LOD перед новой UV,
запекает normal/AO. По умолчанию монтажные меши принятой версии сохраняются.
При подтверждённой ошибке прежнего упрощения рецепт явно задаёт монтажную
геометрию из STL; проверяются её исходные границы, глубина, начало координат,
занимаемая площадь и сквозные отверстия в декодированных render/LOD/shadow.
Для видимого декора ниже монтажного уровня `mountRegions` задаёт измеренные
траектории, радиусы и PBR-параметры отдельных граней крепления. TS-053 сохраняет
нижние медные стойки и перекладину лестницы внутри шахты. Эти параметры входят
в геометрический рецепт и требуют полного `prepare` при изменении.
`paint-toxic-sewer.mjs <report.json>` размечает цвет и PBR на физической
поверхности UV. Зелёная кладка имеет вариацию оттенка и влажности; швы пола
следуют измеренному рельефу. Свет не запекается в цвет.

У TS-039/040 отдельная emissive-карта размечена только по стеклу; рамка,
решётка и кладка остаются несветящимися. GLB использует `emissiveTexture`
и `emissiveFactor` стандартного материала. Через MCP дополнительно
зарегистрирован и повторно прочитан источник `wall-lamp`: цвет `#e6c62a`,
intensity 3, radius 2,5 клетки, включён, без мерцания. Координаты
`[0.5,0.215,0.665]` для TS-039 и `[0.5,0.17,0.728]` для TS-040
следуют положению стекла; высота исключает монтажную глубину.
Рецепты сохраняют эти параметры в `defaultLight`; изменение поведения
выполняется отдельно через MCP с текущей revision и сохранением переходов.
У TS-043/044 измеренные объёмы драгоценных камней имеют отдельные цвет,
roughness и metallic; маски деревянной рамки предшествуют содержимому.

Узкие UV-треугольники могут не покрыть ни одного центра пикселя. Их поля
albedo/ORM/emissive заполняются по ближайшей физической грани до расширения
краёв островов; это устраняет золотые точки на дереве и камне рядом с кладом.
Полностью пустая UV-развёртка отклоняется. Угол SmartUV по умолчанию —
0,55 rad, отступ островов — 0,0025; слишком большой отступ при множестве
островов может схлопнуть площадь, поэтому проверка покрытия обязательна.

Для добавленных деталей `toxic_sewer_reference.py` измеряет пол и переднюю
поверхность голого авторского аналога с шагом 0,2 мм. Объёмные маски труб,
дерева, костей и жидкости учитывают обе стороны детали и сдвиг принятой
системы координат. Проверка расстояния до голой кладки исключает попадание
металлического цвета и metallic на соседний кирпич. Рецепты хранятся
отдельными файлами в scripts/maps/toxic-sewer-recipes/.
`ellipsoid.basis` задаёт три ортонормированные оси наклонной детали:
радиусы относятся к проекциям на эти оси. TS-041 использует такую маску
для жидкости за боковым окном, исключая выступающий металлический обод.
Для низкой воды без вертикальной стены эталон содержит пустую сетку стены;
маски используют измеренную поверхность жидкости. Этот случай и пустой
допустимый диапазон проверяет `test_toxic_sewer_reference.py`.
У наклонного свода диапазон передней стены задаётся рецептом через
`referenceWallMinYMM`; кэш эталона пересоздаётся при смене этого параметра.
TS-086 использует Y от 3 мм, чтобы исключать из медной окраски наклонную кладку.
Для сложного излома `referenceFloorMaxZMM` включает всю высоту исходника:
маска `topSurfaceMM` следует верхней поверхности по XY, сохраняя нижние
вертикальные грани. TS-091 ограничивает эту маску собственно колонной,
исключая ступени основания.
Для низкой воды `surfaceBandMM` ограничивает расстояние до измеренной высоты
с обеих сторон. В TS-056 это сохраняет каменной высокую внутреннюю стенку
канала, которую односторонняя проверка высоты ошибочно окрашивала как жидкость.

Если новая деталь оборачивается вокруг старого дерева или металла,
`toxic_sewer_proximity.py` измеряет расстояние до полной поверхности голого
аналога. `toxic_sewer_proximity.mjs` интерполирует сетку расстояний; painter
проверяет SHA-256 исходника и самой сетки. В TS-095 сетка TS-035 с шагом
0,35 мм охватывает весь бак и верх стены: маска щупалец исключает прежние
доски, обручи и кладку. Наследованные деревянные части задаются собственными
объёмами, без повторной проверки добавленной поверхности.
Рецепт может повернуть голый аналог через `rotationZDegrees` и использовать
отдельный эталон высоты жидкости. SHA-256 сетки расстояний сверяется с архивным
исходником её собственного code: в TS-099 пустой тупик TS-067 повёрнут на90°,
а высота открытой воды измеряется на TS-099 ниже костей. Это исключает
попадание костного материала на старый берег и использование верхушек черепов
как уровня жидкости.
Для мокрых берегов `minimumSurfaceZMM` оставляет в эталоне расстояний
только верхнюю часть пустого канала. TS-056 сравнивается с TS-065 выше11,6 мм:
старая стенка исключается из жидкости, а уже затопленные мелкие камни
не создают ложных каменных пятен на воде.
Искусственные грани, закрывающие срез рабочей копии эталона, исключаются из
дерева расстояний. Проверка TS-059 выявила, что такая плоскость среза
отсекала часть настоящей волны; эталон учитывает только исходную поверхность берега.
`added: "height"` выбирает отдельный эталон высот для новых костей,
когда поле расстояний занято старым каменным берегом. В TS-057 череп и
длинная кость сравниваются с водой TS-056, а жидкость — с верхним берегом TS-065.
`added: "both"` требует и новой высоты, и удаления от старого берега;
в плотной группе TS-063 это защищает каменную рамку от костного материала.

`validate-toxic-sewer.mjs` проверяет дрейф границ, сохранность монтажной
геометрии, отклонение от STL и дефекты используемых UV. Превью и виды обеих
сторон создаёт `preview-model-revisions.py`; сравниваются render и LOD,
полный габарит и более лёгкий вариант карт. `prepare-reviewed-shadow.mjs`
строит отдельную геометрию теней из выбранного LOD;
`toxic_sewer_shadows.py` проверяет её с двумя направлениями солнца и
точечным светом. Публикуемое WebP проверяется через `transparentPreview`:
прозрачные углы, запас до краёв, неизменённый alpha после сжатия.
Диагностические снимки используют AgX; камера восточного солнца смотрит
со стороны тени, чтобы модель не закрывала её от проверяющего.

`sewer_crop.py` закрывает сечение сразу по всем контурам: внутренние
контуры остаются отверстиями. `test_sewer_crop.py`, запускаемый Blender,
проверяет площадь кольцевого сечения и лучи через шахту отдельно для корпуса
и монтажной части. Отдельно проверяется конечная геометрия после Meshopt.

Пакет создаёт `package-masonry.mjs --collection=toxic-sewer
--base=models/collections/toxic-sewer/detailed/<code>
--recipe=toxic-sewer-individual-v1`. Все пять ресурсов проходят
`TestPreparedCollectionManifest` со свежим реестром сравнения. Загрузка —
`cmd/map-model-upload -workers 1`, подтверждение —
`confirm-reviewed-model.mjs <code> <fresh-snapshot> --collection=toxic-sewer`.
После подтверждения `record-reviewed-model.mjs` обновляет локальную очередь.
Непубликованные модели не отмечаются завершёнными.
`process-toxic-sewer.mjs <code> prepare` выполняет подготовку и сохраняет
сравнение принятой версии с полной и облегчённой новой версией.
`process-toxic-sewer.mjs <code> repaint` повторяет окраску и сравнения без
повторного упрощения и запекания. Он допускает только неизменённые исходные
ресурсы, параметры модели и геометрический рецепт; конечные render/LOD сверяются с предыдущей
подготовкой по геометрии и UV. Изменение монтажных параметров или материала видимой
внутренней части крепления требует полного `prepare`.
`process-toxic-sewer.mjs <code> publish --candidate=<name>
--review-note=<inspection-result>` публикует только одну осмотренную модель,
проверяет актуальность исходных ресурсов и параметров и подтверждает запись свежим MCP-чтением.
`record-toxic-sewer.mjs` обновляет таблицу ниже только по подтверждённым
публикациям и сверяет SHA-256 и фактические размеры локальных файлов с реестром.
UUID остаётся постоянным при обработке; одного совпадения UUID недостаточно
для проверки исходного состояния. `toxic_sewer_baseline.test.mjs` проверяет
отклонение изменившихся ресурсов и размещения при том же UUID.
`prepare --revise-uv` исправляет развёртку уже опубликованной модели:
принятые render/LOD и крепление сохраняются, UV создаются заново и normal/AO
запекаются с исходного STL. Все треугольники сравниваются с текущими ресурсами,
а каждый используемый пиксель UV проверяется на поверхности дальше0,1 мм.
Проверяются и исходный размер запекания normal/ORM, и фактический размер
albedo выбранного облегчённого варианта; результат хранится в `uvAtlasSizes`.
Старый локальный отчёт помечается заменённым только после MCP-подтверждения;
UUID модели остаётся прежним, журнал учитывает её один раз.
Свежие чтения реестра повторяются до трёх раз с ограниченной задержкой
при временных HTTP502/503/504 и обрывах соединения
(`UND_ERR_SOCKET`, `ECONNRESET`, `ETIMEDOUT`). Если регистрация уже завершилась,
восстановление выполняется свежим чтением и сравнением с проверенным пакетом;
повторная загрузка не требуется. Старый отчёт заменяется только после
подтверждения всех пяти ресурсов и параметров.

При параллельных изменениях backend можно задать `MAP_MODEL_BACKEND_ROOT`
с путём к чистой копии актуального commit и ссылкой `models` на рабочие файлы.
В ней выполняются manifest-проверка, загрузка и общие скрипты упаковки,
подтверждения и регистрации. Подготовка геометрии и материалов использует
скрипты текущего рабочего каталога.

геометрия присосок и кривые кончиков сохранены в render и LOD.

Результаты и сравнения: `models/collections/toxic-sewer/detailed/<code>/`;
новые папки подготовки содержат префикс SHA-256 исходного render из реестра.
Старые рабочие папки сохраняют прежние имена; их подтверждённые ресурсы
сверены с текущими UUID после перехода реестра к постоянным ID.
Пакет и свежий MCP-реестр подтверждают хэши и размеры пяти ресурсов;
локальные снимки и журналы других коллекций не используются для этой очереди.
