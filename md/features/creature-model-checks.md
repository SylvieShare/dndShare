## Продолжение TRELLIS

`generate-trellis.py` сохраняет каждый этап в рабочей папке. Повторяется та же
команда с тем же изображением, seed и resolution:

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/generate-trellis.py models/creatures/SLUG/miniature-reference.png models/creatures/SLUG/trellis-native --seed ITEM_ID --resolution 1024 --token-stdin --allow-pro
```

Файлы состояния:

- `trellis-checkpoint.json` — SHA изображения, параметры, идентификатор серверной
  сессии, состояния этапов, ID принятых задач и хеши локальных файлов.
- `trellis-results/<stage>.json` — полученный ответ этапа. Записывается до перехода
  checkpoint к следующему этапу, поэтому обрыв между этими записями восстанавливается.
- `trellis-input.png`, `generation-preview.html`, `generated-original.glb` — результаты.
- `generation.json` — итог с originalMeshExported, параметрами, размером и SHA GLB.

Запись атомарна, checkpoint/ответы имеют режим 0600. Ключ HF остаётся в памяти
и не сохраняется. Сессионные ID и URL не выводятся в отчёт консоли. Блокировка
`.trellis.lock` запрещает два параллельных генератора в одной папке и снимается
при завершении процесса. Другие выходные папки независимы.

| Где прервалось | Следующий запуск |
| --- | --- |
| Подготовка изображения | Использует сохранённый результат либо продолжает CPU-этап. |
| Ожидание подтверждённой задачи | Забирает тот же event ID через SSE, без повторного POST. |
| Генерация завершена, экспорт отклонён по квоте | Повторяет только extract_glb в той же сессии. |
| GLB готов на сервисе, скачивание оборвалось | Скачивает файл по сохранённой ссылке, не запускает GPU. |
| GLB уже сохранён и проверен | Возвращает локальный результат без сети и запроса ключа. |
| Ответ на POST потерян до получения ID задачи | Останавливается: неизвестно, принят ли запрос. Автоматического дубля нет. |
| Сервис удалил сессию/задачу | Останавливается с сохранёнными локальными результатами. |

`--views-only` останавливается после видов; запуск без него продолжает экспорт.
`--status` показывает состояния без сети, чтения ключа и изменения файлов; работает
параллельно генератору. `--wait-timeout 600` ограничивает ожидание одной задачи
за запуск. Изменившееся изображение/параметры или повреждённые локальные результаты
не используются молча. Неподтверждённый запрос не отправляется повторно; явный
отказ HTTP до принятия задачи допускает исправление авторизации и повтор.

Продолжение зависит от сервиса. [Официальный Space TRELLIS.2](https://huggingface.co/spaces/microsoft/TRELLIS.2/blob/main/app.py)
передаёт промежуточные latent-данные через Gradio State. На компьютере сохраняется
доступ к этой сессии, а не копия latent-данных. Перезапуск Space, очистка состояния
и удаление готового файла могут сделать продолжение невозможным. Инструмент
не восстанавливает уже утраченные сессии старых запусков без checkpoint.
Новая генерация выполняется в новой папке и считается отдельной попыткой.

Транспорт читает config/API info и использует очередь/SSE Gradio с прежним
session_hash; номера функций не зашиты. Схема параметров сохраняется и проверяется
при продолжении. Протокол проверен на Gradio 6.1.0 официального Space, включая
повторное подключение к существующей CPU-задаче. При изменении протокола требуется
повторная проверка адаптера; результат GPU не имитируется.

## Сравнение силуэта render/LOD

После оптимизации файлов и перед verify-single-miniature:

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/compare-lod-silhouette.py models/creatures/SLUG --recipe scripts/creatures/RECIPE.json
node scripts/creatures/verify-single-miniature.mjs models/creatures/SLUG scripts/creatures/RECIPE.json
```

Для файлов реестра можно задать `--render ПУТЬ --lod ПУТЬ`; первый аргумент остаётся
папкой отчёта. Тест не изменяет GLB и не требует GPU или Blender.

Сравниваются 17 ортографических проекций: восемь направлений с шагом 45° на
высотах 0° и 30°, плюс вид сверху. Все матрицы GLB применяются, включая нативный
масштаб дочерних узлов. Обе роли используют одну камеру, вычисленную по render;
LOD не центрируется и не вписывается отдельно. Выход его геометрии за кадр
помечается ошибкой, чтобы обрезка не скрывала лишние детали.

`lod-silhouette.json` содержит policy, хеши обоих GLB, метрики каждого вида и
итог passed. `lod-silhouette.png` — контактный лист: серое совпадает, розовое
пропало в LOD, голубое появилось. Силуэт оценивается по непрозрачной геометрии;
модели с alphaMode MASK/BLEND отвергаются как требующие сравнения с материалами.
Цвет, блики, UV, нормали и посадка одежды остаются отдельными проверками.

Пороговая политика — `scripts/creatures/lod-silhouette-policy.json`:

| Метрика при 512×512 | Условие для каждого вида |
| --- | --- |
| IoU, пересечение площадей / объединение | ≥ 0,97 |
| Пропавшая площадь относительно render | ≤ 2,5% |
| Добавленная площадь относительно render | ≤ 2,5% |
| 95-й процентиль отклонения кромки от второй заполненной маски | ≤ 2 пикселей |
| Максимальное расстояние точки силуэта до второй заполненной маски | ≤ 8 пикселей |
| Выход LOD за кадр | Нет |

Одного IoU недостаточно: длинное тонкое оружие занимает малую площадь. Максимум
расстояний ловит его исчезновение. Расстояние до заполненного силуэта, а не до
ближайшего контура, предотвращает ложный большой штраф за одиночную растровую
дырку внутри фигуры. Крупная внутренняя дырка всё равно выявляется по глубине
и площади. Для численных тестов намеренно удаляются тонкая деталь и часть тела,
добавляются лишние детали и сдвиг; одинаковые модели и одиночный пиксель проходят.

Рецепт может явно задать `lodSilhouette` с переопределениями policy. Причину
изменения следует фиксировать при оценке конкретного результата; пороги не
ослабляются автоматически ради прохождения уже опубликованной модели.
Эта авторская настройка не отправляется в реестр map_model.

Verifier требует успешный отчёт с текущей политикой и теми же SHA render/LOD.
Его verification.json хранит SHA самого отчёта. Упаковка и публикация проверяют
эту связь: изменение файлов, отчёта или policy требует нового сравнения/проверки.
Старый passed не позволяет отправить непроверенные ресурсы.

## Проверка текущего набора

Аудит 24 октября 2026 охватил 11 раздельных фигур без подставок. Совомед:
минимальный IoU 0,99120, максимум отклонения 3 пикселя, все 17 видов прошли.
Десять моделей прошли policy целиком. Кобольд-чародей CRE-2053 получил пограничный
fail сверху: IoU 0,96961 при пороге 0,97, пропало около 2,09% и добавилось 0,98%
площади, максимум 6,40 пикселя. Порог сохранён; существующие S3-файлы аудит не
меняет. Перед следующей публикацией этого LOD нужна доработка и новая проверка.
Рабочие отчёты находятся в `models/creatures/lod-audit-20261024/`.

## Тесты инструментов

`test_trellis_resume.py` проверяет разрывы отправки, ожидания, записи receipt,
экспорта и скачивания через подставной сервис, без GPU. `test_lod_silhouette.py`
строит собственные меши и маски: принятые assets из models/ ему не нужны.
Численные зависимости обязательны в [профиле models](../testing.md); запуск
на stdlib Python явно отмечает отсутствие этих зависимостей как skip.
