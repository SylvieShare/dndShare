# Миниатюры существ: создание и публикация

← [3D-модели итемов](item-models.md) · [Обработка моделей карт](maps-model-pipeline.md)

## Результат и хранение

Результат — статическая текстурированная игровая миниатюра: отдельные render,
LOD, shadow, подробный source и preview. Фигурка не содержит подставку.
Это не сетка для 3D-печати: водонепроницаемость, скелет и анимация не заявлены.

Рабочая папка `models/creatures/<slug>/` игнорируется Git. В ней сохраняются
иллюстрация, принятый референс, исходный экспорт сервиса, `.blend`, полные карты,
готовые GLB и отчёты. Исполняемые инструменты, промпты и JSON-рецепты находятся
в `scripts/creatures/`, файлы для приложения — в S3. Реестр `map_model` хранит
хеши, геометрию и калибровку; `item_model` связывает ресурс с одним или несколькими
публичными итемами. Расстановка карты хранит размер и позу, а не URL или копии GLB.

[Навык dndshare-miniatures](../../skills/dndshare-miniatures/SKILL.md) направляет
повторные задачи в этот процесс. Рецепт принятой модели — воспроизводимый вход
обработки, а сохранённый нативный GLB нужен из-за недетерминированности генерации.

## Референс и генерация

1. Прочитать публичный итем: источник, внешность, размер по **коду** словаря,
   оружие, одежду, особые детали. Проверить существующие привязки и ресурсы.
2. Из иллюстрации встроенным imagegen сделать изображение цельной миниатюры на
   прозрачном фоне: вся фигура, устойчивая поза, читаемые конечности и оружие,
   объёмные волосы/перья, без подставки и окружения. Проверить силуэт до генерации.
   Ракурсы полезны для оценки, но могут противоречить друг другу; один принятый
   вид остаётся основным входом текущего image-to-3D процесса.
3. Получить **нативную текстурированную сетку**, сохранив исходник без изменений.
   Текущий инструмент — официальный Space `microsoft/TRELLIS.2` через
   [generate-trellis.py](../../scripts/creatures/generate-trellis.py).

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/generate-trellis.py models/creatures/SLUG/miniature-reference.png models/creatures/SLUG/trellis-native --seed ITEM_ID --resolution 1024 --token-stdin --allow-pro
```

`--token-stdin` читает ключ скрытым вводом. `--allow-pro` применяется при
действующем разрешении пользователя использовать личный PRO-аккаунт и его квоту.
Навык не даёт отдельного разрешения на расходы. Цены и квоты проверяются у сервиса
при необходимости, а не берутся из этого документа. Ключи не сохраняются в
рецепте, истории команд, отчётах или чате.

Успех подтверждают `generated-original.glb` и `generation.json` с
`originalMeshExported:true`. `--views-only` оставляет только виды и не подходит
для публикации. Если квота закончилась после генерации, сохранить результат и
ошибку; не запускать серию новых генераций. Автоматического восстановления
удалённой сессии после завершения процесса сейчас нет.

## Калибровка фигуры

Ноги после экспорта GLB лежат на Y=0, центр опоры — X/Z=0. В Blender вертикаль Z.
Нативные матрицы узлов сохраняются. Подставка отделена от тела во всех ролях.

`referenceDiameter` — диаметр **условного круга опоры в единицах готового GLB**,
а не габарит хвоста или размах оружия. Для нынешних тел принят 0,9. Автор выбирает
размер корпуса и стойку относительно этого круга; размер Small не означает,
что кобольд обязан быть той же высоты, что стражник Medium. Выступы допустимы.

На поле диаметр опоры `D = size - min(0.3, size*0.3)`, масштаб тела
`D/referenceDiameter`. Для 1×1 D=0,7, для 2×2 D=1,7, для Tiny D=0,35.
Это оставляет 0,15 клетки по внешним краям обычной/крупной площади; у Tiny отступ
меньше. Логические занятые клетки от выступов не меняются. Отключение подставок
не меняет масштаб фигуры. Справочник использует тот же расчёт.

Рецепт хранит `referenceDiameter`, идентификаторы и имена, `maxHeight`,
`materialProfile`, `assetFiles`; для точного воспроизведения исходной опоры —
`calibration: {sourceDiameter, sourceOrigin:[x,y,z], rotation}` в координатах
нативного исходника Blender. Все роли получают один transform:
смещение на `-sourceOrigin`, масштаб `referenceDiameter/sourceDiameter`, поворот Z.
Опору измеряют по стойке и корпусу, исключая оружие/хвост. Проверяют вид сверху
и сравнение с принятой фигуркой на одной сетке. `--height` и `--footprint` подходят
для черновой нормализации; итоговый рецепт фиксирует принятую калибровку.
У [совомеда](../../scripts/creatures/owlbear-2579.json) transform уже сохранён.

Подставки имеют `baseSize` — размер жетона, и собственный `referenceDiameter` —
измеренный наружный диаметр меша. Масштаб основания по X/Z равен
`D/referenceDiameter`, по Y равен 1. `surfaceHeight` задаёт подъём ног.
Толщина не растёт вместе с существом. Контракт API и расстановки —
[3D-модели итемов](item-models.md).

## Обработка геометрии и текстур

Нужны Blender, Node/runtime из `scripts/maps/setup-model-tools.sh` и Python
с зависимостями [requirements.txt](../../scripts/creatures/requirements.txt).
Команды ниже выполняются из корня репозитория; SLUG заменяется рабочей папкой.

```bash
models/creatures/.generation-runtime/bin/python scripts/creatures/prepare-native-geometry.py models/creatures/SLUG --lod-triangles 12000
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python scripts/creatures/bake-native-miniature.py -- models/creatures/SLUG --recipe scripts/creatures/RECIPE.json --token-size 1
node scripts/creatures/optimize-miniature.mjs models/creatures/SLUG scripts/creatures/RECIPE.json
node scripts/creatures/verify-single-miniature.mjs models/creatures/SLUG scripts/creatures/RECIPE.json
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python-exit-code 1 --python scripts/creatures/render-final-miniature.py -- models/creatures/SLUG --recipe scripts/creatures/RECIPE.json
node scripts/creatures/package-miniature.mjs models/creatures/SLUG scripts/creatures/RECIPE.json
python3 scripts/creatures/publish-miniature.py models/creatures/SLUG scripts/creatures/RECIPE.json
```

`prepare-native-geometry.py` делает QEM и новую UV-развёртку xatlas:
начальные бюджеты 44k render, 12k LOD, 3,5k shadow. Совомеду нужен LOD 24k
для сохранения тонких перьев. Бюджет выбирается по видимому результату.

`bake-native-miniature.py` переносит albedo/PBR и геометрические tangent normals
с исходника на render/LOD, сохраняет `.blend`. По умолчанию основание отсутствует;
`--embedded-base` предназначен только для авторского сравнения, verifier такую
фигурку не пропустит. Shadow содержит только геометрию. Source сохраняет подробную
текстурированную сетку с тем же transform. Опорная высота и ориентация совпадают.

Отдельный проход покрытия заполняет пропуски лучей и расширяет края UV-островов.
Для тонких перьев корректируются обратные tangent normals. Эти меры не заменяют
осмотр: провал геометрии, инвертированная нормаль и тёмная текстура — разные причины.
Albedo использует sRGB, normal/ORM — Non-Color. Проверяются конечные координаты,
UV, автономность GLB, отсутствие скелета/анимации, части, треугольники и datum.
LOD может отличаться по границам не более 0,04 нативной единицы; этого недостаточно
для оценки силуэта. Ограничения «весь меш обязан влезть в круг опоры» нет.

Оптимизатор сокращает карты: albedo до 2048 render/1024 LOD, normal вдвое,
ORM вчетверо меньше; albedo JPEG, карты данных PNG. Запускать на свежем экспорте,
чтобы не перекодировать JPEG повторно. `--materials-only` меняет профиль без
пережатия изображений. `native` сохраняет PBR исходника; `dielectric` задаёт
metallicFactor=0 во всех видимых ролях, включая source. Он подходит целиком
органическим существам, но не смешанной броне из кожи и металла.

Для примерки на отдельную подставку добавить к render-final-miniature.py:
`--base ПУТЬ_К_GLB --base-diameter ИЗМЕРЕННЫЙ_ДИАМЕТР --token-size РАЗМЕР`.
`on-base.png` использует тот же расчёт масштаба, что приложение.

## Варианты и одежда

Кобольды используют принятый общий корпус, экипировка — отдельная геометрия.
[Рецепты семейства](../../scripts/creatures/kobold-family.json) и
[ориентиры тела](../../scripts/creatures/kobold-landmarks.json) описывают варианты.
При смене тела ориентиры требуют повторной проверки. Не менять принятую позу
без причины и не создавать независимый body-ресурс для каждого одинакового итема.

`kobold_clothing.py` строит связную одежду с плечами, боками, проймами и вырезом.
BVH-лучи идут от оси туловища наружу: руки перед грудью не вытягивают ткань вперёд.
Для всех детализаций используется одна принятая поверхность render. Верх/пояс
проверяются на зазор до тела не более 0,022; основной кусок ткани связен.
`clothing_fit.py` удаляет закрытые полигоны кожи, оставляя перекрытие около краёв.
Отчёт `creation.json` содержит зазоры и число закрытых полигонов.

Первые кобольды/стражник создавались со встроенными основаниями. Их историческая
подготовка использовала `build-kobold-family.py`, `prepare-family.py` и
`publish-family.py`; перед текущей публикацией тела и основания разделены через
`separate-bases.mjs`. Эти промежуточные bundles нельзя публиковать поверх текущих
тел без отделения подставок. Для новой миниатюры использовать процесс выше.

## Приёмка и публикация

До публикации осмотреть перед, спину, оба бока, верх; сравнить render/LOD и серый
материал при нейтральном свете. Проверить ноги, одежду, внутренние стороны крыльев,
оружие, тени. Затем поставить на поле рядом со стражником/кобольдом и стенами;
сравнить размеры 1×1 и 2×2. HTTP 200 и факт загрузки GLB не доказывают отрисовку:
масштабированный камень однажды закрыл всю фигурку из-за потери матрицы узла.

`verification.json` относится к окончательным файлам. После изменения геометрии,
материалов или калибровки повторить проверку. `package-miniature.mjs` создаёт
контентные имена/SHA-256, вычисляет maxHeight по проверенной геометрии и требует
принятую калибровку. Проверка заново измеряет геометрию и сохраняет хеши GLB;
упаковка и публикация отвергают файлы, изменённые после проверки. `publish-miniature.py`
по умолчанию выполняет только локальную проверку. `--publish` загружает через MCP
в S3, регистрирует модель и первичную связь. `--server-token` использует только
конкретный разрешённый серверный файл; ключ остаётся в памяти.

При замене файлов использовать `--update-from ПРЕЖНИЙ_publication.json`:
проверяются прежние assets, сохраняются текущие метаданные и связи. Чужая версия
ресурсов останавливает запись. Изменение диаметра опоры — отдельная операция
с метаданными, не побочный эффект обновления картинки. Итоговая проверка читает
реестр и связи; только после неё `publication.json` получает `verified:true`.
Операция набора не атомарна; после сбоя повторять тот же проверенный набор.

Для текущего набора [standing-calibration.json](../../scripts/creatures/standing-calibration.json)
задаёт 11 тел и 14 подставок. Инструмент не меняет GLB или назначения:

```bash
python3 scripts/creatures/calibrate-miniatures.py scripts/creatures/standing-calibration.json models/creatures/standing-calibration
python3 scripts/creatures/calibrate-miniatures.py scripts/creatures/standing-calibration.json models/creatures/standing-calibration --snapshot --server-token
python3 scripts/creatures/calibrate-miniatures.py scripts/creatures/standing-calibration.json models/creatures/standing-calibration --apply --server-token
```

Snapshot сохраняет текущие модели и связи до записи. Apply проверяет весь набор,
отказывается заменять посторонние изменения и читает результат обратно. Повтор
допускает точное состояние до/после. Это явная операция данных, не SQL-миграция.
В редакторе ресурса поле «Диаметр опоры модели» и окружность позволяют проверить
и настроить уже зарегистрированную калибровку.

## Что выяснилось и что ещё улучшать

- Кобольды: одежда плоскостями и рамки по всему силуэту дали неверный результат.
  Исправлены связная посадка и отдельная калибровка опоры. Общая поза у семейства
  остаётся заметной; уникальные стойки потребуют новой геометрии.
- Совомед: получен настоящий экспорт TRELLIS вместо чернового визуального объёма;
  тонкое оперение потребовало большего LOD. Ошибочная металличность почти 1 делала
  тело тёмным; исправлен материал, а не освещение. Модель остаётся стилизованной,
  мелкие перья не гарантируют точного повторения иллюстрации.
- Следующий полезный шаг для генератора — восстановление удалённой сессии на этапе
  экспорта, если сервис её ещё хранит. Сейчас после сбоя данные ракурсов сохраняются,
  но перезапуск автоматически не продолжает прежний расчёт.
- Для дальнейшего каталога полезны отдельные принятые позы, смешанные PBR-материалы
  экипировки и сравнение силуэта LOD по изображениям. Сейчас их оценивают визуально;
  численный тест границ не заменяет такую оценку.
