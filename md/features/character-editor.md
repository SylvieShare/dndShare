# Character Editor

Read this before touching `features/character-editor`.

`features/character-editor/pages/ViewCharacter.vue` provides `charCtx` and renders recursive blocks through:

- `features/character-editor/components/TemplateBlockInner.vue`

Block components receive:

- `block`
- `value`

and emit:

- `update:value(id, value)`

Block families (registered in `blocks/blockRegistry.js`):

- `blocks/generic` - input and generic sheet blocks (`AvatarBlock`, `BlockMoney`, `BlockResources`, `BlockStates`, `BlockTags`, `CampaignBadge`, `InputIntBlock`, `InputIntModal`, `InputItem`, `InputSuggest`, `InputText`, `LinePoints`, `LinePointsList`, `SettingsMenuTile`).

`SettingsMenuTile` has an owner-only «Источники» action. Its «Использовать все
источники» toggle hides the publication checklist when enabled; disabling it
reveals the explicitly selected publications. It edits
`data.settings.contentSources {mode,ids,allowLegacy}` through the ordinary
character autosave, so polling and old-sheet compatibility remain unchanged.
`charCtx` exposes the normalized settings plus `sourceVersionId`; shared
`ItemPickerModal`, identity selectors, `InputItem` and `DndLevelUpModal` pass
that scope to `/items` before pagination. Already stored item ids are always
resolved with unscoped `/items/by-ids` and are never deleted when the allowlist
changes.

**Race/class are item references, not suggests.** `values.race` / `values.class` store `{ id, name }` (item-id refs into types 8/9), produced by the create wizard. Subrace/subclass live the same way in `values.subrace` / `values.subclass` (the wizard writes them; base ⇔ `parent_id` NULL, variants link via `item.parent_id`). The `INPUT_ITEM` block (`blocks/generic/InputItem.vue`, `content.item_type`) edits them as a select over **base items only** (`/items?typeId=N` filtered to `parentId == null`), storing `{ id, name }`; `DndCharIdentity` (desktop) does the same in its edit window; `accessors.race/charClass` and both read the `.name` and tolerate a legacy plain string. The D&D mobile `race`/`class` blocks were switched from `INPUT_SUGGEST` (suggest 1/2) to `INPUT_ITEM` (item_type 8/9). Do not store race/class as bare suggest strings.

`INPUT_ITEM` is **parent/child-aware** for subrace/subclass (matching the desktop window). Optional content keys: `child_id` (the value key for the sub-item, e.g. `subrace`/`subclass`), `child_placeholder`, and `child_display` (`replace` = show the child name in place of the base, used by `race`→subrace; `paren` = show `base (child)`, used by `class`→subclass). When `child_id` is set the block needs `values` (registered as `passValuesOnly: true`); after picking a base item it loads `/items/children?parentId=…` (filtered by `item_type`) and renders a second select **only when that base has children**, emitting `update:value(child_id, …)`. Changing the base clears the child to `null`. The mobile `race`/`class` blocks set these keys in `dnd/blocks.json`, so mobile now mirrors `DndCharIdentity`'s subrace/subclass behavior.

**`DndCharIdentity` edit window (`DND_CHAR_IDENTITY`, the `char_identity` block).** Renders `name · subline` (subline = `subrace||race · class (subclass)`) plus an **edit pencil** shown to owners (`charCtx.ownerMode`, falls back to `editMode`). The pencil opens a borderless **`AppModal`** on the shared `--bg` form canvas — deliberately **not** a `MorphSheet`/`MorphEditorShell` morph; it reuses the shared modal shell (overlay/backdrop/Escape/click-outside/close-✕/mobile bottom-sheet) instead of hand-rolling its own overlay. The window edits **name** (`FormTextInput`), **avatar** (own uploader → `POST /api/storage/images`, writes the `ava` block value), **race** + **class** (`ValueSelect` over base items only — `/items?typeId=8|9` filtered to `parentId == null`), and conditionally **subrace** ("Происхождение") / **subclass** ("Архетип") — each shown only when the selected race/class has children (`/items/children?parentId=…` filtered by type). Changing race/class resets and reloads its children. On save it emits `update:value` for each of `name`/`race`/`class`/`subrace`/`subclass`/`classes`/`ava` (block-value ids are `content.*_id`-configurable, defaulting to those keys); cleared subrace/subclass emit `null`. There is no `editMode`-gated whole-tile click anymore — only the pencil opens the window.

**Multiclassing.** The canonical class list is **`values.classes`** — `[{ id, name, level, subclass: {id,name}|null }]`; `values.class`/`values.subclass` stay mirrored to the **first** entry for old consumers (subline, spells, accessors), and the create wizard seeds `classes` with the picked class at level 1. Legacy sheets without `classes` are migrated on read by `classEntriesOf(values)` (`blocks/dnd/lib/levelUp.js`): the single `values.class` + `values.lvl.level` become one entry. For a **single** class the sheet-level block stays the source of truth for the level (`classEntriesOf` overrides the entry's level with `lvl.level`); with **two or more** classes the per-class levels govern and their sum is written to `lvl.level`. The identity window renders the class field as **rows** (class `ValueSelect` + per-row "ур." `FormNumberInput` + remove ✕ — level/✕ appear only when there is more than one row; a subclass select under each row when that class has children) with a "+ Добавить класс" footer and a running "Суммарный уровень". The subline shows `classesLabel(entries)` (`"Волшебник 6 (Некромантия) · Плут 2"`) when multiclassed, the old `class (subclass)` form otherwise.

**Level-up window (`DndLevelUpModal`, opened from the `lvl` block).** `BLOCK_LVL` is registered `passValues: true`; `DndLvlEditor`'s "Повысить уровень" button (always visible below 20, pulsing "Level Up!" when XP ≥ threshold) emits `levelup` → `DndLvl` closes the morph editor and opens the modal. Flow: **step 1** — pick which class takes the level (one card per `classes` entry with `N → N+1`), or "Взять новый класс" (base-class grid with PHB multiclass prerequisite badges — `multiclassCheck` against the sheet's final scores, unmet requirements warn but don't block), or "Просто повысить уровень" (bumps `lvl.level` only). **Step 2** — the gains preview: required **archetype pick** when the new class level reaches `subclass_level` and none is chosen; **new features** at exactly that class level (type-4 items via `featuresForBinding`, `cumulative:false`; a just-picked subclass also pulls its earlier features; each row has an eye → `ItemViewModal`); **HP** (Среднее/Бросок/Вручную toggle — avg = die/2+1 + CON, roll via `useDiceStore`); **ASI** when the level is in the class's `asi_levels` (`+2 к одной` / `+1 к двум` / `Черта` via type-7 `ItemPickerModal`, 20-cap enforced, "решу позже" skip); and an "Также изменится" summary (total level, +1 hit die, prof-bonus change, **spell-slot diff** behind a checkbox). Feat picking evaluates structured ability/spellcasting/armor/level requirements; unmet rules disable confirmation and explain why. A feat with `choices[]` opens `FeatChoiceModal`, and the selected values persist under the feat entry's `choices`. Repeatable feats receive a `uid`, so several takes coexist and can be reordered/removed independently. Simple feat ASI and static proficiencies are applied on acceptance. "Принять" emits one `apply` payload that `DndLvl` fans out as `update:value` per key: `lvl`, `classes` (+`class`/`subclass` mirrors), `abilities_class` (appended `{id,count}` entries, `manual_size` honored), `hp` (`max`/`current` + gain, `diceCount`+1), the ASI stat blocks (a named bonus row `Повышение (ур. N)`) or `abilities_feats`, and `spells.slots`. Slot totals come from `computeSlots(entries, itemsById)` in `lib/levelUp.js` — the PHB multiclass caster table: caster kind by the class item's `nameEn` (full: bard/cleric/druid/sorcerer/wizard; half: paladin/ranger; artificer rounds up; third-caster subclasses eldritch knight/arcane trickster; warlock = pact magic, merged into the slot rows only when it's the sole caster, with `slots_rest: 'short_rest'`). Single-class casters use their own table (round up), multiclass sums per PHB (round down). The create wizard reuses `computeSlots` for level-1 slots (so a warlock starts with 1 pact slot, not 2).

**Granted subclass spells + feature choices on level-up.** Subclass items carry `data.granted_spells` (`[{ level, spell, option }]` — see `md/features/handbook.md`); `lib/levelUp.js` exposes `grantedSpellRows`/`grantedSpellsAt(items, classLevel, {exact, options})` and `chosenOptionLabels(...maps)` (flattens `values.feature_choices` + in-modal picks into the option labels that gate terrain-scoped rows). The level-up modal renders an inline **choice picker under each gained feature** that has `data.choice` (inline options or `from_suggest_id` chips — Circle terrain, fighting styles, totems…; required before Принять) and a "Заклинания архетипа" section listing the granted spells for the new level (a just-picked subclass pulls its whole backlog, a new class its level-1 rows). On accept: choices merge into `values.feature_choices`, granted spell ids append to `values.spells.spells` as `{id, prepared:true}` (the spells value is initialized if absent — `stat_path` via `castingAbilityIdOf`, which falls back to CHA/WIS for paladin/ranger whose items carry no `spellcasting` block). The create wizard does the same at level 1 (cleric domains): `useDndCreateWizard.grantedSpellIds/grantedSpellList` → shown as tags in `StepSpells` («Заклинания архетипа — всегда подготовлены») → `buildCharacterData(grantedSpellIds)` merges them into `values.spells.spells`.
- `blocks/dnd` - D&D-specific blocks (`DndAbilities`, `DndArmor`, `DndCharIdentity`, `DndCharStat10`, `DndCounters`, `DndDeathSave(s)`, `DndExhaustion`, `DndHitDice`, `DndHp`, `DndInitiative`, `DndItems`, `DndLvl`, `DndPotions`, `DndProfBonus`, `DndSkillBonus`, `DndSpeed`, `DndSpells`, `DndWeapons`) plus per-block modals (`DndHpCalcModal` — still used by the encounter NPC HP popover; `DndSlotEditModal` — the **magic settings editor** opened from the `SpellSlotsBar` "Редактировать" pencil: **подготовка заклинаний** (`ToggleSwitch` → `preparation`), базовая характеристика (`ValueSelect`), бонус к спасброску + бонус к атаке заклинаний (`FormNumberInput`, manual extras layered on top of prof+stat), тип отдыха для восстановления ячеек (`MultiToggle` Длинный/Короткий → `slots_rest`), and the per-level slot-total grid. Built on `AppModal` + `EditorSection`). Spell slots are **not** a standalone block — they render inside `DND_SPELLS` via `SpellSlotsBar`. (The old standalone `DND_SPELL_SLOTS` block / `DndSpellSlots.vue` was removed.)
- `blocks/vtm` - Vampire-specific blocks (`VtmBloodPool`, `VtmHealth`).
- `blocks/layout` - layout/section blocks (`LayoutInnerTabs`, `SectionHeader`).

`DND_SPELLS` renders spellcasting stats, spell slots, and spell cards in a compact card style. Spell cards show the spell attack bonus when spell item data has `damage.range_attack`, and can show structured damage/healing dice summaries. Block value shape: `{ stat_path, save_bonus, attack_bonus, slots_rest, preparation, spells, slots }` — `save_bonus`/`attack_bonus` are **manual extras** layered on top of `8 + prof + statMod` (DC) / `prof + statMod` (attack); `slots_rest` (`'long_rest'` default | `'short_rest'`) controls which rest recharges the slots; `preparation` (bool, default **false**) turns on the **spell-preparation** mechanic (legacy array/`{spells,slots}`-only values tolerated — missing fields default to 0 / `long_rest` / `false`). When `preparation` is on, `SpellCard` shows the bookmark toggle and a **prepared-summary strip** renders **before the cantrips** (`DndSpells`): total prepared + per-circle prepared counts (only circles with >0). The old per-group `N/M` count in the level header was removed.

**Damage scaling render.** `useSpellCalc.damageDiceParts(item, castLevel, charLevel)` / `healDiceParts(...)` apply `data.damage.scaling` (see `md/features/items.md`): `slot` adds `addon` rows × `(castLevel − spellLvl)`, `cantrip` adds `addon` × thresholds passed at character level (5/11/17), `none`/absent → base only. `mergeRows` folds an addon row into the matching base row (same `dice_id`+`type`) or appends it. Dice `bonus` (e.g. Волшебная стрела `1d4+1`) is summed into the `modifier` passed to `AttackDamage` and into the roll expression (`exprWithBonus` in `DndSpells`). `SpellCard` owns a local `castLevel` (default = spell level); for `scaling:"slot"` spells with headroom (`ctx.maxSlotLevel > spellLvl`) it shows a **круг −/+ stepper** that rescales the displayed dice and the roll; cantrips scale automatically off `ctx.charLevel` (= `values.lvl.level`) with no control. `SpellCard` also shows a **save tag** (`save_ability`+`save_effect`, e.g. `ЛВК ½`) and **`×N` instances** (лучи/дротики). `ctx` gained `charLevel` + `maxSlotLevel`; `rollSpellDamage/Heal` take `castLevel`. Publication badges come from common `item.contentSources`, not spell JSON.

### Attack/damage display (`AttackDamage` / `DamageDice`)

`blocks/dnd/components/AttackDamage.vue` is the **single shared attack+damage display** for both spells and weapons (it replaced the old `WeaponAttackDamage.vue`, deleted; `DieIcon.vue` is no longer used here). Props: `attack` (string `+N`, `null`/`''` → no attack pill), `damageParts`, `modifier` (flat damage bonus, merged into the first die group), `twoHandedParts` (versatile/two-handed dice — renders an extra **"2р"** group with the same `modifier`), `healParts`, `rollable`. Emits `roll-attack` / `roll-damage` / `roll-damage-two` / `roll-heal` (the parent owns the dice-store calls). Layout: a bordered **Атака** pill (`--accent-soft`), a **frameless** damage group, an optional **2р** group, and a green **heal** pill; chips are `<button>`s, `:disabled` when not `rollable`.

`blocks/dnd/components/DamageDice.vue` renders dice **grouped by damage type** (`{ count, diceLabel, iconUrl, type, typeColor }` — the shape both spell `dicePart` and weapon `attackDisplay` produce). Each type group is a **column**: its dice (joined by `+`) on top with a **single type label underneath**; same-type dice/modifiers share that one label. The flat `modifier` attaches to the first group (positive sits left of the dice, negative right). The die is the **dice-suggest svg** (`part.iconUrl` = `dice.svg`, `v-html`, **42px**), with `dieText` (`8d6`/`d10`) as the text fallback; colour comes from the damage-type (`typeColor` → `--dc`, `defaultColor` prop fallback — amber for damage, green for heal). Between-group `+` aligns to the die row, not the column. Weapons feed it **raw** parts (`damagePartsRaw`, no modifier merged) + `modifier` separately; the **table variant** still uses the old `damageParts` (modifier baked into `parts[0]`). Two-handed data comes from the weapon item's `data.universe_attacks` (`itemTwoHandedAttacks` → `twoHandedParts`); `damageExpressionTwoHanded` builds its roll expression.

`BLOCK_STATES` supports compact placement variants:
- `props.variant: "only_add_button"` renders only a dashed `+ статус` picker. The picker excludes statuses already present in the character value.
- `props.variant: "only_states"` renders only current status chips, without add or remove controls.

`DND_WEAPONS`, `DND_SPELLS`, `DND_ITEMS`, and `DND_ABILITIES` add items through a dashed button that opens `ItemPickerModal` (a full-screen list+detail picker modal). The modal accepts `itemTypeIds`, `title`, `searchPlaceholder`, `excludeItems`, and `allowQuantity` props, uses `HandbookItemList` + `HandbookItemDetail` internally, and emits `pick(item, qty)`. When `allow-quantity` is passed by the caller, the footer shows a `−/input/+` quantity control (clamped 1–999) and the "+ Добавить" button reflects `×N`; otherwise qty defaults to 1. The caller decides how to apply the quantity (e.g. `DndItems.onPickerPick(item, qty)` loops `addItem` qty times). When `itemTypeIds.length > 1`, the modal renders a tab strip under the toolbar (one tab per type, purple underline on active) and scopes the list/search/group-by/"Create new" to the active type. Browse uses `/items?typeId=<active>` (paginated); search uses `/items/search?typeId=<active>&q=...`.

`DND_ITEMS` (`BLOCK_ITEMS` in `blocks.json`, `content.item_ids` = the handbook types the picker browses, e.g. `[2, 1]`) is a **single-mode, frameless list** — there is **no `charCtx.editMode`**; everything is gated on `charCtx.ownerMode`. Rows have **no border/background/radius** — they're separated by a hairline divider (`.di-row + .di-row { border-top }`), matching `DND_WEAPONS`/`DND_SPELLS` (the block sits on the inner-tab `BaseTile`). The value is a `{ equipped, sections: [{ id, name, items }] }` model (`blocks/dnd/lib/itemSection.js` — `normalizeValue`/`cloneModel`/`entryDisplayData`/`allCatalogIds`/`makeSectionId`/`makeEntryUid`, legacy array/old-sections shapes tolerated). The locked **"Экипировано"** section renders first, then user sections (default "Рюкзак"). Each entry is `{ uid, id, count, override? }` — `id == null` ⇒ a custom item whose `override` holds `{ name, desc, consumable }`; catalog items resolve through `catalog` (`/items/by-ids`).
- **Owner** (single mode, all controls always visible): section name → inline rename, delete-section `×` (when >1 user section), "+ Добавить из справочника" (opens `ItemPickerModal` scoped to `item_ids`, `allow-quantity`) + "+ предмет" (custom via `ItemInlineFormModal`), "+ Добавить секцию"; per row a right-aligned control group — consumable **use** button (decrement, removes at 0), `− N +` count stepper, `✦` edit (custom only → inline form), and a **trash** delete. Clicking the name opens `ItemViewModal` (catalog) or the inline form (custom).
- **Viewer**: read-only rows, `×N` count badge, name → `ItemViewModal`. The header rename/add/manage controls and the row control group are not rendered.

Section-id helpers come from `itemSection.js`; the lower-level `makeUid` lives in `blocks/dnd/lib/itemEntry.js`. Reuse these instead of inlining list walks.

`DND_COUNTERS` (`BLOCK_COUNTERS` in `blocks.json`, the `counters` block) is a **universal counter-tile block** — the owner creates named, icon'd tiles, each a numeric counter. It sits **left of the wallet** in the "Снаряжение" tab (desktop: a `space-between` row `[counters … money]`; mobile: stacked above `money`). The two original asks (рацион with a day counter, бурдюк) are just two such tiles, not hardcoded blocks. Value = a flat array of `{ id, name, icon, color, unit, value, max }` (`blocks/dnd/lib/counterEntry.js` — `normalizeCounters`/`defaultCounter`/`patchCounter`/`makeCounterId`; `max: null` = open-ended, `color: ''` = no accent). `icon` is a **Lucide component name** from the curated set (`shared/ui/icons/counterIcons.js`).
- **One adaptive tile** (`DndCounterTileView`, the shared view for tile + morph `#view`): icon + name + `− value +`; `max != null` → `value/max` + a glowing progress bar (unit hidden); `unit` set → caption line; `color` set → left strip + tinted icon. No `editMode` — owner gate is `charCtx.ownerMode`.
- **Owner**: taps `− / +` inline (`adjust`, clamped `[0, max]`), drags the **whole tile** to reorder (`useSortable` group `counters`, whole-tile `@pointerdown` with a `<button>`/`<input>` guard), and opens a **per-tile vertical morph** (`DndCounterTile` owns `useMorphOrigin` + `MorphEditorShell`, like `WeaponCard`) via the tile pencil. A dashed **"+ плитка"** appends a tile and auto-opens its editor (`justAddedId` in the provided `countersBlockCtx`).
- **Editor** (`DndCounterEditor`, on `EditorPanel`/`EditorSection`): Название (`FormTextInput`), Подпись (`unit`), Иконка (`shared/ui/IconPicker`), Цвет (`ColorPresetPicker inline allow-clear`), Значение (`FormNumberInput`), Максимум (`ToggleSwitch` → enable sets `max = max(1, value)`; `FormNumberInput`), plus Удалить / Готово.
- **Viewer**: read-only tiles (number + unit/bar), no pencil/steppers/add. The block root always renders (so the desktop `space-between` row keeps `money` on the right even when there are no counters).

Shared editor helpers and modals live in `features/character-editor/components`.

Composables live in `features/character-editor/composables`: `useCharacterData` (load/sync/save), `useSaveDebounce` (debounced autosave), `useScrollHide` (hide-on-scroll chrome), `useTabSwipe` (mobile tab swipe), and `useMorphOrigin` (capture a tapped tile's rect to drive the morph window).

Feat effects may also be bound to the player's selected value: `ability_bonus`,
`grant_proficiency`, and `grant_spells` are applied automatically. Selected feat
spells are stored as prepared entries with `source: 'feat'` and do not change
class spell slots.

## Drag-and-drop reordering

`DND_WEAPONS`, `DND_SPELLS`, `DND_ITEMS`, `DND_COUNTERS`, and `DND_ABILITIES` use the shared pointer-event sortable composable `shared/composables/useSortable.js` (see `md/features/sessions.md` for the full API contract). `DND_ABILITIES` (in its morph editor) renders a 6-dot drag handle; `DND_WEAPONS` (drag the name), `DND_SPELLS`/`DND_ITEMS` (drag the whole row) and `DND_COUNTERS` (drag the whole tile) have **no handle** — the sortable's 4px threshold keeps a plain tap a click, and a `sortable.dragging` watch suppresses the trailing click so a drag doesn't open the row's modal/editor.

- **DND_WEAPONS** — single group `weapons`, items are root `entries`. Drag-handle replaces the legacy `▲/▼` order buttons in both the `list` and table variants. For the table variant, `useSortable` wraps the cloned `<tr>` in a fresh `<table><tbody>` and copies cell widths so the ghost renders correctly outside its original table.
- **DND_SPELLS** — one group per spell level (`level--1` … `level-9`), each group's `accepts` predicate checks `entry.item.data.lvl === lvl`. This restricts drag to within the spell's own level — the cross-level drop is rejected at hit-test. `onDrop` rebuilds `spells.value` by splicing the source out and reinserting at the matching position in the target level. There is **no drag handle** — the **whole row is the drag handle** (`@pointerdown` on the row root → `onSpellDragStart`; the sortable's 4px threshold keeps a tap a click, and a `sortable.dragging` watch suppresses the trailing click so a drag doesn't open the spell modal). A press starting on a `<button>` (bookmark/delete) doesn't start a drag. Owner-gated via `charCtx.ownerMode` (`onSpellDragStart` early-returns for non-owners). Rows carry `touch-action: pan-y` so the list still scrolls on touch (whole-row reorder is effectively a desktop/mouse gesture). The "+ Найти заклинание" button is likewise owner-gated (`canAddItems = ownerMode`).
- **DND_ABILITIES** — reorder lives in the **morph editor** (`DndAbilitiesEditor`), not the always-visible tile. Single group `abilities` over the `entries` prop, `getKey: e => e.id`. The editor doesn't own the data, so `onDrop` emits the reordered id list as `reorder`; `DndAbilities.reorderAbilities` maps it back onto `stored` (array of `{ id, count, max_use? }`). Handle hidden when there's a single ability.
- **DND_COUNTERS** — single group `counters` over the value array, `getKey: c => c.id`. The **whole tile is the drag handle** (`@pointerdown` on the tile root → `ctx.onDragStart`; a press on a `<button>`/`<input>` doesn't drag). `onDrop` uses `reorderByDrop`. Owner-gated; tiles carry `touch-action: pan-y`.
- **DND_ITEMS** — one group per section (`sec_<sectionId>`, including the locked `sec_equipped`). The **whole row is the drag handle** (`@pointerdown` on the row root → `onRowDown`; a press starting on a `<button>`/`<input>` doesn't start a drag). Drag is **cross-section** — `onDrop` splices the entry out of `fromGroup` and reinserts at `toIndex` in `toGroup` (same-section forward moves adjust the index by one). Owner-gated (`canDrag = charCtx.ownerMode`); rows carry `touch-action: pan-y` so touch still scrolls.

Each component uses `sortable.displayItems('<group>')` for the rendered list, `:data-sortable-key="<key>"` on row roots, `data-sortable-container="<group>"` on container elements, and a `sortable-placeholder` class (purple dashed outline, content hidden via `visibility: hidden`) on the source row while dragging.

**Generalized mechanism (use these for any new block you migrate):**
- `components/MorphEditorShell.vue` — wraps `shared/ui/MorphSheet` and lays out the two-column split: `view` slot (left, a stand-in for the tile) with a colored strip + the `editor` slot (right, fades in/out over the morph via the `revealed` slot prop), divider, plus an optional `sub` slot when a `nav` (`useSheetSubpages`) is passed. Props: `originRect`, `originEl`, `color` (strip + `--sc`), `editorWidth` (default 360), `minViewWidth` (floor for the view), `orientation` (`'horizontal'` = editor to the right, default; `'vertical'` = editor **below** the view), `strip` (default true; pass `false` for blocks with no accent strip like HP), `nav`. Also `frame` (color): when set, the **panel itself** takes a gradient + colored border (passed through to `MorphSheet`'s `frameColor`) so the morphing block "unfolds" — its frame becomes the whole window (used by HP). Framed panels draw the 1px border as an absolute overlay (not layout border), so the body width stays aligned with the source tile. Panel width = horizontal: `max(originWidth, minViewWidth) + editorWidth`; vertical: `max(originWidth, minViewWidth)`. Horizontal view columns stay layout-identical to the source tile during morph; do not animate margin/padding there, because changing `scrollHeight` mid-FLIP makes tall stat blocks recalculate height and visibly twitch. The view body carries `min-height: originRect.height` to avoid a source→panel height snap from rounded measurements. The editor column and the divider have no top inset — the divider is full-height (`margin: 0`) and the editor sits at its own padding.
- `composables/useMorphOrigin.js` — `{ editorOpen, originRect, originEl, open(event), openFrom(el), close }`. A block calls `open` from any variant's click; the captured rect is what the window morphs out of / back to.

  - `components/EditorPanel.vue` — outer shell. Owns padding + vertical rhythm + the bold 16px title. Props: `title` (optional; bind it for mode-switching editors like `DndExhaustion`), `compact` (16/18/18 padding for `CalcPad`-driven editors — HP, money, level, resources, abilities, weapon). Replaces the old per-editor `.ae`/`.se-root`/`.pe`/`.nbe`/`.hpe`/`.lved`/`.mc-ed`/`.wed`/`.bre`/`.bte`/`.bsp-editor` containers and their `.*-title` rules.

Group related fields into sections (e.g. `DndArmor` = Основа / Бонусы / Щит).
  - `components/EditorTotal.vue` — the summary footer (muted label, top border, `<strong>` emphasises numbers). Replaces the old `.ae-total`/`.pe-total`/`.nbe-total`/`.sk-total`/`.im-total` copies.
  - `components/EditorSectionTitle.vue` — the underlying uppercase mini-heading (used inside `EditorSection`; was per-editor `.se-head`/`.abe-head`/`.bte-sec-title` copies). Default slot holds trailing controls. Only reach for it directly if you need a heading outside an `EditorSection`.
  - Migrated to these: `DndArmor`, `DndProfBonus`, `NumBonusEditor` (initiative/speed), `DndStatEditor`, `DndStatSkillEditor`, `DndHpEditor`, `DndLvlEditor`, `WeaponEditor`, `DndExhaustion`, `BlockMoney`, `BlockResourcesEditor`, `BlockTagsEditor`, `BlockStatesPickerEditor`, `DndAbilitiesEditor`, `InputIntModal`. `DndCharIdentity` and `DndSlotEditModal` are not morph editors — both build on `AppModal` (shared chrome) and share the 16px title.

So a migrated block: renders its tile (any variant) with `@click="open"`, and `<MorphEditorShell v-if="editorOpen" :origin-rect :origin-el :color @close="close">` with a `view` slot (looks like the tile) and an `editor` slot (the form). The source tile is hidden during the morph by `MorphSheet` (`setOriginHidden`), so the `view` slot need not be pixel-perfect.

**Mandatory: one shared view component for tile + morph `#view`.** The tile face and the morph `#view` are two separate DOM nodes (the tile stays in layout; the morph clone lives in the shell's overlay and FLIPs out of it — both nodes are required). But they must render **the same `*View` component**, never two hand-copied markup blocks. Duplicated markup silently drifts (padding, min-height, a stray pencil) and that drift is exactly what makes the morph jitter — every "дёргается сверху / слева / иконка карандаша" bug traced back to a copy that diverged. The view component is purely presentational (props in, events out); per-mode differences (interactive tile vs static clone, rollable vs not, pencil button vs fading ghost) are flags/props on it, not a second copy. The wrapper owns only padding/strip/frame. Compliant blocks: `DndCharStat10`→`DndStatView`, `StatTile`→`StatTileFace`, `DndHp`→`DndHpView`, `DndLvl`→`DndLvlView`, `BlockStates`→`BlockStatesSummaryView`, `DndExhaustion`→`DndExhaustionView`, `BlockMoney`→`BlockMoneyView`, `WeaponCard`→`WeaponCardView`, `BlockTags`→`BlockTagsView`, `DndAbilities`→`DndAbilitiesView`, `BlockResources`→`BlockResourcesView`. When you add a new morph block, follow this — do **not** inline the view markup twice.

### Utility tiles (AC / initiative / speed / prof-bonus)

`DndArmor`, `DndInitiative`, `DndSpeed`, `DndProfBonus` are thin wrappers over `components/StatTile.vue` — the shared shell that owns **all three variants** (`mini` toolbar chip / `tile` desktop card / default) **and** the click-to-morph editor. Each block just computes its display (`label`/`miniLabel`/`value`/`pre`/`unit`/`icon`/`color`/`toggled`/`rollable`) and provides an `#editor` slot; `StatTile` renders `components/StatTileFace.vue` for the tile and the morph's `view`, plus the `mini` chip (cmini styles live in `StatTile`). **Interaction (tile/default variants):** clicking **anywhere on the tile opens the morph editor** — the value body emits `@open` → `openTile`. The stat tiles have **no edit pencil** (`StatTileFace`'s `showEdit` defaults to **false**); the whole tile is the affordance. There is no whole-tile "primary action" anymore. Instead, a tile that should roll passes **`rollable`**: `StatTileFace` then renders a small **dice button (`.stf-roll`, d20 icon, **accent/`--sc` purple**) on the right of the value**, and clicking it emits `@roll` → `StatTile` re-emits `action` → the block rolls `d20 + value` via `useDiceStore().roll(title, expr, { crit_mode: true })`. **Initiative and prof-bonus are `rollable`**; speed is not; **armor is not rollable** — its shield is toggled **only inside the morph** (the `ToggleSwitch` in the `#editor`), and the purple strip on the tile reflects `toggled` (shield up). The **morph window itself has no accent strip** — `StatTile` passes `:strip="false"` to `MorphEditorShell` (the `color` still drives `--sc` for the editor). The `mini` toolbar chip is unchanged (whole chip opens the morph). For a block whose default (mobile) variant needs a different look, override the `#tile` slot (AC → shield graphic, prof-bonus → compact `+N`); the slot still gets **`open`** (→ morph) **and `action`** (→ the block's `@action`, e.g. AC mobile shield toggle / prof-bonus mobile tap-to-roll) props — those slots render their own small pencil (`.sb-edit`, top-right) wired to `open` and route the main tap to `action`. No `editMode` gate anywhere. Editors: initiative & speed share `components/NumBonusEditor.vue` (base value + bonuses); prof-bonus (auto/manual toggle + bonuses) and armor (ac / dex toggle / bonuses / shield toggle + shield bonus) inline their editor in the `#editor` slot. Armor's "Учитывать ловкость" toggle reads `content.dex_mod_path` (`values.DEX.mod`) but **computes the modifier from the stat's live value** (parent-of-path `.value`: `floor((base + Σbonuses − 10) / 2)`) so changing DEX updates the AC immediately; the persisted `mod` is only a fallback when the stat carries no live `value`. (Note: the session-encounter AC accessor `settings/dnd/accessors.js#ac` still ignores `use_dex` entirely — a separate gap.) This replaced `DndArmorModal` + `DndProfBonusModal` (deleted) and the `InputIntModal` usage in initiative/speed. The desktop grid holding these four tiles is `430px` wide (3 cols) in `settings/dnd/desktop.json` — narrowed from 480px.

### Rest tile (`DND_REST`)

`blocks/dnd/DndRest.vue` (component `DndRest`, registered `noValue: true, passValuesOnly: true`) is the **rest tile** that replaced the `diary` stub in the desktop "База" utility grid (3rd-col bottom). It is **stat-tile-sized** (`BaseTile`, `min-height: 80px`, `height: 100%`, `overflow: hidden`) and split by a **diagonal divider** into two halves — **left = short rest (☕, amber `#ca9a4a`), right = long rest (🌙, indigo `#7f77dd`)**. Presentational face is `components/DndRestView.vue`: two **complementary** `clip-path` `<button>` halves sharing one seam (left `polygon(0 0,57% 0,45% 100%,0 100%)`, right is the mirror) so the hover highlights never overlap. Each half is full-width with `padding-{right,left}: 50%` to centre its content inside its own triangle, and the vertical justify **lifts "short" up / drops "long" down**. The halves are **icon-only** (☕ / 🌙, 30px) with a native `title` (+ `aria-label`) tooltip naming the rest — a styled tooltip would be clipped by the tile's `overflow: hidden` (needed for the diagonal/rounded corners). The seam is drawn by `.rest-divider` — a thin diagonal band via percentage `clip-path` (`inset: 0`, scales with the tile at any size). Halves emit `short`/`long`; `interactive` (owner only) gates hover/press (`scale(0.95)`). Non-owners see the static face.

The block has **no value of its own** — it reads the whole `values` (`passValuesOnly`) and writes sibling blocks by **emitting `update:value` with their block id** (`hp`/`spells`/`resources`/`exhaustion`, all configurable via `block.content.{hp_id,spells_id,resources_id,exhaustion_id,con_id}`). This cross-block write is the whole mechanism — `update:value(id, value)` accepts any id, not just the block's own.

Pure transforms live in `blocks/dnd/lib/rest.js` (no Vue/Pinia, unit-testable): `statMod`, `recoveredHitDice`, `longRestHp`, `longRestSpells`, `shortRestSpells` (slot recovery gated on `spells.slots_rest === 'short_rest'`), `restResources`, `longRestExhaustion`, `exhaustionLevel`, `spendHitDie`.

- **Short rest** (owner taps left) opens a borderless **`AppModal`** on `--bg` (the shared modal already supplies the dim + blur backdrop) whose body is `components/DndShortRestEditor.vue`: shows HP + remaining hit dice, a **"Потратить кость хитов"** button (rolls `1dX + CON mod` via `useDiceStore().roll`, disabled when no dice left or HP full — the block applies `spendHitDie`), and **"Завершить отдых"** which restores resources flagged `short_rest` (`restResources(..., 'short')`), recovers spell slots **when the spells block is configured to recharge on a short rest** (`shortRestSpells` — only acts when `spells.slots_rest === 'short_rest'`, e.g. warlock pact magic), and closes. The editor does **not** wrap itself in `EditorPanel` (the modal card already pads + gaps its children); it lays out a 16px title + `EditorSection` groups directly. CON mod comes from `statMod(values.CON)` (live stat value, same shape as the stat block / `accessors.abilities`). (Short rest is a modal, not a morph — `MorphEditorShell` is not used here.)
- **Long rest** (owner taps right) opens a `ConfirmDialog` (`variant: warning`); on confirm it applies in one go: `hp` → full + temp 0 + death saves reset + half hit dice regained (`recoveredHitDice`, min 1); all spell slots `used: 0`; resources flagged `short_rest` **or** `long_rest` restored; exhaustion `level − 1` (only emitted when level > 0). The spell-slot flasks and resource pips **re-animate their recharge for free** off their `spent` props — no extra animation code.

Short-rest slot recovery is **block-level** (`slots_rest === 'short_rest'` set in `DndSlotEditModal`), not per-level — fine for warlock pact magic where every slot recharges together. Not done (deliberate): a mobile placement (the `diary`/`rest` tile is desktop-only in the schema).

## Per-setting hardcoded schema (`settings/`)

The sheet structure is moving **out of the DB JSON template and into code, one module per game setting**. This is the replacement for the (never-built) visual template editor and the per-template `pathValues` config. First migrated setting: **D&D 5e**.

`features/character-editor/settings/`:
- `index.js` — `SETTINGS` registry + `resolveSetting(template)`. **Identity is keyed off the template *name*** (`char_template.name`, e.g. `'DND5'`, matched against the setting's `names` list) — **never the schema**, which may be empty (`{}`). `resolveSetting` accepts a descriptor carrying at least `{ name }`: the full template from `/templates`, or a `{ name, schema }` pair assembled for the editor. Also exports `settingRenderSchema(template)` (matched setting's hardcoded schema, else `template.schema`) and `settingAccessors(template)`. Call sites pass the **whole template** (list `accessorsFor`, `participantView`, create modal) or `{ name, schema }` (editor); the `/char/:uuid` response carries `templateName` so the editor's direct-fetch path has the name.
- `dnd/blocks.json` — id-keyed block definitions (shared by both profiles).
- `dnd/desktop.json` — desktop layout profile (tabs База / Личность / Заметки).
- `dnd/mobile.json` — mobile layout profile (6 tabs + `toolbar_blocks` + `common_mobile_blocks`).
- `dnd/schema.js` — assembles the three data files into the schema (`{ system: 'dnd5e', blocks, layouts: { desktop, mobile } }`) and applies a **code-driven restyle transform** (`buildSchema()`): strips container "backdrop" backgrounds (`style.background`), strips container separator borders (any `style.border*`), and scales every `props.gap` by `GAP_SCALE` (1.4×). Tweak the per-setting look here, not 40 inline JSON style blocks.
- `dnd/newCharacter.js` — `blankCharacter()` / `blankValues()`: the hardcoded blank D&D character (the in-code replacement for the DB `char_template.create_form.preset`). The create flow seeds from this, then layers grants + chosen ability scores.
- `dnd/creation/progression.js` — pure "what does this race/class grant" engine. `featuresForBinding(abilityItems, binding, level, { cumulative })` / `featureIdsForBinding(...)` filter ability items (types 3/4) by their own `data` bindings (`class_id`/`subclass_id`/`race_id`/`subrace_id` + `level`). `binding = { classId?, subclassId?, raceId?, subraceId? }`. Cumulative (`level <= N`) feeds the create-flow grants panel; `cumulative: false` (`=== N`) feeds the future level-up delta. This is the **single progression source** — no stored progression array.
- `dnd/creation/grants.js` — `extractGrants({ race, subrace, charClass, subclass })` normalizes the static grants of the chosen race/class items (type 8/9) into one object (speed, size, ASI, saves, proficiency ids, hit die, skill-choice spec, spellcasting config). `applyGrants(values, grants, { suggestValue, raceAbilityIds, classAbilityIds })` writes the **non-stat** grants onto character `values` (proficiencies resolved id→label via the injected `suggestValue(typeId, id)` lookup, speed, hit dice, `save_up` flags, granted feature ids) and returns `{ values, asi }` — racial **ASI is carried out, not applied**, to be layered on the chosen ability scores in the stats step. Pure (no Pinia); the caller injects `suggestValue`. Suggest-typed item fields store ids; the character keeps proficiencies as strings, hence the lookup.
- `dnd/creation/startingEquipment.js` — pure PHB 2014 starting-equipment profiles for all 12 base classes (Russian and English class-name aliases). The create wizard renders these choices directly inside the **Class** step; broad clauses such as "any simple weapon" expand into a concrete weapon/instrument picker and remain required. Fixed bundle rows and ammunition are appended automatically. `selectedStartingEquipment(profile, choices)` produces custom inventory rows, which are merged with optional catalog items from the later Equipment step and written to `values.items`; switching class clears only the class-equipment choices.
- `dnd/creation/backgroundEquipment.js` — converts a selected background's rich-text `data.equipment` sentence into custom inventory rows and starting coins. The create wizard previews both separately: possessions are merged with class/manual equipment in `values.items`, while coin fragments such as `кошель с 15 зм.` are excluded from inventory and added to the canonical `values.money.amounts` wallet (suggest type 17 ids, where gold is id 3).
- `dnd/accessors.js` — `dndAccessors`: the **single source of truth** for D&D semantic fields (`displayName`, `avatar`, `race`/`charClass`/`subtitle`, `level`, `hp`, `ac` (armor calc), `initiativeBonus`, `statesValue`, `headerTitle`, `listFields`). Each takes the character `data` (`{ values, var }`). `race`/`charClass` tolerate both a legacy plain string and a `{ id, name }` item-id reference (the create flow stores the latter), reading `.name` for display. This replaces the `pathValues` lookups. **Wired consumers:** the list card (`CharBox`) and the **session encounter + join flow** all resolve display fields via accessors — the latter through `features/sessions/lib/participantView.js` (`pvName/pvAvatar/pvSubtitle/pvLevel/pvHp/pvAc/pvHpPath`), used by `useEncounterPlayers`/`useEncounterHp`, `SessionParticipantCard`, `SessionJoinModal`, `ViewJoinSession`. `participantView` resolves accessors from the participant's `templateId` and falls back to the legacy `path_values_for_list` only for settings without accessors (VTM). So a D&D character renders from the in-code schema; legacy settings (VTM) return the template as loaded and keep using the DB JSON pipeline. There is intentionally **no per-setting Vue sheet component**; the working renderer handles both.

## Template Schema

There is a single sheet-schema model (the old `schemaVersion` field and its checks were removed — `useCharacterData.apply` no longer gates on it, and `dnd/schema.js` no longer emits it). The model separates reusable block definitions from layout placement:

- `blocks` - id-keyed registry of real sheet blocks (`INPUT_TEXT`, `DND_HP`, `BLOCK_MONEY`, etc.). Block data is still saved by block `id`.
- `sections` - optional reusable layout fragments.
- `layouts.desktop` - required layout profile.
- `layouts.mobile` - optional; if absent, the renderer falls back to `desktop`.

Each layout profile has these layers:

- `tabs` - always present. If there is only one tab, its content is rendered and the top tab switcher is hidden.

`sidepanel_left` / `sidepanel_right` are no longer supported. Put every sheet section in `tabs`.

Tab fields:
- `title` - text label and fallback accessibility label.
- `svg` - optional icon URL. If set, tab controls render the image instead of text.
- `content` - layout/block node.
- `width` - optional max width for this tab content.
- `default` - optional initial active tab marker.

Layout profile title fields:
- `header_title_path` - data path shown in the global app header, e.g. `"values.name"`.
- `tooltip_title_path` - string path or array of paths shown in the character toolbar, e.g. `["values.race", "values.class"]`.
- `title_path` is a legacy fallback for `header_title_path`.

Desktop tabs are displayed in `CharEditorToolbar`. Mobile tabs are displayed as a sticky tab bar under the character toolbar, not at the bottom of the screen.

Mobile tab switching uses a horizontal track model in `ViewCharacter.vue`:

- all tabs are arranged in one horizontal row and the row is moved with `transform`;
- on mobile, the outer sheet area is a fixed-height viewport below the toolbar/common strip/tabbar, and each tab pane owns its own vertical scroll container;
- mobile tab pane scroll containers keep bottom padding so the final blocks remain reachable above the viewport edge and safe area;
- each mobile tab preserves its own scroll position while switching tabs;
- swiping moves the row with the finger;
- releasing the finger settles to the current or adjacent tab;
- while the settle animation is running, new swipes are ignored;
- first/last wrap swipes temporarily reorder the row so the adjacent wrapped tab appears from the expected side;
- the active tab underline is a separate moving indicator whose width/position is derived from the current track offset;
- the highlighted tab changes based on which tab is mostly on screen, not only when `activeTab` changes.

Visited tabs stay mounted. `ViewCharacter.vue` keeps a stable `TabPane` per tab and caches normalized tab block trees so item-based blocks do not reload just because the user switches away and back. If data still reloads after that, add a block-level item cache instead of remounting fixes.

Layout content nodes are normalized by `ViewCharacter.vue` into the existing renderer:

- `{ "kind": "block", "ref": "hp", "props": { ... } }` renders a block from `blocks.hp`.
- `{ "kind": "section", "ref": "stats" }` renders a reusable section.
- `{ "kind": "layout", "type": "row" | "column" | "grid", "props": { ... }, "children": [] }` renders a layout container.
- `{ "kind": "layout", "type": "inner_tabs", "children": [ { "title": "...", "content": <node> } ] }` renders inline tab navigation within a column. Each child has `title` (string), optional `svg` (icon URL), and `content` (a layout/block node). Rendered by `blocks/layout/LayoutInnerTabs.vue` via `INNER_TABS` in `blockRegistry`.

Rows stretch their visible child columns to the tallest column. `inner_tabs` stretches to available tab/container height so its content background can fill the remaining vertical space.

Use `content` only inside block definitions for block behavior/configuration. Use `props` on placements/layout nodes for presentation and placement settings such as `gap`, `width`, `grow`, `shrink`, `columns`, and `hr`.

Placement `props.style` is passed to the block wrapper as Vue inline style. Prefer object syntax for JSON templates, for example:

```json
{
  "props": {
    "style": {
      "border-right": "1px solid #e8e8ef",
      "padding": "20px"
    }
  }
}
```
