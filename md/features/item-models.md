# 3D-модели итемов и существ

← [Карты](maps.md) · [Обработка моделей](maps-model-pipeline.md)

## Хранение

`item_model` связывает публичный итем справочника и зарегистрированный ресурс
`map_model`: `item_id`, `model_id`, `is_default`, `sort_order`. Пара идентификаторов
уникальна; отдельный partial unique index допускает одну основную модель итема.
Удаление итема удаляет связи, сохраняя общий ресурс. Один ресурс может
использоваться несколькими итемами. Файлы, хеши, геометрия и LOD не дублируются.

Основная модель выбирается по `is_default DESC, sort_order, model_id`.
Без явной основной используется первая в этом порядке. Привязка требует
публичный нескрытый итем и модель типа `object`. Миниатюры регистрируются с
`hidden:true`, чтобы не попадать в обычную палитру строительных объектов.

## Поле и трансляция

Метаданные `GET /api/maps/models` содержат `itemIds`: итемы, для которых ресурс
выбран основной моделью. У нового жетона существа сохраняется необязательный
`itemId`. При расстановке, переносе и открытии карты модель определяется через
каталог. Пока файл загружается, при ошибке или отсутствии связи остаётся обычный
жетон с портретом. Существа без модели, игроки и произвольные маркеры сохраняют
прежнее представление.

Масштаб модели соответствует размеру жетона; начало модели — центр подставки на
поверхности. Цвет обозначается кольцом, выбранное существо получает внешний
ободок. Подпись располагается над моделью. Геометрия и текстуры переиспользуются
между экземплярами и освобождаются общим кешем, материалы учитывают туман и
скрытие. Ближний/дальний LOD и «Использовать всегда LOD» действуют на существ.
Тени используют отдельный shadow asset с масштабом и перемещением существа.

Для старых расстановок itemId выводится из актуального списка NPC только для
отрисовки. Чтение карты не переписывает сохранённый JSON и не создаёт автосохранение.
Публичная read-only проекция также разрешает старую связь по UID NPC; внутренний
`ref` удаляется. Каталог и выдача GLB трансляции допускают модели только видимых
нефизических существ: скрытые жетоны, туман и скрытые области фильтруются раньше
определения нужных ресурсов. Исходный `source` через публичный endpoint закрыт.

## Управление и публикация

- `item_models_list {itemId}` — связи итема; 0 перечисляет все публичные связи.
- `item_model_bind {itemId,modelId,default,sortOrder}` — идемпотентная привязка.
  Установка основной модели атомарно снимает прежнюю под блокировкой строки итема.
- `item_model_unbind {itemId,modelId}` — убрать связь, сохранив ресурс.

Запись требует `MCP_WRITE_ENABLED`. Данные не добавляются startup-миграцией.
Сначала файлы загружаются обычным MCP-процессом моделей напрямую в S3, затем
регистрируются метаданные и связь. `cmd/map-model-upload` принимает `-item-id`
для каталога ровно с одной моделью и делает её основной после успешной публикации.
Произвольные URL GLB в состоянии карты не принимаются.

Первый ресурс — кобольд, item **1635**, из локального второго эксперимента.
Полная, LOD, shadow, preview и подробный source публикуются общим процессом.
Подготовка новых миниатюр, экипировки вариантов, UV/PBR и проверки описаны в
[пайплайне миниатюр существ](creature-model-pipeline.md).

## Проверки

`item_models_integration_test.go` проверяет ограничения, основной вариант,
повтор привязки, общий ресурс для двух итемов, удаление и запрет скрытых/личных
итемов и плиточных моделей в одноразовом PostgreSQL. Frontend-проверки покрывают
разрешение связи, неизменность сохранённых жетонов при обогащении для рендера,
масштаб, туман, общий ресурс, освобождение, подмену после асинхронной загрузки
и геометрию теней.
