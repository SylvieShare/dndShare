# Игровые карты

Карты пока доступны только пользователям с ролью `ADMIN`. Для остальных
пункты «Карты» в desktop/mobile меню и «Карта» в сессии серые и не открываются;
наведение, фокус и нажатие показывают «Скоро будет» через FloatingTooltip.
Прямая ссылка показывает ту же заглушку и не загружает данные карт.
Все закрытые API дополнительно проверяют `ADMIN`, сохраняя проверку владельца.
Публичный монитор без входа работает только для сессии администратора;
для остальных владельцев публичные map API возвращают 404. Миграция 166 удаляет карты старого формата по запросу пользователя; карты версии 2 остаются.

Библиотека мастера — `/maps`, рабочее место в сессии — вкладка «Карта».
`/map-screen/:code` — отдельная трансляция на лежащий на столе монитор.
Она использует публичный `displayCode` сессии, но имеет собственные состояние,
камеру и SSE: обычный экран сессии продолжает работать независимо.

## Библиотека и редактор

Администратор видит свои и две системные 3D-карты. Есть поиск по названию и
тегам, фильтр источника и SearchMultiSelect тегов: варианты собираются только
из доступных карт. Несколько выбранных тегов пересекаются (карта содержит все
выбранные). Создание сразу открывает 3D-редактор; доступны просмотр,
дублирование и удаление. Системная карта редактируется через собственную копию.
Единственный формат документа — `tiles`, конструктор готовых 3D-моделей.

Превью карточки — WebP-снимок той же Three.js-сцены в начальном изометрическом
ракурсе редактора (наклон 35,264°, азимут 45°, вписать всю карту). Снимок включает
геометрию, материалы, свет и видимость областей; служебные маркеры и выделение
не рисуются. Файл хранится в S3 под map-previews/, подпись сцены и ключ — в
battle_map_preview. Подпись зависит от документа и актуальных используемых моделей;
теги не влияют. Готовая карточка загружает img без создания WebGL renderer.
Если снимка нет или он устарел, видимая карточка лениво генерирует его одним
скрытым renderer 420×280 и публикует через preview-context/preview API.
Автосохранение изменённой сцены также запускает обновление снимка. Сервер отвергает
устаревшую подпись или revision карты; генератор повторяет попытку со свежим контекстом.
Замена и удаление карты удаляют прежний S3-файл. Для системных карт снимки общие.
Простаивающий GPU уничтожается через 15 секунд; ошибка превью сохраняет возможность
открыть карту и повторить генерацию при следующем открытии библиотеки.

Редактор открывается отдельной страницей `/maps/editor` на всю область окна,
без модальной рамки и навигационных панелей приложения. Кнопка «Карты»
возвращает в библиотеку. Параметр `id` открывает сохранённую карту, `copy`
создаёт копию. После первого сохранения
адрес содержит `id`; редактор и текущие изменения остаются смонтированными.

Ширина и высота задаются в целых клетках: 2–160 по стороне, не более 16000
клеток площади. Уменьшение обрезает объекты и разметку за границей после
подтверждения; undo восстанавливает прежнее состояние. В настройках выбираются
существующие теги или добавляются новые. `document.tags` — массив строк: до 32
тегов, до 64 символов в каждом; пробелы нормализуются, дубликаты без учёта регистра
объединяются с сохранением первого написания. Теги сохраняются с обычной revision,
копируются в сессию и участвуют в undo/redo.

Каталог объединяет Lost Cave, Ultimate Dungeon, Toxic Sewer, Basic Elements,
Majestic Highlands XL, [Medieval Town Vol.1](medieval-town.md)
и отдельные модели объектов. UD-104, UD-108 и UD-092 исключены из нового выбора;
исторические UUID остаются для уже сохранённых карт. Пак выбирается слева над категориями через селектор с тематическими SVG-эмблемами.
Для переключения пака в свёрнутой колонке нужно раскрыть вкладку «Плитки». Карточки используют BaseTile,
показывают превью, отдельные название и
исходный код LC-001. Единый набор WebP-иконок выбирает пол, прямые стены,
внутренние углы (Angle), наружные углы (Corner), диагональные стены, T, X,
выступы/окончания, лестницы, каркасы, мосты, проходы/двери и колонны.
Фильтр «Свободные / С предметами» расположен под категориями: он разделяет
плитки без встроенной обстановки и со встроенными предметами или декорациями
по флагу hasDecor. Он показывается, только если внутри выбранной категории
есть оба варианта; при одном варианте он выбирается автоматически. Возможность
ставить персонажей и объекты задаётся отдельно canStand/placementPoints.
Пустые категории выбранного пака не показываются; учитываются только последние
видимые модели. Название выбранной категории выделено над её иконками. Corner соответствует колонне на
углу клетки, как UD-096; окончания остаются отдельным типом. «Все стены» и
«Сложные стены» в фильтре отсутствуют. Иконки общие для всех паков: 192×192,
прозрачный фон, цельная непрозрачная геометрия; исходный рендер воспроизводится
через `scripts/maps/render-type-icons.py` в Blender;
`scripts/maps/export-type-icons.mjs` кодирует итоговые WebP через Sharp.
По умолчанию выбран пол; если в коллекции его нет — первый доступный тип.
Фильтр и справочник используют один `tileType`: `floor`, `wall-straight`,
`wall-angle`, `wall-corner`, `wall-diagonal`, `wall-tee`, `wall-cross`, `wall-end`,
`stairs`, `frame`, `bridge`, `passage`, `column`. Пак задаёт `collection`; маска стыков хранится отдельно
от категории. Расположение и контуры не меняются при исправлении категории.
Параметры тайлов доступны ADMIN через кнопку «Справочник тайлов» справа в шапке; она открывает отдельное окно.
Двух выпадающих списков типов и форм стен нет; в левой колонке также нет
кнопки кисти. Поиска,
обычной кисти выбранным тайлом, заливки по кнопке и ластика нет. Слева находится
сворачиваемый каталог с обычной сеткой карточек выбранной категории.
Карточки отсортированы по code и объединяют варианты одного семейства в одну
ячейку. В группе основной вариант показан немного меньше, справа — вертикальные
миниатюры. Наведение открывает немодальный BasePopover: мышь можно перевести в
список и перетащить конкретный вариант; R и отмена сохраняют прежнее управление.
Одиночные модели перетаскиваются напрямую. Лампочка обозначает встроенные
источники, включая выключенные по умолчанию. Группировка применяется после
фильтров категории/наполнения и действует также для объектов и справочника.
В справочнике «Код группы» меняет семейство модели; логический id и технический UUID
uuid разделены. Правила заполнения — в
[общей инструкции моделей](maps-model-pipeline.md#идентификатор-код-группы-и-название).

Фон карточек совпадает с прежним фоном картинок-превью; прозрачные изображения
показывают его через альфа-канал. Правый клик по иконковой полосе вкладок слева
открывает штатное меню браузера, в том числе во время постановки из каталога;
он не отменяет постановку. ПКМ на рабочем холсте сохраняет управление камерой
и отмену вставки.
Повторного заголовка категории и её отдельного сворачивания над списком нет. Плитку можно перетащить из него непосредственно на карту;
на мобильном экране колонка первоначально свёрнута. Поле занимает оставшуюся
область под шапкой без внешних отступов и скругления углов.
Выбор пака глобален для редактора и доступен в левой колонке плиток и
справочнике. Каталог объектов общий для всех паков. Общую шапку WorkspaceHeader также использует
страница сессии. Базовая высота шапки — 64px.
Шапка редактора заготовок содержит возврат в библиотеку и доступную ADMIN кнопку
«Справочник тайлов». Верхние кнопки undo/redo, копирования и удаления убраны. Переключателя режимов нет: рабочая область всегда показывает
карту, справочник открывается в AppModalFrame. Слева находится узкая панель
иконок «Плитки / Объекты / Области / Освещение / Настройки»; ширина с раскрытым
каталогом 334px, в свёрнутом состоянии 48px. Настройки открываются шестерёнкой
рядом с рабочим холстом: название, теги, ширина, высота, видимость сетки и
точек в пазах.
Редактор использует области экземпляров; вкладка и инструменты рисования зон
удалены. Существующая разметка зон тумана в документе сохраняется для сессии. Старые процедурные объекты исключены из нового выбора;
существующие документы с ними продолжают отображаться. Объекты выбираются в
боковом каталоге; клавиатурный выбор запускает превью у курсора до размещения.
Копирование и удаление доступны в панели выделения; undo/redo — через Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z. Кисти стен и экспорта JSON в редакторе нет.
Справа поверх холста появляется MapSelectionPanel высотой по содержимому:
для одного элемента счётчик выбора не показывается. Имя стоит над превью,
справа от имени — менее заметные `code · id`. Превью обрамлено BaseTile с
закруглёнными углами; справа стоят иконки копирования и удаления. Таблица
показывает X, Y, Z и поворот. Для группы — строки моделей с количеством
экземпляров, добавление в область и удаление. Область, переходы, встроенный и
прикреплённый свет выделены отдельными секциями с заголовками и разделителями.
Участник области показывает её название и иконку перехода: она раскрывает
вкладку областей слева и открывает фокус этой области справа.
MapEntityRow переиспользуется для моделей, источников
света и привязок. Панель не меняет размер холста и ограничена его высотой.
Иконки категорий увеличены до 64px; равномерные ячейки занимают ширину строки,
последняя неполная строка также растягивается.

Сферы показывают только свободные пазы моделей. На плоскости, в том числе рядом
с тайлами, сфер нет. Сферы полностью непрозрачны: у тайлов синие, у объектов зелёные. Контур того же
типа использует тот же цвет; наведение даёт тонкий контур, выбор — более сильный.
Точка под переносимым превью увеличивается, сохраняя цвет своего типа. Клик на сферу ставит базовый пол текущей коллекции;
протягивание по ней сохраняет pan, а Cmd/Ctrl оставляет множественный выбор.
«Настройки» отдельно переключают сферы и сетку. Видимость сфер — локальная
настройка редактора, сетка сохраняется в документе. Контур остаётся на движущейся
геометрии при переносе, подъёме и посадке; он следует реальным instance matrices.

Подсказки управления находятся снизу слева: каждая команда — отдельная строка.
Во время вставки ПКМ описывается как отмена, в обычном выборе — как вращение камеры.

Панель выбранной модели также содержит направленные переходы и отдельные списки
встроенного и прикреплённого света. Постоянная идентичность модели, замена с Undo,
удаление связанного света и шаблоны описаны в
[переходах моделей и встроенном свете](maps-model-behaviour.md).

«Справочник тайлов» доступен только ADMIN. В нём можно просматривать исходный код,
имя, пак и постоянный UUID, менять название, конкретный тип и расположение стен,
маску стыков, занимаемые клетки, смещения, глубину основания, высоты, метки,
опорные пазы, общие точки размещения, флаги декора/доступности и контуры препятствий. Сохранение через `PUT /api/maps/models/{modelId}`
обновляет текущую модель, повторно используя пять существующих файлов S3.
Тип и расположение стен выбираются общими WebP-иконками. Размеры задаются числами
или кликом по прямоугольнику на SVG-сетке 8×8; стрелки меняют ширину/длину.
Полный GLB в превью вращается ЛКМ, масштабируется колесом и использует свет карты.
Цветные линейки и отметки показывают глубину монтажной части ниже 0, поверхность,
верх и смещения X/Z; числовые изменения сразу обновляют положение модели/отметок.
Высоты сохраняют прежние единицы: от нижней точки файла с поправкой mountDepth
при размещении. Стыки выбираются на поднятой плоскости превью: восемь сфер для
center, четыре широкие стороны для edge; none очищает маску. Это разметка
текущего меша и не подбирает другую модель. Пазы показаны непрозрачными зелёными
сферами по клеткам, выбранный паз — фиолетовым; некорректный — красным.
У каркасов поле «Подъём при вставке» отдельно задаёт измеренную посадку
монтажного выступа на фаске. Сфера продолжает обозначать саму кромку паза.

Каждый тайл хранит canStand и placementPoints [{x,y,elevation}]. Точки общие
для предметов и персонажей, координаты задаются внутри занимаемого прямоугольника,
высота — от нижней точки файла. Флаг canStand отключает возможность размещения.
В справочнике точки показаны голубыми сферами и редактируются отдельно от зелёных
пазов. Миграция измеряет начальные высоты по реальной геометрии совместимых исходников.
Мосты получают точки по клеткам, лестницы — на подходящих ступенях.

Модельный объект хранит modelId и placement {tileId,point}. При вставке сферы
показывают свободные допустимые точки (зелёные, активная крупнее); привязка
учитывает поворот, этаж и mountDepth. Объект следует за опорным тайлом; удаление
опоры удаляет его из редактируемого документа. Предметы и персонажи используют
одинаковые координаты поверхностей. Модель сундука подготовлена из пользовательского
STL и загружается напрямую в S3 через MCP, без передачи модели по SSH.

Исходный код, коллекция, имя исходника и старые UUID не редактируются.
Текущая геометрия и параметры используются во всех картах и сессиях, включая
прежние размещения. Истории моделей и выбора версии нет. Конфликт behaviour.revision
получает 409 и сохраняет черновик формы; каталог обновляется по запросу пользователя.
При незавершённых параметрах окно справочника остаётся открытым: перед закрытием
правки нужно сохранить или отменить. Рабочая карта сохраняет своё состояние. Переключение пака при незавершённых параметрах
также требует сохранения или явной отмены черновика. Расположение стен (`wallMode`)
задаёт стыки по центру клетки (`center`) или по её краям (`edge`); это независимо
от формы. При `none` стыков нет.

Редактор и сессия используют общую панель MapSidebar: одинаковые вертикальные
вкладки, заголовок, сворачивание, отступы и прокрутка. В сессии панель прилегает
к левому краю рабочего поля на всю высоту, без отдельной рамки, скругления и тени;
колонка игроков расположена справа с обычным отступом.

Вкладка «Освещение» в обоих местах использует MapLightingControls: переключатель
«Освещение», секцию «Дневное освещение» и секцию «Источники света». Заголовки
обеих секций оформлены общим DetailSection. Все флаги освещения — ToggleSwitch.
В редакторе пунктирный плюс «Добавить источник света» — первый элемент списка,
перед источниками. Плюс открывает меню пресетов «Факел», «Свеча», «Магический свет»;
выбор запускает постановку источника у курсора. Меню поддерживает стрелки,
Home/End, Enter, Escape. Источник показан общей строкой-плиткой MapEntityRow:
лампочка отображает состояние, отдельный ToggleSwitch справа переключает
включение, а область указана в скобках после имени. Сессия использует такую же
строку без действия выбора и редактирования параметров. Выбор открывает поля справа на холсте.
Поля источника: название, включение, цвет, яркость,
радиус, высота, мерцание, тени и отдельный переключатель «Показывать сферу источника».
Скрытие сферы исключает только маркер редактора и его выбор на холсте; источник
продолжает светить и доступен в списке. Пока источник вставляется, превью сферы
остаётся видимым. Esc/ПКМ отменяют постановку.

«Привязать» включает выбор модели: следующий клик на тайл или объект задаёт
anchor, Esc отменяет выбор. Привязанная модель показана миниатюрой и именем;
нажатие выделяет её и перемещает камеру к ней. Привязка не требует заранее
выделенного тайла. Настройки источника находятся только в правой панели.

Без режима освещения используется прежний постоянный свет без локальных
источников, теней и мерцания. Флаг `lightingEnabled` сохраняется в документе,
первоначально выключен; изменение режима не сбрасывает параметры солнца и
источников. Маркеры доступны для редактирования и при выключенном режиме.
«Дневной свет» включается отдельным переключателем в секции «Дневное освещение», ползунки задают
направление 0–360° и высоту 10–85° над горизонтом. Эти поля доступны при включённом
режиме; при выключении только солнца остаётся слабый общий свет, а локальные
источники продолжают работать.

Источник можно выбрать/перенести по маркеру на холсте и привязать следующим
кликом к тайлу или предмету: он следует положению, повороту локального смещения и высоте
модели. Удаление опоры удаляет привязанный свет. Область выбирается явно или
определяется по опоре: скрытая область выключает свет в редакторе/трансляции,
в сессии оставляет 12% его яркости. Параметры освещения копируются с картой в сессию.
Ctrl/Cmd+C сохраняет снимок выбранного источника; Ctrl/Cmd+V ставит независимую
копию у текущей мыши, включая размещение на возвышенности. Повторная вставка и
отмена сохраняют буфер. Копия получает новый UUID, сохраняет параметры и флаг
сферы; исходная привязка/область снимается, высота опоры определяется в новой
позиции. Если обе теневые позиции заняты, копия размещается без теней.

Тени солнца и до двух локальных источников используют отдельные shadow GLB моделей.
Карта хранит до 32 ручных источников и встроенные источники моделей; renderer выбирает до восьми активных по выделению,
теням и близости к обзору. Мерцание при неподвижной сцене обновляется 10 раз/с;
карты теней обновляются при изменении сцены/положения света.

Боковая вкладка «Области» содержит компактные строки с именем, цветной иконкой,
числом тайлов/объектов и отметкой скрытия. Нажатие открывает область в правой
панели и выделяет все её тайлы и объекты, включая скрытые. Пустую область также
можно взять в фокус. Фокус не сохраняется в документе. Создание области из
обычного выделения добавляет эти элементы; если уже выбрана область, новая
создаётся пустой.

Справа редактируются название, цвет через ColorPresetPicker и скрытие; полный
список выводит каждый экземпляр отдельно через MapEntityRow, без группировки
одинаковых моделей. Список включает тайлы, объекты и источники, относящиеся к
области явно либо через привязку к её моделям, включая встроенный свет. Нажатие
на строку открывает фокус конкретного элемента. Пока область в фокусе, изменение
её состава и undo/redo обновляют выделение целиком; переименование, смена цвета
и скрытие сохраняют фокус. Цвет обозначает область в списке и заголовке;
контуры тайлов и объектов сохраняют цвета своего типа.

Иконка минуса в строке тайла/объекта убирает его из области, оставляя на карте.
Новые элементы добавляются через блок «Область» их собственного фокуса или
группового выделения. Каждый экземпляр может входить в одну область. Название
ограничено 100 символами, число областей — 200. Цвет хранится как непрозрачный
`#RRGGBB`, стандартный — `#8b5cf6`; короткий пользовательский HEX разворачивается
в RGB. Удаление области, включая Delete при её фокусе, оставляет модели на карте.
Снятие фокуса кнопкой X или Esc снимает её выделение. Состав, цвет и переключатель
«Скрыть область» сохраняются в документе и участвуют в undo/redo. При удалении
моделей или уменьшении карты ссылки на них убираются из состава.

Скрытая область полностью исчезает в редакторе и на отдельном `/map-screen/:code`.
На странице сессии её тайлы и объекты отображаются с прозрачностью 12%, чтобы
ведущий видел расположение. Скрытые экземпляры остаются частью расстановки:
занимают прежние клетки и сохраняют физические опоры. На холсте редактора они исключены
из выбора, магнитных точек и кисти стен; выбор строки области позволяет
управлять её составом. Параметры области копируются в карту
сессии при добавлении исходной карты. Имена областей не передаются в публичный
снимок. `areas` группируют конкретные ID экземпляров; `zones` описывают клетки и
прямоугольники тумана.

Текст в левой и правой колонках можно выделять и копировать стандартным
Ctrl/Cmd+C: непустое текстовое выделение сохраняет нативный буфер обмена.
Перенос из каталога начинается с изображения или свободного места карточки;
названия и коды допускают выделение текста.

Без текстового выделения Ctrl/Cmd+C сохраняет снимок выбранных тайлов, объектов, области или источника света
во внутренний буфер. Ctrl/Cmd+V сразу показывает превью у текущей позиции мыши,
без дополнительного движения. Исходный выбор во время вставки не подсвечивается.
Превью учитывает верхние пазы под курсором и сохраняет относительные уровни
скопированного участка; клик применяет его одним шагом undo. ПКМ и Esc отменяют
вставку и возвращают обычный выбор. Буфер не очищается после вставки или отмены, поэтому V
можно повторять многократно. Новые копии получают собственные UUID.
Для каждого исходного кода и названия предлагается одна текущая модель;
два разных исходника UD-055 остаются отдельными карточками. Исторические UUID
остаются в каталоге для документов и проверки размещений.

Плитку перетаскивают из левого каталога либо выбирают клавиатурой: редактор показывает модель,
следующей за курсором до клика. Она магнитится к ближайшей
допустимой позиции и плавно переходит между позициями; документ меняется только
при клике размещения. При подборе учитываются вся площадь, поворот, уровень и опора.
При переносе и анимации посадки всегда используется основная геометрия render,
даже если неподвижные модели отображаются через LOD при отдалении.
Если рядом нет допустимой позиции, размещение не применяется.
Esc, потеря фокуса и pointercancel отменяют размещение. Клик за пределами поля
не размещает плитку. Можно также выбрать карточку клавишей Enter/Space, перемещать модель
центром обзора и разместить Enter. R поворачивает переносимую или выделенную плитку
на 90°; отдельной кнопки поворота плитки нет.

Удержание Cmd/Ctrl при переносе карточки показывает заполнение пустого пространства
выбранной моделью. Область должна быть окружена размещёнными плитками; достижение
границы карты, занятая стартовая клетка или превышение лимита отменяют заполнение.
До клика это предварительные экземпляры; весь участок сохраняется одним шагом undo.

По умолчанию на карте действует выбор. Наведение подсвечивает видимый контур
геометрии, включая выступы и пустоты; нажатие усиливает контур. Действия удаления
и копирования находятся в панели выделения, всплывающего меню удаления над моделью нет.
Raycaster проверяет реальные треугольники экземпляра,
а не прямоугольную ячейку. ЛКМ с движением сразу сдвигает камеру, даже над моделью. Короткий клик выбирает
элемент; удержание 500 мс без смещения на 5px или больше запускает перенос модели или
источника. Модель сразу поднимается, ещё до движения мыши. Выбранная плитка
переносится с сохранением точки захвата; её исходное положение остаётся в
документе до завершения переноса. Объекты на её точках размещения и все
привязанные источники (в том числе встроенные и свет на объектах) следуют за
анимированным преобразованием опоры: подъёмом, сдвигом, поворотом, изменением
высоты и посадкой. Для таких объектов используется render-геометрия; их тени
тоже следуют за превью. Отпускание применяет размещение и поворот объектов одним
шагом undo; Esc, pointercancel и потеря фокуса отменяют перенос. Правило удержания
действует в редакторе; токены в сессии переносятся сразу.
Валидное перемещение или добавление создаёт один шаг undo, выбор и отмена
не изменяют историю. Cmd/Ctrl + клик добавляет тайл в группу или снимает его;
протягивание области с Cmd/Ctrl добавляет пересекающиеся модели в экранном
прямоугольнике. Перенос группы сохраняет относительные позиции, применяя всю
операцию только при отсутствии пересечений и выхода за карту. Delete и корзина
удаляют группу. R поворачивает группу целиком вокруг общего центра с привязкой к
сетке: меняются позиции и ориентации, а взаимное расположение и уровни сохраняются.
Опорные каркасы поворачиваются вместе с зависимыми верхними плитками. Тот же поворот
доступен при переносе и в превью вставки. Пересечение, выход за карту или потеря
опоры отменяют весь поворот; успешный поворот создаёт один шаг undo. Копирование
переносит выбранные тайлы.
Участок можно выделить, скопировать и вставить вместе с объектами. История хранит 50 состояний.

Выбор одного тайла подсвечивает его геометрию и открывает доступ к действиям
в панели выделения. Разметка стен, маска стыков и геометрия размещения редактируются
в админском справочнике. Выделение на карте служит для переноса, копирования,
поворота и удаления, без выбора раскладки стен над моделью.

Размеры моделей могут занимать несколько клеток; лестницы, каркасы, мосты,
проходы и колонны доступны отдельными типами фильтра. Встроенная обстановка фильтруется отдельным флагом. Явного переключателя уровней нет: при переносе
из каталога и на карте выбирается ближайшая подходящая опора под курсором,
включая верхний паз уже собранного каркаса. Вне пазов плитка возвращается на землю.
Переносимые модели и их зависимые тайлы исключаются из поиска опоры, чтобы не
прилипать к собственным прежним слотам. Предпросмотр плавно меняет координаты
и высоту; расстановка меняется одним шагом undo только при отпускании.
Первый уровень допускает свободное размещение без нижней опоры. Для уровней 2–16
достаточно опорного слота хотя бы под одной клеткой всей площади: мост и другие
большие плитки могут свешиваться над пустотой. Самые высокие доступные слоты
определяют плоскость; более низкие клетки остаются под свесом. Проверки границ
карты и пересечений на одном уровне охватывают всю площадь плитки.
Высота берётся из слотов, а не из фиксированного расстояния. Проверка одинакова в редакторе
и Go API. Опора переносится и удаляется вместе с зависимыми верхними тайлами.
Размещение и отображение используют повёрнутые координаты слотов.
Основание корпуса задаёт высоту размещения; монтажный выступ находится ниже
него. `mountDepth` задаёт расстояние от низа GLB до корпуса и вычитается при
рендере. Высоты поверхности, верха и пазов в каталоге измеряются от низа файла,
поэтому мировой верх паза равен `elevation + slot.elevation - mountDepth`.
У каркаса паз может содержать измеренный `insertionRise` от0 до0,1 клетки:
дополнительный подъём корпуса плитки с монтажным выступом при посадке
на внутреннюю фаску. Его добавляют только для входящей модели с mountDepth>0;
каркас без выступа ставится прямо на кромку. Геометрическая высота слота,
maxHeight и сфера паза сохраняют реальные координаты каркаса. Например,
у Lost Cave Level Grid проверенные вставки садятся на2 мм выше кромки.
Следующий выступ входит в паз, не увеличивая высоту каждого этажа.
Миграция 172 добавляет измеренные значения существующим версиям по коллекции,
исходному коду/имени и SHA-256 исходника. UUID и расстановка сохраняются.
Для моделей без монтажного выступа глубина равна нулю.

В браузерных версиях монтажные части заменены простыми усечёнными пирамидами
по 12 треугольников. Контуры исходных выступов определяют их количество,
размеры и расположение, включая несколько отдельных выступов больших плиток.
Корпус выше mountDepth, его UV и карты материалов сохраняются. Исходные STL
не меняются; упрощение заменяет геометрию текущей модели.

R поворачивает тайлы и объекты, включая перетаскиваемое превью. Отрисовка плавно
доворачивает модель за 280 мс; документ сразу хранит угол, кратный 90°.
Группа движется по дуге вокруг общего центра, без изменения расстояний между
моделями. Повторное нажатие продолжает поворот с текущего визуального угла.
Объект из бокового каталога перетаскивается так же, как плитка; отпускание вне
поля, Esc и ПКМ отменяют размещение. Клавиатура также поддерживает вставку после выбора. Пока GLB загружается, под курсором отображается
фиолетовая клетчатая площадь с вращающимся индикатором; загрузка не блокирует
перемещение превью или отмену.

При переносе плитка плавно приподнимается над опорой. После отпускания она
опускается в сохранённую позицию; при отмене возвращается на прежнее место.
Пока идёт посадка, результат уже находится в документе, а его неподвижная копия
скрыта за анимированной. Посадка не создаёт дополнительных изменений или undo.
Приземляющаяся модель остаётся доступной для повторного захвата.

Начальный ракурс ортографической камеры
изометрический: по диагонали, азимут 45° и наклон около 35,26° над сеткой.
Под сеткой нет сплошной плоскости; плитки рисуются на фоне сцены.
Сетка клеточных моделей лежит ниже основания и проходит depth test: видна в
пустых местах и закрывается геометрией. У сетки изображения остаётся высота
поверх фона; контуры зон и маркеры стыков показываются поверх сцены.
Колесо меняет масштаб, Alt/средняя кнопка перемещают поле, правая кнопка или
Shift вращают обзор и меняют наклон. Стрелки перемещают камеру относительно
экрана плавно, с ускорением и торможением по времени кадра; частота повтора
клавиатуры не задаёт скорость. В полях ввода и штатных клавиатурных переключателях
они не перехватываются. ЛКМ с движением перемещает поле, удержание 500 мс над моделью запускает её перенос;
Cmd/Ctrl оставляет протягивание области множественного выбора.
Подсказки находятся снизу слева, кнопки камеры — снизу справа; кнопки поворота нет.
Кнопки «Сверху» / «Изометрия» переключают плоский и изометрический ракурсы.
Поворот обзора не меняет поворот плиток. На мониторе стола камера всегда смотрит сверху.
Превью библиотеки показывает сохранённый 3D-снимок.

Каждое размещение хранит собственный ID, постоянный UUID модели,
целые координаты клетки, поворот 0/90/180/270 и уровень 0–15. Размеры и форма
компонента берутся из каталога, а не из присланного документа. Исходные STL,
текстурированные GLB, облегчённые GLB, геометрия теней и WebP-превью находятся в S3;
в PostgreSQL хранятся их ключи, размеры, SHA-256, коллекция, тип стен, маска стыков
и верхние слоты `{x,y,width,height,elevation}`. Локальная папка
models игнорируется Git. Загрузка и регистрация доступны через [MCP](mcp.md#плитки-3d-редактора).
Инструкция подготовки — [пайплайн обработки моделей](maps-model-pipeline.md).

Геометрия теней загружается через shadowUrl только при включённом режиме
освещения. Она использует координаты GLB, монтажное смещение, масштаб и анимацию
видимого тайла/объекта. Теневые экземпляры группируются по модели в InstancedMesh;
они разделяют геометрию и не используют текстуры. Контуры blockers предназначены
для логики препятствий; объёмы, вытянутые из них, для теней не используются.
Скрытые области не отбрасывают тени. Если shadow ссылается на LOD, API отдаёт тот
же URL, поэтому повторной загрузки файла нет. Публикация отдельного shadow GLB
обновляет тени текущей модели во всех сохранённых картах.

Материалы Ultimate Dungeon, индивидуальная покраска и уровень `textureDetail`
описаны в [текстурах моделей](maps-textures.md).

В map_model хранится одна запись на definition_id. Миграция 189 сохраняет первый
UUID модели, переносит в него актуальные параметры и assets, заменяет modelId
в battle_map/session_map и таблицах FK, удаляет исторические строки и колонку version.
Экземпляры, координаты, области, привязки и состояние сессии сохраняются.
Рендер использует текущую запись. Файлы остаются content-addressed в S3;
render/lod/shadow/preview URL содержат ?sha=<хеш файла>. Новая публикация меняет
адрес ресурса при том же UUID, поэтому браузер загружает актуальный файл.
URL без sha требует повторной проверки кэша. Публичный экран отдаёт только модели
показанной карты и запрещает исходные STL. Изменение каталога обновляет меши сцены
и инвалидирует сохранённые снимки всех карт, использующих изменённую модель.
Открытый редактор, сессия и публичный экран перечитывают текущий каталог раз в
30 секунд, пока вкладка видима; старые GPU-ресурсы заменённых моделей освобождаются.
Перенос тайлов и объектов сохраняет непрозрачность их материалов и запись глубины;
полный render GLB используется для переносимого превью.

Объекты лежат поверх основы: дверь, двойная дверь, решётка, бочка, ящик,
стол, сундук, факел, лестница, колонна, обломки и мост. Есть перемещение,
поворот, размер и начальное состояние интерактивных объектов. Зона состоит
из объединения клеток и/или нескольких прямоугольников; её можно назвать,
дополнить, очистить или удалить.

Сохранение автоматическое после паузы, включая первое сохранение новой копии.
Кнопки сохранения и экспорта JSON нет; успешные записи не открывают уведомления.
Настройки показывают дату и время последней успешной записи по changedAt сервера.
Ошибка сохранения открывает AppModalFrame с повтором при сетевой ошибке.
При конфликте `409` локальный вариант остаётся в редакторе. Undo не откатывает
серверную revision или время последней записи. Закрытие с несохранёнными
изменениями требует подтверждения.

Кнопка «Карты» в шапке редактора возвращает в библиотеку. Стрелка передаётся
в отдельный `icon`-слот общего `ActionButton` и выровнена по вертикали с текстом;
такой же слот используется для возврата из состояния ошибки загрузки.

## Карта в сессии

Вкладка «Карта» стоит справа от «Бой», перед разделами каталогов. Карта занимает
всё рабочее поле, как сюжет; отдельной страницы мастера для её показа нет.
`SessionTabWorkspace` использует режим `full` для карты и `column` для вкладок
с центральными колонками. Во вкладке «Бой» карта и её панель не отображаются:
там сохраняются прежние колонки инициативы, запаса и превью текущего хода.
Карта и камера сохраняются при возвращении на вкладку «Карта».

Сессия использует тот же MapEditor, MapTileSidebar, палитры, жесты, историю,
буфер обмена и MapSelectionPanel, что и редактор заготовок. Доступны добавление,
перенос, поворот, копирование и удаление плиток/объектов, редактирование областей,
источников, привязок и переходов моделей. Скрытые области для мастера прозрачны,
для игроков убраны. Справа выбранный элемент редактируется общей панелью.
Колонка игроков, прежние верхний выбор карты/трансляция и нижняя панель режимов
на карте отсутствуют. Верхних кнопок действий и входа в справочник в сессии нет;
копирование/удаление доступны в правом фокусе, история — с клавиатуры.
При переходе к сюжету/бою карта и камера сохраняются, её горячие клавиши отключаются.

Вверху боковой панели сессии стоят «Настройки» и «Существа».
После разделителя идут общие вкладки «Плитки», «Освещение», «Объекты», «Области».
Настройки показывают карточку исходной заготовки, «Переключить карту» (из уже
открытых копий) и «Открыть новую» (из библиотеки). Здесь же название/размеры/теги,
сетка/пазы, последний момент сохранения, туман, вид игроков и экран стола.
При переключении меняется активная карта экрана; флаг показа и калибровка сохраняются.
Перед переключением/открытием/удалением редактор завершает сохранение; при ошибке
показывает выбор остаться или уйти без несохранённых правок.

Добавление создаёт независимую копию документа и source {id,name,system}.
Геометрия, свет, области и состояние редактируются только в сессии; исходная
заготовка не меняется. Повторное открытие той же заготовки создаёт ещё одну копию.
Удаление копии требует подтверждения и выключает её экран. Если заготовка удалена,
её сохранённое название остаётся в карточке основы.

В «Существах» сначала показаны участники сессии, затем NPC encounter, отдельно
метки. Строки используют MapEntityRow, портрет и SessionHpBar. HP читаются из
живого листа/encounter, не копируются в карту. Нажатие на строку или жетон открывает
фокус справа; там портрет, HP, координаты, размер, скрытие/физическая миниатюра,
размещение и удаление с карты. Игроку доступно открытие листа; участнику encounter —
его существующий калькулятор HP. Неразмещённое существо тоже можно выбрать в фокус.
Плюс запускает следующее за курсором превью на общих точках поверхностей;
Esc/ПКМ отменяют размещение. Удержание ЛКМ на жетоне позволяет перенести его,
короткий протягивающий жест перемещает камеру. Перенос — одно действие undo;
жетоны на тайле следуют его перемещению, повороту и анимации подъёма.
Жетон хранит идентичность, имя/портрет на момент размещения, позицию, размер,
цвет и флаги. Физическая миниатюра видна мастеру и скрыта на экране игроков.
Удаление опоры удаляет её размещённые жетоны; существа остаются в составе сессии.
У процедурных интерактивных объектов переключатель «Открыто» находится в фокусе;
модельные состояния меняются общими переходами каталога.

Туман имеет три состояния: скрыто, исследовано, видно. Мастер видит скрытое
под затемнением и штриховкой; экран игроков полностью закрывает скрытое,
а исследованное показывает затемнённым без жетонов. При пересечении зон
побеждает более открытое состояние. Вне размеченных зон действует общее
состояние. Можно открыть/скрыть всё, выключить туман и включить предпросмотр
вида игроков. Автоматической линии зрения, света от препятствий и ограничения
перемещения стенами нет: видимостью и расстановкой управляет мастер.

Сервер удаляет из публичного ответа скрытые жетоны, физические миниатюры,
жетоны в тумане и на плитках скрытых областей, ссылки на сущности, названия зон и теги карты. Геометрия
передаётся экрану целиком; туман — визуальная маска, а не ограничение
скачивания фрагментов карты. Код трансляции даёт доступ к экрану без входа,
но не даёт права изменять состояние.

## Экран стола

Переключатель «Показывать карту игрокам» находится в сессионных настройках. Можно
затемнить экран, вписать карту, задать фиксированный масштаб, повернуть
на 90° и перенести центр обзора мастера. Обычные pan/zoom мастера не сдвигают
стол. Ссылка открывается отдельным окном; полноэкранная кнопка появляется
при движении указателя и затем скрывается.

Для физических миниатюр выключают «Вписывать всю карту», измеряют клетку
линейкой на целевом мониторе и задают измеренный и нужный размеры в мм.
Калибровка умножает CSS-пиксели клетки на `нужно / измерено`. Она сохраняется
на сервере вместе с камерой; поворот и переподключение сохраняют масштаб.
Калибровать следует после выбора монитора, браузерного zoom и полноэкранного
режима. Смешанный стол поддерживается флагом физической миниатюры у каждого
жетона. Масштаб задаёт размер клетки 3D-карты на экране.

## Реализация и синхронизация

Сессионная копия содержит редактируемые name/document и отдельный state с жетонами,
туманом и состояниями интерактивных объектов. PUT принимает {name,document,state,revision};
документ, состояние, timestamp/revision и FK моделей сохраняются одной транзакцией.
Сервер валидирует полную сцену и размещение жетонов на её поверхностях. CAS защищает
от конкурирующих записей. SSE и повторные чтения не заменяют локальный черновик во
время жеста/сохранения/несохранённых изменений; конфликт требует явной перезагрузки.
Миграция 190 переносит прежние state.areas/state.lighting в document и удаляет
эти дублирующие поля из state. Она сохраняет настройки видимости/солнца/источников,
позиции жетонов и revision. Встроенные источники, ранее существовавшие только при
чтении, получают сохранённую активацию; гидратация восстанавливает их положение
и актуальные поля по модели. Source — неизменяемое происхождение копии;
по имени/документу миграция связывает существующие копии с доступными заготовками.
Публичный ответ не содержит source, скрытые жетоны, ссылки и внутренние названия.

`internal/battlemap` — документ версии 2, валидация, пресеты и публичная
проекция. `features/maps` — Vue-композиции и Three.js WebGL2 renderer.
GLTFLoader читает GLB с Meshopt и KTX2 (`KHR_texture_basisu`). Meshopt встроен
в единственный JS bundle; Basis worker JS/WASM запрашивается при первой KTX2
модели. KTX2Loader выбирает поддерживаемый GPU-формат. Загрузчики и кеш
текстур разделяются только между canvas с одинаковыми возможностями GPU.
Начатые загрузки могут завершиться для других пользователей общего кеша;
ещё не начатые без пользователей отменяются.
Плитки группируются по модели и пространственным чанкам в InstancedMesh;
при масштабе меньше 72 CSS-пикселей на клетку используется облегчённая геометрия.
Она сохраняет цветовые карты и рельеф. Ресурсы загружаются по необходимости,
не более трёх моделей одновременно; геометрия и текстуры разделяются между
открытыми canvas и освобождаются после последнего пользователя.

Сцена открывается после метаданных, не ожидая всех GLB. На месте отсутствующих
плиток/объектов показаны фиолетовые клетчатые плоскости с анимированным кольцом;
плоскости сцены объединены в InstancedMesh и учитывают этаж, размеры, скрытые
области и прозрачность мастера. По ним можно выбрать ещё загружаемый элемент.
Каждая модель отдельно загружает LOD и заменяет свою заглушку, затем при масштабе
от 72 CSS-пикселей — render. При отдалении до завершения LOD лишний render не
запрашивается. Готовый вариант остаётся видимым до готовности нужного качества;
сбой одной модели не задерживает остальные. Геометрия теней загружается отдельно.
Общий лимит — три одновременных загрузки: переносимая полная модель имеет
приоритет, затем LOD сцены, детализация и тени. Переносимые превью сохраняют
полную геометрию и свою заглушку до готовности render.
Готовые меши применяются через объединённые обновления на animation frame;
смена LOD/render пересобирает соответствующие слои и контуры. Повторить загрузку
сбрасывает ошибочные запросы. Снимок для S3 ожидает нужные меши и тени;
заглушки не попадают в сохранённое изображение.

Canvas2D создаёт карту видимости; шейдеры применяют её в мировых координатах
ко всем поверхностям плиток и объектов. Скрытая геометрия не рисуется игрокам,
исследованная затемняется, мастер видит закрытое под затемнением и штриховкой.
Перерисовка происходит по изменениям и ResizeObserver, постоянного ticker
нет. При движении предварительного тайла короткая анимация сглаживает его
позицию; она прекращается после достижения цели. Предварительная модель имеет
отдельный слой и не пересобирает все экземпляры карты при каждом движении.
Силуэт выделения строится из геометрической маски; depth prepass исключает
поверхности за другими моделями. Плоскость стыков привязана к проекции модели
и обновляется вместе с камерой. Группы выделения и заполнения также используют
InstancedMesh, не создавая отдельную геометрию для каждой клетки.
Отдельные слои кешируются, ресурсы renderer
освобождаются при закрытии.

Код карт, редактора и движка входит в единый production JS. Компоненты и WebGL
renderer создаются при открытии карты. SSE сообщает об изменении;
клиенты получают durable snapshot через REST. Reconnect и возвращение
вкладки повторяют чтение; есть backoff и проверка каждые 45 секунд.
Записи сериализованы и защищены compare-and-swap revision, HTTP `409`
не перезаписывает более новую серверную версию. Во время локального
перемещения и сохранения чтение откладывается. Вкладка карты после первого
посещения остаётся смонтированной при переходе к сюжету/бою; уход со страницы
проверяет несохранённые действия. Перед перезагрузкой действует browser guard.

Ограничения документа: 4096 плиток, 1000 объектов, 200 зон, 100 прямоугольников на зону,
64000 суммарных ссылок на клетки зон. В сессии — до 250 жетонов. ID объектов
уникальны; состояния могут ссылаться только на зоны/объекты своего документа.
Сессионные API доступны исключительно владельцу сессии.

## Системные карты и проверки

«Пещерные залы» — 3D-заготовка из каталога Lost Cave; «Пустая пещера» —
поле для собственного построения. Модельные файлы в frontend не встраиваются.
Режимы image/image-grid, их пресеты, загрузка фонов, смещение сетки и публичный
map-background API удалены. Миграция 187 удаляет библиотечные и сессионные карты
этих типов, выключает их трансляции и убирает фон/авторство/калибровку из документов.
Остальные 3D-карты, модели, объекты, области и состояние сессии сохраняются.

Unit-тесты проверяют размещение, заливку, повороты, координаты, resize, теги и очередь снимков,
пересечения тумана, публичную проекцию и валидацию пресетов. Browser-сценарии:
`cd frontend && npx playwright test -c playwright.maps.config.js`.
Persistence-тест запускается только с `DNDSHARE_MAP_TEST_DSN`, localhost
и именем БД `dndshare_test_*`; проверяет независимость копий, владельцев,
CAS, межсессионные FK, ссылки на текущие модели и выключение удалённой карты. Production DSN для него
не используется.
