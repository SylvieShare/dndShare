# Обучение листу персонажа и сессии

Первое открытие собственного листа или страницы сессии авторизованным игроком
запускает короткую прогулку по интерфейсу. Она ждёт загрузки страницы и настроек
аккаунта. Первая карточка объясняет управление; доступны «Далее», «Назад»,
«Пропустить» и завершающая кнопка. Пропуск, включая Escape, запоминается отдельно
от прохождения. Закрытие страницы или смена размера на другой профиль отменяет
текущий тур без записи результата. Ошибка загрузки, цели или сохранения позволяет
повторить попытку и не записывает ложное прохождение.

В листе D&D сценарий показывает характеристики, здоровье с открытием редактора,
оружие, магию, снаряжение, способности, дневник и меню. Для других листов есть
общий сценарий заполнения без D&D-специфичных целей. Публичный чужой лист,
печатная версия и предпросмотр в модальном окне не запускают обучение владельца.
В сессии отдельные сценарии для мастера и игрока: интерфейсы и доступные действия
различаются. Гостям прогресс не записывается.

## Хранение

`dndshare.user_tutorial` — нормализованная часть настроек пользователя. Это
отдельная таблица, а не растущий JSON с перезаписью всех настроек. Первичный ключ:
`(user_id, flow_id, source_key, device)`.

- `flow_id`: `character`, `session-player`, `session-dm`.
- `source_key`: `edition:<sourceVersionId>` для листа; `source:<systemId>` для
  сессии; `unassigned` для сессии без системы. Идентификаторы берутся из самого
  листа/сессии, а не из текущего глобального выбора аккаунта. Дополнительные
  книги, Legacy и homebrew в фильтре контента не создают новый UI и новый флаг.
- `device`: `mobile` или `desktop`. Лист использует breakpoint 640px, сессия —
  760px, согласно своим раскладкам. Это профиль интерфейса, не определение ОС.
- `revision`: версия сценария; `status`: `completed` или `dismissed`;
  `updated_at`: дата результата. Отсутствующая запись или меньшая версия
  запускает обучение. Внутренний номер текущего шага не сохраняется.

API всегда использует пользователя из серверной cookie-сессии, не принимает
`userId` от клиента. `GET /api/account/tutorials` возвращает `{ tutorials: [] }`;
`PUT /api/account/tutorials` принимает одну запись без `updatedAt`;
`POST /api/account/tutorials/reset` принимает только её ключевые поля и удаляет
ровно одну запись. Проверяются сценарий, профиль, формат и существование
источника. Upsert не понижает revision и не заменяет `completed` на `dismissed`
для той же revision. Одновременные записи других устройств/сценариев не теряются.

Pinia `stores/tutorials` кэширует данные текущего пользователя и объединяет
параллельные чтения. Серверный прогресс доступен после входа в другом браузере;
`localStorage` для него не используется. Автопроверка выполняется один раз за
контекст страницы. Один владелец тура блокирует конкурирующие туры.

## Повторный запуск

В меню листа и настройках сессии есть «Пройти обучение снова»: запускает текущий
сценарий сразу, независимо от сохранённого результата. Во вкладке «Обучение»
на странице аккаунта показаны сохранённые результаты по системам и устройствам.
«Показать снова» удаляет выбранный результат: обучение появится при следующем
открытии соответствующей страницы. Сброс одного профиля не сбрасывает остальные.

## Устройство сценариев

- `share-ui/GuidedTour` и `useGuidedTour` отвечают за карточку, подсветку цели,
  ожидание DOM, кнопки, focus trap, Escape, блокировку горячих клавиш и rollback.
  Пакет не знает о пользователях, API, маршрутах и игровых системах.
- `features/tutorials/flows/character.js` и `session.js` содержат порядок, тексты,
  стабильные ID шагов и условия desktop/mobile/роли/системы.
- `useCharacterTutorial` / `useSessionTutorial` адаптируют страницу.
  `usePageTutorial` отвечает за readiness, контекст аккаунта, отмену и сохранение.
- Семантические `data-tutorial` обозначают цели. Поиск ограничен текущей страницей;
  телепортированные окна разрешаются явно через `document`. Классы оформления
  и русский текст кнопки не используются как селекторы действий.
- `useTutorialAction` регистрирует по имени контролируемое UI-действие.
  Шаг получает AbortSignal и сразу регистрирует синхронный `onCleanup` перед
  изменением состояния. При уходе с шага, назад, отмене и размонтировании
  восстанавливаются прежняя вкладка, состояние открытого меню/редактора и
  прокрутка. Запоздалый async-результат отменённого шага не должен менять UI.

Обучение не делает бросков, не меняет HP/ресурсы, не создаёт записи и не запускает
бой, музыку или трансляцию. Переходы разделов идут через временные refs, без
записи в историю маршрутов и сохранённые пользовательские настройки раздела.
Карточка стоит выше открываемых окон, а её щит блокирует игровые кнопки.

## Изменение страниц и проверка

При изменении навигации, расположения блоков, редактора или прав доступа в листе
и сессии обязательно проверить соответствующий сценарий в этом же изменении:

1. Обновить `data-tutorial`, регистрацию UI-действия, тексты и порядок шагов.
2. Проверить desktop и mobile; для сессии — игрока и мастера. Пустые списки,
   персонаж без магии и сессия без выбранной главы должны оставаться допустимыми.
3. Проверить назад, пропуск, повтор из настроек, отмену при навигации/resize и
   отсутствие игровых mutations. Для существенной переработки обучения поднять
   `TUTORIAL_REVISION` в `lib/tutorialIdentity.js`. Редакционные правки текста
   не требуют принудительного повторного показа всем пользователям.
4. Выполнить `npm test -- --run`, `npm run build` и
   `npx playwright test --config playwright.tutorials.config.js` в `frontend`.
   Браузерные тесты используют реальные страницы с перехваченным API: проходят
   все цели и проверяют, что единственная запись — прогресс обучения.
5. Обновить эту страницу, wiki листа/сессий и публичный контракт share-ui, если он
   изменился. Работа со страницей не завершена при устаревшем обучении.

Перенос бонуса магического оружия в защиту добавляет условный пункт внутри
существующего меню атаки и панель состояния под оружием. Цели обучения,
открытие оружия и порядок шагов не меняются; отдельный шаг для редкого свойства
не нужен. Проверки desktop/mobile и ролей выполняются прежним browser suite.

Окно повышения уровня использует широкую композицию, счётчики новых заклинаний,
явную замену и автоматическое начисление ячеек. Шаг «Магия» объясняет это для
обоих устройств; существующие цели листа и сценарии игрока/мастера сессии не
меняются. Обучение не открывает повышение и не принимает его, поэтому оно не
может случайно начислить уровень, хиты или заклинания. Изменение текста не
поднимает `TUTORIAL_REVISION`.
