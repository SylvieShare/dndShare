# Игровой контекст игрока

## Задача

В приложении есть единый текущий игровой контекст: игровая система и конкретная
редакция её правил. Игрок выбирает его в левом хедере приложения. Контекст
определяет:

- какие типы, предметы и словари участвуют в глобальном поиске;
- какая система и редакция изначально выбраны на посадочной странице
  справочника;
- на какую физическую страницу ведёт верхнеуровневый пункт «Правила».

Изменение выбора внутри справочника остаётся локальным для справочника и не
перезаписывает глобальный контекст. Это позволяет разово посмотреть материалы
другой системы, не меняя весь интерфейс.

## План реализации

1. Хранить в `users.source_version_id` ссылку на `source_version`; систему
   получать через `source_version.source_id`, не сохранять вторую копию.
2. Добавить игровой контекст в ответы авторизации и endpoint его изменения.
3. Создать Pinia-store, который загружает системы, выбирает сохранённую редакцию
   и предоставляет единый контекст навигации и поиска. Для гостя использовать
   local storage; для авторизованного игрока — БД.
4. Разместить доступный с клавиатуры компактный индикатор текущей системы и
   редакции в раскрытом и свёрнутом desktop rail и в мобильной шапке; подробные
   селекторы открывать по нажатию в popover.
5. Ограничить глобальный поиск системой и редакцией: item types и suggests —
   системой, публикации items и статьи правил — конкретной редакцией.
6. Инициализировать справочник глобальным выбором, после чего хранить его
   локальный выбор до ухода со страницы.
7. Зарегистрировать отдельные URL и физические Vue-страницы для каждой известной
   пары система/редакция. Не подменять отсутствующие правила контентом другой
   редакции.
8. Покрыть схему, выбор по умолчанию, маршруты, фильтры поиска и навигацию
   автоматическими тестами; проверить production build и интерфейс.

## Контракт данных и API

`users.source_version_id` является обязательным FK на `source_version`. Startup
schema назначает существующим и новым пользователям `DND5e / 2014`, пока они не
выбрали другое значение.

Ответы `POST /api/user/auth` и `GET /api/user/checkAuth` содержат в `user`:

```json
{
  "gameContext": {
    "sourceId": 1,
    "sourceName": "DND5e",
    "sourceVersionId": 1,
    "version": "2014"
  }
}
```

`PUT /api/account/game-context` принимает `{ "sourceVersionId": 1 }`, проверяет
существование редакции, сохраняет её текущему пользователю и возвращает
`gameContext` того же формата. Endpoint требует сессию.

## Навигация правил

Физический адрес включает систему и редакцию:

```text
/rules/dnd5e/2014                  D&D 5e 2014 — хаб
/rules/dnd5e/2014/:articleSlug    D&D 5e 2014 — статья
/rules/vampire-tm/v20             Vampire: The Masquerade V20
```

`/rules` является только входной точкой и переводит на страницу текущего
контекста. Пункт меню сразу использует целевой адрес из store. Для известной
редакции без подготовленного учебника существует собственная страница с явным
состоянием «материалы готовятся» и ссылкой на справочник; контент D&D 2014 в неё
не подставляется.

## Поиск и справочник

Глобальный поиск передаёт `sourceVersionId` в `items/search-multi` и `sourceId`
в `suggest/search`. Типы предметов дополнительно фильтруются на клиенте по
`sourceId`. Локальный индекс статей подключается только для DND5e 2014.

Посадочная страница справочника после загрузки выбирает глобальную пару
система/редакция. Пользователь может отдельно сменить обе величины внутри
страницы. При открытии коллекции выбранный `sourceVersionId` попадает в query и
используется для publication scope, включая совместимость редакций.

## Критерии готовности

- выбор авторизованного игрока переживает перезагрузку и новое устройство;
- гостевой выбор переживает перезагрузку в текущем браузере;
- смена системы сразу меняет ссылку «Правила» и область глобального поиска;
- справочник стартует в глобальном контексте, но локальная смена не меняет его;
- ни один результат другой системы или заблокированной редакции не появляется
  в глобальном поиске;
- адрес страницы явно и стабильно кодирует систему и редакцию;
- управление селектором доступно мышью, касанием и клавиатурой.
