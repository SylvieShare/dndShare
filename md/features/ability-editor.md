# Редактор зависимостей способностей

Редактор общий для расовых, классовых и сюжетных способностей (типы 3/4/18).
Каждая самостоятельная запись `object_array` верхнего уровня — отдельная карточка зависимости.
`scaling` и `display_scaling` объединены в одну карточку «Развитие с уровнем»: строки редактируются в таблице.
Повторное добавление типа добавляет одну запись, удаление карточки удаляет только
её запись. Внутренние массивы остаются списками внутри записи. Основной ресурс
и объектные настройки одиночные; `use_resources` добавляется как повторяемый
«Отдельный ресурс». Данные правил сохраняются в исходных массивах; служебные
ID карточек существуют только в UI. Неиспользуемые поля удаляются версионными
миграциями, перечисленными ниже.

Содержимое раскрытых спойлеров получает отступ слева и вертикальную линию.
Каждый вложенный спойлер добавляет свой отступ, показывая иерархию настроек;
положение заголовков при раскрытии не меняется.

Правила композиции, условной видимости и примеры сборки скрытой атаки и ярости
описаны в [манифесте редактора](ability-editor-manifest.md).

## Действие на листе

`AbilityActionEditor` показывает название, ключ, вид действия и описание.
Незаданный ключ транслитерируется из названия в `snake_case`, совпадения в одной
способности получают числовой суффикс. Ручной ввод, в том числе очистка, отключает
автоматическое изменение. При повторном открытии существующий ключ, включая
явно пустую строку, сохраняется. Ключ нужен для устойчивой идентификации действия
на листе; пустой ключ использует позиционный идентификатор runtime.
В пустом поле, в том числе после ручной очистки, плейсхолдер показывает ключ,
рассчитанный из текущего названия с учётом занятых ключей. Подсказка не заполняет
очищенное значение. Пока название не даёт ключа, виден текст «Заполнится из названия».

Стандартное действие из suggest 24 вставляется в описание как rich-node-ссылка.
При открытии редактора существующие `suggest_action_codes`, найденные в словаре,
переносятся в описание; неразрешённые коды сохраняются в особых настройках.
Лист выводит описание через безопасный `DndRichContent`, поэтому ссылки доступны
в самом тексте. Нетронутые предметы продолжают использовать текущий контракт
`suggest_action_codes`.

Условия появления содержат:

- выбор активных эффектов по названиям из каталога типа 15; в
  `required_status_codes` сохраняются коды, не ID, требуются все выбранные эффекты;
- текстовые памятки `requirements`, по одной на строку, без автоматической проверки;
- необязательное «Открыть действие позже». Уровень предмета — получение способности,
  уровень действия — отдельный порог относительно персонажа или связанного класса.

Расход имеет один режим: выключен, основной ресурс этой способности, выбранный
ресурс способности или общий ресурс класса. Общий пул — `class_resources.key`,
отдельный ресурс — `use_resources.key` вместе с предметом-источником; основной
ресурс другого предмета не требует ключа. Эти варианты не комбинируются.
Выключение очищает ссылку и стоимость. При открытии противоречивых настроек
сохраняется фактически действовавший источник: общий пул имеет приоритет.
Отсутствие другого `resource_item_id` не препятствует поиску локального ресурса.
У действия без расхода итоговая стоимость равна нулю.

Применение эффекта к оружию настраивается отдельно. Эффект выбирается по названию;
параметр цели `weapon_uid` используется по умолчанию и может быть переопределён
в особых настройках.

Пункты меню изменяют числовой показатель листа (`adjust_counter`). У каждого
есть название, автоключ, выбор показателя, величина изменения, границы и цвет.
Истощение доступно как готовый показатель; другие связи ищутся среди пунктов
меню справочных предметов, специальный контейнер можно задать явно.
Пустая верхняя граница означает отсутствие ограничения. Корзинки действий,
пунктов меню и вложенных записей находятся у заголовка и требуют подтверждения.
Удаление применяется к предмету при сохранении формы.

Сохранение блокируется для незавершённого действия, невыбранного ресурса/эффекта,
дублирующихся непустых ключей и некорректных пунктов меню. Ошибки показаны в footer.

## Поиск связей

`GET /api/items/rule-references` читает текущий JSON предметов. Параметры:

| Параметр | Значение |
| --- | --- |
| `kind` | Обязательный: `resource`, `resource_pool`, `action`, `status`, `choice`, `widget`, `counter`, `effect_link`, `weapon_damage` |
| `q` | Поиск по ключу, названию зависимости или предмета |
| `itemId` | Необязательное ограничение одним предметом |
| `excludeItemId` | Исключение сохранённой версии редактируемого предмета |
| `limit`, `offset` | Размер страницы (1–100, по умолчанию 40) и смещение |

Ответ: `{references: [{itemId, itemName, kind, block, key, title, valueId?}]}`.
`valueId` используется для составного адреса показателя персонажа. Видны только
публичные предметы и личные предметы текущего пользователя; анонимному запросу
доступны только публичные. Обновление/удаление предмета сразу меняет результаты,
дублирующая таблица ключей и её синхронизация не требуются.

Picker добавляет ссылки из несохранённого черновика и показывает предмет-источник
и название блока. Связи, действующие внутри одной способности (виджеты, локальные
выборы), ограничиваются этим черновиком; ссылка на выбор другого предмета
учитывает `source_item_id`. Ключи действий и виджетов имеют отдельные типы,
поэтому не смешиваются с ресурсами и кодами эффектов.

Регрессии: frontend-тесты генерации ключа, карточек, формы и runtime действий;
`TestItemRuleReferences` проверяет SQL на отдельной локальной PostgreSQL
(`DNDSHARE_RULE_REFERENCE_TEST_DSN`, база `dndshare_test_*`), включая права,
пагинацию и актуальность результатов после изменения предмета.

## Формы механик

`AbilityWeaponDamageEditor` предлагает фиксированное число костей или рост от уровня
и показывает предпросмотр тем же вычислением, что использует лист. Поле «Условие применения» (`condition`) даёт понятную подпись в меню и справочнике. «Способ атаки» (`attack_mode=thrown`) обозначает бросок оружия. «Требует другого переключателя» выбирает правило этого же предмета по названию и хранит `requires_damage_key`; выбор показывается при наличии других правил. Циклические и разорванные ссылки блокируют сохранение, переименование ключа обновляет зависимые переключатели.
`AbilityProgressionEditor` объединяет строки роста в таблицу; собственные подписи
спрятаны за флажком. `AbilityStatusEffectEditor` получает параметры из выбранного
эффекта и подписывает их названиями правил. Постоянное значение параметра видно
только в соответствующем режиме, длительность по умолчанию наследуется.
`AbilityMechanicEditor` читает метаданные панелей и условий из
`abilityMechanicManifest.js`; переключение режима удаляет несовместимые поля.
Миграция `77_ability_editor_damage.sql` удаляет неиспользуемые подписи пунктов
меню из `weapon_damage` в схемах и данных, совпадающие таблицы скрытой атаки
и отделяет текст о безлимитной ярости от её числового бонуса.

## Явные связи и источник уровня

У зависимости `weapon_damage` есть уникальный внутри способности `key`, который
создаётся из названия. Панель с `value_source=weapon_damage` выбирает конкретное
правило по названию и хранит `weapon_damage_key`. Ссылка не зависит от порядка
записей. Изменение ключа в редакторе обновляет связанные панели текущей способности;
удалённое или невыбранное правило блокирует сохранение панели, без выбора другой
записи автоматически. На листе разорванная связь явно обозначается.

В левой колонке настраивается источник уровня для всех зависимостей:
`level_source=class` + `level_class_id` — определённый класс,
`character` — общий уровень, `bound` — привязки `class_ids`/`subclass_ids`.
В режиме привязок берётся наибольший уровень подходящего класса; без привязок —
общий. Если заданный класс не найден, расчёт получает 0, добавка к урону не
предлагается, а панель показывает «Нет нужного класса». У одноклассового листа
общий уровень остаётся актуальным уровнем единственного совпавшего класса;
при мультиклассе используются отдельные уровни записей классов.
Форма урона и панель показывают выбранный источник уровня по названию.

Миграция 78 задаёт стабильные ключи существующим правилам без конфликтов,
материализует прежнюю связь панелей с первым правилом и устанавливает явный
источник у способностей с одним классом. Ручные существующие ссылки сохраняются.

### Ресурс дополнительного урона и цель эффекта

У «Дополнительного урона оружия» можно выбрать собственный тип урона.
Флажок «Расходует ресурс» раскрывает выбор основного/отдельного ресурса текущего
источника и положительную целую стоимость. Выключение удаляет эти настройки;
редактор проверяет существование ресурса. Основной ресурс не выбирается вместо
набора `use_resources`. Цена относится к одному броску урона, крит её не меняет.

У «Связанного эффекта» задаются получатель (владелец / другое существо), условие
наложения и необязательная связь с переключателем дополнительного урона текущего
предмета. Переименование ключа урона обновляет эту связь. Условие на цель остаётся
решением игрока: такой эффект не активируется на владельце источника.

### Рассвет и тезисы

У основного и отдельного ресурса поле «На рассвете» предлагает не восстанавливать,
восстановить полностью или использовать формулу. В последнем случае появляется
поле формулы, например `1к3` или `1к6+1`; значение проверяется до сохранения.
Данные: `dawn_recovery: {mode: "full"}` или `{mode: "roll", formula: "1к3"}`.

Описание действия объясняет результат обычным связным текстом и выводится через
`DndRichContent` с авторской разметкой, ссылками и костями. Оно не превращается
в тезисы и не делится автоматически на предложения. Например, «Хитрое действие»
остаётся одной фразой с доступными стандартными действиями.

Условия и ограничения задаются отдельно в «Условиях применения» (`requirements`),
по одному на строку. Только они выводятся под описанием через `MechanicTheses`
тем же стилем, что пункты виджетов и условия эффектов (13 px, интервал 1.5).
Если условий нет, список не появляется. Не повторяем в условиях описание
результата, вид действия и стоимость; одинаковые условия при выводе объединяются.

### Выбор количества зарядов для урона

В блоке дополнительного урона при расходе ресурса можно включить «Выбирать
количество ячеек». `resource_units_max` задаёт от 2 до 20 ячеек; отсутствие поля
оставляет обычную галочку. Количество костей и `resource_cost` задаются за одну
ячейку. Игрок выбирает 0…N, что одновременно умножает кости и расход. Поля,
валидация и механизм одинаковы для всех справочников способностей и магических
предметов; снимки схем обновлены миграцией 100. При выключении расхода настройка
числа ячеек удаляется. Справочная карточка явно подписывает кости за одну ячейку.


У магических предметов есть отдельная зависимость «При последнем заряде»
(`last_charge`). Специализированный `ItemLastChargeEditor` предлагает ресурс
только при необходимости выбора, одну кость, диапазон опасного результата
и последствие «Теряет магические свойства». Все поля подписаны и имеют подсказки
по наведению; несуществующий ресурс и результат за пределами кости блокируют
сохранение. Случаи уничтожения или иных последствий пока не представлены.
