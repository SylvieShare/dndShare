# Воззвания колдуна

Воззвания D&D 5e 2014 — отдельные классовые способности (item type 4).
«Таинственные воззвания» (4069) управляют выбором; каждое из 32 воззваний
связано с ними через `data.selection_parent_id`. Такие записи исключены из
автоматической выдачи классовых умений при создании, повышении и в справочной
прогрессии. Через обычную кнопку добавления их также нельзя получить в обход
выбора.

## Выбор и получение

Общая способность задаёт `ability_selection.counts[{level,count}]` и
`replace_count`. У колдуна лимит 2/3/4/5/6/7/8 на уровнях 2/5/7/9/12/15/18;
при каждом повышении уровня колдуна можно заменить одно известное воззвание.
Повышение другого класса этих выборов не открывает. Справочная прогрессия
показывает отдельно добор и необязательную замену.

Окно повышения показывает уже изученные воззвания, оставшийся добор, замену и
сброс черновика. Принять повышение можно после заполнения обязательного числа
воззваний и их вложенных выборов. Предварительный просмотр ничего не сохраняет.
Требования проверяются по будущему состоянию персонажа: уровень класса,
известные заклинания, включая выбранные при этом повышении, и выбор Дара пакта.
Изменение Дара пакта в черновике повторно проверяет доступность воззваний.

`selection_requirements.spells[{id,name}]` требует известные заклинания;
`selection_requirements.choices[{item_id,key,values,label}]` — одно из значений
выбора конкретной способности. Минимальный уровень задаётся в `data.level` и
проверяется по классу родительского набора. Проверяется уникальность, лимит
числа, лимит замен и принадлежность набору, а не только состояние кнопки UI.

Выбор хранится обычными записями `values.abilities_class` с
`selection_source: <id родительской способности>`, стабильным `uid` и
необязательными `choices` для вложенных решений. Сохранившиеся способности
сохраняют свои заряды. Удалённые при замене теряют свои дарованные заклинания
и включённые состояния с источником этой способности; независимые источники
того же заклинания/состояния остаются.

В существующем листе меню «Таинственных воззваний» → «Выбрать способности»
позволяет заполнить недостающие выборы без повышения. Замена ранее выбранных
в этом окне недоступна. В листе показываются отдельные карточки воззваний, а
у родительской способности — выбранное число и лимит. Это общий компонент
для desktop/mobile; в чужом листе кнопок управления нет.

## Автоматизация каталога

- «Мучительный взрыв» добавляет модификатор Харизмы к одному попаданию
  «Мистическим зарядом». Каждый луч бросается отдельно; бонус не удваивается
  при критическом попадании. Отрицательный модификатор сохраняется.
- «Мистическое копьё» меняет дистанцию в карточке этого заклинания на 300 футов.
  Эти правила задаются общим массивом `spell_modifiers` с `spell_id`,
  `damage_ability` и `range`; идентификаторы класса/воззвания в runtime не зашиты.
- «Обманчивое влияние» добавляет владение Обманом и Убеждением через
  `derived_effects`, не суммируя его с уже имеющимся владением.
- Воззвания с неограниченными заклинаниями дают отдельные заклинания без
  расхода ячеек и строки в действиях. Ограничения цели, компонентов,
  концентрации и последствия остаются в описании заклинания/воззвания.
- Заклинания раз за продолжительный отдых показаны действиями с зарядом.
  Расход ячейки **колдуна** остаётся ручным; заряд и ячейка пока не объединены
  в одну операцию. «Приспешники хаоса» требуют длительного сотворения.
- «Единство с тенью» позволяет включить Невидимость. Условие освещения и
  снятие после перемещения/действия/реакции отслеживаются игроком.
- «Книга древних секретов» предлагает выбрать два ритуала 1-го круга и
  показывает выбор в карточке. Ритуальное сотворение и переписывание
  дополнительных ритуалов пока ведутся вручную.
- Отталкивание, перемещение/восприятие целей, фамильяр, число атак оружием
  пакта и некротический урон именно оружием пакта описаны памятками. Лист не
  выдаёт эти бонусы всему оружию. В карточках таких воззваний указан частичный
  уровень автоматизации.

## Обновление данных и проверки

Описание каталога находится в `scripts/catalogue/warlock-invocations/*.json`.
`scripts/sync-warlock-invocations.py` публикует его через MCP после деплоя
runtime и схемы. Без `--apply` показывает план; с `--apply` создаёт/обновляет
записи по точному английскому имени, сохраняет посторонние поля, назначает
источники книг через `handbook_item_set_content_sources`, затем подключает
выбор родительской способности. Повторный запуск не создаёт дубли.
Токен читается из окружения и не печатается. Миграция 112 меняет только схему
полей item_type, не записи воззваний.

Unit-тесты проверяют отсутствие массовой выдачи, лимиты, требования,
мультикласс, выборы того же повышения, сохранность зарядов и удаление даров.
`npx playwright test --config playwright.ability-selection.config.js` проверяет
реальные компоненты выбора, повышения и карточек на desktop/mobile.
Обучение устройств и ролей проверяется `playwright.tutorials.config.js`.
