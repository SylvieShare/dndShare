# Применение урона и история существа

В хронике у броска урона справа находится «Применить к целям». Мастер отмечает
персонажей и NPC текущего боя; сервер использует уже сохранённый результат броска,
а не бросает кости повторно. Источники: оружие, безоружная/импровизированная атака,
урон заклинания и этапы применения магического оружия. Броски лечения, атаки и
численные результаты других эффектов не считаются уроном.

Спасбросок расположен после кубиков урона. В каждой строке результата есть две
кнопки: «Применить успех» и «Применить провал». Подсвечен исход броска, но мастер
может выбрать противоположный. Успех означает половину урона при `onSuccess=half`
(округление вниз), иначе отсутствие урона; эффект на успехе не накладывается.
Провал применяет полный урон и выбранный связанный эффект. При наличии нескольких
`status_effects` мастер выбирает нужный; условия ссылки показаны с подтверждением.

После применения кнопки заменяются фактическим результатом `DamageImpact`:
полученный урон по типам, хиты до/после, поглощение временными хитами, полоса HP,
эффекты и длительности. Этот же компонент используется в истории NPC и в
событиях точечного/массового урона из вкладки боя. Последние относятся к фильтру «Бой».

Учитываются структурированные сопротивления, иммунитеты и уязвимости листа,
активных способностей, выбранных вариантов, магического снаряжения и эффектов.
Повторяющиеся сопротивления не складываются. Текстовые условия бестиария сами
по себе не являются механикой. Урон без указанного типа (в том числе введённый
калькулятором боя) снимается как заданное мастером количество. Сначала расходуются
временные хиты, затем текущие; текущие не опускаются ниже нуля. Автоматические
спасброски концентрации, смертельные исходы и отдельные реакции на урон здесь
не запускаются.

В меню NPC есть «История урона и эффектов». Сервер хранит `impactHistory` внутри
экземпляра combatant: время, источник, цель, HP до/после, урон и добавленные/снятые
эффекты. Сюда попадают также обычные изменения HP/состояний в бою, принятые
применения зелий/заклинаний и снятие концентрации. Повторное наложение экземпляра
того же эффекта фиксируется. История живёт до удаления NPC; у копии начинается
заново. Клиентское сохранение не может подменить или очистить серверную историю.

## Транзакции

`POST /api/sessions/{uuid}/impacts` доступен только владельцу сессии:

```json
{
  "eventId": 123,
  "clientActionId": "UUID",
  "effectKey": "burn",
  "targets": [{"target": {"kind": "character", "charUuid": "UUID"}, "outcome": "failure"}]
}
```

Для NPC используется `{kind:"npc",encounterId,npcUid}`. `outcome` — `success` или
`failure` для цели, уже бросившей спасбросок; без спасброска поле опущено.
Для прямого урона из боя `eventId` опущен, `amount` — целое 1–100000; создаётся
одно событие `damage_applied` со всеми результатами.

Ответ: `{event,characterIds}`. `event.data.impacts` хранит результаты по ключу цели.
Сервер проверяет актуальную принадлежность целей сессии, блокирует событие и
документы, атомарно меняет HP, эффекты, историю и событие. `clientActionId` сохраняет
отпечаток запроса: повтор идентичного запроса возвращает прежний результат,
другие параметры с тем же ID отвергаются. Одна цель получает результат исходного
события только один раз даже при новом ID запроса.

Эффекты разрешаются через справочник. Параметры зависят от заклинателя и круга;
концентрация связывает экземпляры с заклинателем. Применение только успешных
исходов не начинает концентрацию. Завершённую концентрацию сохранённого
применения продолжить нельзя. Запись NPC увеличивает `applicationRevision`,
чтобы старый снимок боя не восстановил хиты или снятые эффекты.

Проверки: `TestImpactDamage`, `TestItemTransfersPostgres/session_impacts`,
`useEncounterHp.test.js`, `useEncounterImpacts.test.js`, `session-saves.spec.js`
(оба размера экрана, ручной выбор исхода, повтор запроса и несколько целей).
