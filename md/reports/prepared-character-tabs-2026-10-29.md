# Подготовленные вкладки и независимая загрузка листа — 29 октября 2026

Статус: исторический отчёт. Текущие правила находятся в описании листа,
нативного клиента и состояний загрузки.

## Реализация

Все разделы листа подготавливаются независимо от посещения и сохраняются до
закрытия. Произвольный переход через сабхеадер использует существующий экземпляр.
До готовности отображается скелетон, навигация остаётся доступной. Веб монтирует
панели по idle-задачам. Android использует штатную pausable precomposition
SubcomposeLayout: одна очередь с общим ориентиром 2 мс на шаг композиции,
измерение отдельно; подготовка приостанавливается на время жеста/редактора.
Это кооперативная подготовка, а не гарантия максимальной длительности любого
измерения/вызова на UI-потоке.

Записи разрешаются независимо: отсутствующая ожидающая запись получает свой
скелетон; доступные записи сохраняются. Ошибка завершает ожидание и позволяет
повторить запрос. Первичная загрузка листа/окна и списка выбора также использует
каркас. D&D-дневник запрашивается при открытии листа. Игровой формат, API и схема
Room не менялись.

Стабилизированы снимок отображаемого документа и RichInteractions. Раньше
обычный вызов фабрики создавал новую lambda броска при навигации; изменение
static CompositionLocal могло инвалидировать все панели. Состояние редактора
вынесено из общего SheetContext в отдельный LocalSheetEditorPreview. Изменение
номера страницы наблюдают отдельные области шапки, а не весь лист.

## Измерение на телефоне

SM-F971B, Android API 37, окно 1248×1972 px, 420 dpi (~475 dp). Обе серии
имеют медианный FrameInterval около 8,33 мс (120 Гц); thermal status — 0.
Проверялась установленная debug-сборка на том же листе. Новая серия выполнена
после прогрева всех вкладок; состояние JIT/кешей между двумя сериями полностью
не контролировалось. Это наблюдение до/после совокупности изменений, а не
изолированный статистический A/B-тест одного параметра.

| Жест | Задержавшиеся кадры до → после | P95, мс до → после | P99, мс до → после |
| --- | --- | --- | --- |
| Обычный, 350 мс | 5,44% → 3,12% | 23,5 → 15,4 | 67,4 → 23,7 |
| Быстрый, 140 мс | 6,38% → 2,86% | 42,0 → 14,7 | 62,7 → 21,8 |
| Короткий с возвратом | 3,47% → 2,71% | 10,2 → 17,4 | 49,2 → 24,7 |

После изменения: 14 обычных свайпов, 1249 кадров/39 задержек; 14 быстрых,
873/25; шесть коротких, 295/8. Порядок всех 28 завершённых переключений
соответствует ожидаемому; финальный раздел — «База». Худшие отдельные кадры
всё ещё достигают 74,4 мс для обычного и 62,3 мс для быстрого жеста.
Плавность улучшилась, отдельные задержки полностью не устранены.

Текущий PSS после прогрева — около 206 МиБ. Старое измерение памяти сделано
в фоне со swap и не используется как сопоставимый baseline. Данные персонажа
не редактировались, аккаунт/кеш не очищались. Сведения о персонаже и трассы
не публиковались. Диагностическое логирование восстановлено, временные файлы
на телефоне удалены.

Локальные артефакты: `build/prepared-tabs/phone/results.json`, `gestures.json`,
пофазные gfxinfo и navigation.log. Количественная сводка использует отдельную
выгрузку gfxinfo каждого жеста. Кольцевой буфер дополнительной трассы переполнился;
она не выдаётся за полный источник всех кадров. Fingerprint Android-входов
проверенного APK совпал с smoke cache. Замер выполнен на APK с основным API
из рабочей копии; его SHA-256 записан в candidate.json. Выпуск из чистой копии
commit собирается отдельно и получает собственный SHA-256 в release.json.

## Исправления при проверках

Смена формата во время незавершённого перехода теряла выбранный раздел.
Сохраняется семантическая цель, старые RAF/timer callbacks отсеиваются поколением.
После удаления общего ожидания инвентаря лишний HTML template делал секции
неотображаемыми; оболочка удалена, добавлен browser-тест с настоящими строками
и управляемой задержкой ответа. В benchmark entry point обновлён вызов формы
под актуальный контракт input/readInput/items/metadata.

Неудачные и прерванные прогоны в PASS не включались. Предыдущая отменённая
попытка сравнения остановлена перед исправлением общей инвалидации; следующая
поймала ошибку template. Финальный отдельный прогон полностью завершён.
