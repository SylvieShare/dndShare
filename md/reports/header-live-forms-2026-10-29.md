# Шапка сессии, живой морф и общие формы — 29 октября 2026

Статус: исторический отчёт о завершённом шаге и проверках, не текущий контракт.

## Результат

Android убрал строки состояния сервера над страницами. ShareWorkspaceHeader
получил слот actions; индикатор ожидания/ошибки раскрывается по ширине справа,
перемещая соседние элементы. Нажатие открывает подробности и повтор. Здоровое
соединение не занимает место. Проверяются также ошибки фонового опроса листа.

Справа в шапке листа находятся название/глава сессии, игроки и события с
счётчиками. Кнопки открывают соответствующие вкладки существующего окна
сессии. Дублирующая карточка сессии в теле листа убрана.

Морф D&D-характеристики работает без кнопок отмены и сохранения. Валидный
ввод объединяется в короткие локальные commit (120 мс) и попадает в Room/outbox
без ожидания сети и закрытия окна. Checkpoint атомарно продвигает baseline и
outbox, сохраняя свежий ввод. Закрытие сбрасывает последний буфер. Незавершённый
ввод остаётся черновиком; конфликт не затирает новую серверную величину.
Серверная версия выбирается с явным подтверждением.

Пунктир восстановлен у всех общих действий добавления. Кнопки навыка и
спасброска в обоих клиентах используют заливку для владения/компетентности,
без сплошной обводки. Локальный RollModeControl также использует общий токен.

Новый стиль стал default библиотеки share-ui: заливки форм/вторичных кнопок,
переключатели, focus/invalid fill, отдельная поверхность popover, ровный canvas.
DnDShare зафиксирован как основной визуальный ориентир нейтральной библиотеки.
Опциональный FormNumberInput.live отправляет валидный ввод сразу, сохраняя
промежуточный текст и не дублируя blur. Пунктирные действия остаются пунктирными.
Другие сайты получают defaults после обновления своей фиксированной версии;
их deployments в эту задачу не входят.

Итоговая библиотека — v0.47.2, commit 5b676bf. Она выпущена из
C:/projects/share-ui/build/worktrees/live-form-appearance с актуальным dist,
проверенными public API/типами и pack. DnDShare установлен с опубликованного
HTTPS tag, без file: dependency. Соседние потребители отсутствуют в локальной
рабочей среде; их production-сборки здесь не выполнялись. Изменение остальных
runtime API библиотеки не требовалось.

Сценарий сессии обнаружил неверную начальную вкладку события: initialTab не
передавался вызывающим экраном. Аргумент исправлен, сценарий повторён успешно.
Браузерный selector нового теста уточнён для телефонной навигации; это не было
сбоем приложения. После парной проверки отдельно завершено подключение индикатора в адаптере
общей шапки AppHeader: повторены два instrumented-кейса, включая ожидание,
ошибку и повтор непосредственно на AppHeader. Суммарно проверено десять
уникальных instrumented-кейсов; здоровый вид шапки не изменён. Веб-runtime
после финальной проверки не менялся.

Артефакты задачи находятся в build/header-live-forms/. Физический FPS в этой
задаче не измеряется. Визуальную приёмку выполняет пользователь.
