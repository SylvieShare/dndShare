Каждый имеет отдельные render/LOD/shadow/source/preview, явную калибровку опоры
и отдельную подставку. [Манифест](../../scripts/creatures/pilot-production.json)
и [принятые рецепты](../../scripts/creatures/pilot-recipes/) сохранены в Git.
Оригиналы генерации, референсы и рабочие сцены хранятся в исходных архивах S3.
Все восемь моделей опубликованы; MCP подтвердил пять ассетов и основную
привязку каждого итема. Публикация завершилась без повторной генерации.

общую компенсацию тела 14/17 относительно диаметра большой подставки.

## Что потребовало исправления

- Первая генерация гоблина дала полость на голове. Принят второй native с
  seed 1713; первый сохранён отдельно. Остальные виды не генерировались повторно.
- Орк содержал много мелких несвязных островов. В производной геометрии убрано
  12810 таких треугольников; исходный GLB сохранён. На 20k LOD терял меховой
  силуэт; принят 24999, без ослабления policy. Shadow содержит 6349 треугольников.
- У паука пересчитаны восемь ходильных ног отдельно от придатков рта. Полости
  брюшка закрыты через ограниченный voxel-проход pitch 0,004 / radius 4.
  Архив сохраняет closed-source и отчёт. Остались небольшие неровности
  запечённых карт на задней поверхности при сильном приближении.
- Волк и кабан имеют укрупнённые скульптурные пряди шерсти. Кости/пальцы скелета
  упрощены. Металл экипировки изображён как окрашенная матовая миниатюра;
  физически смешанный PBR кожи/стали не заявлен.
- Летучая мышь оставлена в позе полёта, без физической стойки; это игровой
  ресурс, не печатная фигурка. У слизи парящая капля — часть статической композиции.

Нейтральные цветные/серые виды, перед/спина/бока/верх, LOD и примерка на подставки
просмотрены отдельно от автоматических passed. Принятые model-review.json
привязаны к SHA render/LOD и входят в готовые S3-архивы.

На весь набор выполнено **9 генераций / 18 GPU-вызовов** при лимитах 10/20.
Личная квота перечитывалась перед отправкой. Последняя проверка сервиса:
overquota_used=0. Сессия с HF-ключом завершена; ключ не записывался в файлы.

## Архивы и проверка публикации

У каждого вида есть подтверждённые native и ready архивы. Последний комплект:
77,95 MiB native, 834,16 MiB ready; пять обслуживаемых ассетов восьми моделей
вместе занимают 147,90 MiB. Это разные назначения: рабочие архивы не загружаются
редактором или справочником. Предыдущие неизменяемые архивы в объёмы не включены.

Проверен публичный `GET /api/items/{id}/model` для всех восьми итемов: UUID,
referenceDiameter, размер и выбранная подставка. Скачанный через публичный URL
render волка совпал по SHA с зарегистрированным GLB. Локальные publication.json
содержат verified:true, пять asset descriptor и подтверждённую основную связь.

Native и ready архивы волка скачаны из S3 и восстановлены в новые папки с
проверкой состава и SHA. Полный ready содержит **71 файл**; фоновый Blender
открыл восстановленный model.blend: одна сетка, 44000 треугольников,
**9 упакованных изображений**, внешних файлов для текстур не потребовалось.
Проверка не открывала и не изменяла пользовательскую Blender-сцену.

Проверенный ready descriptor для повторного восстановления через MCP:

```json
{"itemId":1692,"modelId":"07eddc15-6910-5bcf-bab8-462685f59191","stage":"ready","sha256":"81a09fb38fee376f0328764482712218be2d533a4b81bc6c666de7e511b0e2b3","size":105596865}
```

Остальные архивы находятся через `creature_model_archive_list` по itemId;
UUID и этап входят в неизменяемый S3-ключ. Подписанные download URL и ключи
сервисов в отчёт не включены.

## Поле с 40 миниатюрами

`frontend/tests/maps/miniaturesBenchmark.spec.js`, тег `@local-model`, использует
настоящий createMapRenderer, по пять копий каждого из восьми видов, три размера
существующих подставок и 198 простых плиток пола. Все GLB — окончательные файлы
пилота; фон/пол специально простые, поэтому это не замер большой меблированной
карты. Размер окна 1920×1080. Для каждого режима — прогретая загрузка,
40 шагов поворота камеры, затем покой. Туман, огонь и выделение не включались.

Renderer: **ANGLE / Vulkan / SwiftShader Device (LLVM 10.0.0)**.
GPU timer недоступен. Это программная отрисовка; интервалы ниже не характеризуют
аппаратный GPU пользователя. CPU-профиль измеряет JavaScript/отправку команд,
а не всё время программного драйвера, поэтому его 1,2–1,8 мс нельзя называть
полным временем рендера.

| Модели | Солнечные тени | Треугольники кадра | Draw calls | Медиана интервала, мс | p95, мс |
| --- | --- | ---: | ---: | ---: | ---: |
| LOD | Выключены | 743978 | 364 | 383,3 | 483,3 |
| Полные | Выключены | 1796803 | 364 | 783,4 | 983,2 |
| LOD | Включены | 743978 | 364 | 400,0 | 450,0 |
| Полные | Включены | 1796803 | 364 | 916,7 | 966,7 |

В этих проходах тени уже прогреты; цена холодного построения shadow map сюда
не входит. 364 calls — все проходы, подписи, основания и вывод кадра, а не
число уникальных тел. LOD уменьшил треугольники примерно на 58,6%; число calls
осталось прежним. В покое каждый режим дал **0 новых draw calls за 1,2 секунды**.
Ошибок JavaScript/WebGL и загрузки ресурсов нет; подтверждена загрузка всех ролей.

Кеш после всех режимов: 34 файла, 57,57 MB загруженных данных, около 26,93 MiB
геометрии и 280 MiB распакованных текстур по счётчику приложения. Это один
совместный кеш render/LOD/shadow восьми видов и оснований; 40 копий не означают
40 независимых наборов текстур. Байты кеша — приблизительная оценка памяти,
не отдельный замер VRAM. Программный backend оказался медленным даже с LOD.
Аппаратная производительность этим тестом не подтверждается.

## Воспроизведение

Рабочая папка и подробные отчёты: `models/creatures/pilot-20261024/`.
`benchmark-final.json`, contact.png, рендеры и production-state.json остаются
локальной диагностикой; файлы моделей не включены в Git или Go-бинарь.
Профиль требует эти подготовленные ресурсы и явно пропускается без них:

```bash
cd frontend
npm run test:models -- tests/maps/miniaturesBenchmark.spec.js
```

Быстрые проверки инструментов дополнены тестами возобновления этапов, лимита
квоты, атомарного восстановления, защиты состава архива, дыр и нормалей при
voxel-обработке. Численный набор запускается Python-runtime из requirements.txt.
Приёмка одной модели остаётся обязательной: технические проверки сами не нашли
бы геометрическую полость на коже или неверное количество ног.
