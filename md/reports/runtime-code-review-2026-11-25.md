# Ревью неиспользуемого кода и дублирования в Go и Vue

Статус: исторический отчёт от 25 ноября 2026 года. Исходная ревизия `997ff81f`.

## Область проверки

Для 1 569 модулей JS и Vue в `frontend/src` без файлов тестов построен граф от
`main.js` по статическим и строковым динамическим импортам. Вне графа оказалось
20 файлов. Для каждого проверены ссылки по всему репозиторию, включая тестовые
страницы, загрузчики и wiki. На бэкенде для 614 Go-файлов в `internal/`
проверены имена функций, встречающиеся только при объявлении, и совпадающие
тела функций. Перед изменениями просмотрены вызывающие стороны, включая
`cmd/`, маршруты HTTP и места регистрации. Ручное ревью охватило найденных
кандидатов. Подсчёт модулей сам по себе недостаточен для решения об удалении.

## Исправления

| Область | Что обнаружено и изменено |
| --- | --- |
| Ссылки справочника | Просмотр посылал в запрос имени весь объект `{ id }` и показывал `#[object Object]`. Верхнеуровневая проверка обязательного поля также отклоняла заполненную объектную ссылку. Просмотр и редактирование теперь извлекают ID одним обходом схемы. Проверка обязательных ссылок учитывает оба представления, включая вложенные поля. |
| Редактор справочника | После перехода на `CatalogueEditor` и `AbilityEditor` четыре старых компонента полей использовались только друг другом и проверками исходного текста. Удалены компоненты, 350 строк их CSS и обработчики прежней формы. Проверки используют текущие контролы и штатную страницу справочника. |
| Создание персонажа | Карточки расы, класса и подрасы и списки происхождений по-разному очищали один текст. Теперь у краткого описания одна функция. Карточка подрасы получает готовую строку и выводит её без повторного преобразования HTML-сущностей. |
| Сессии и остальные экраны | Удалены старые плитки выбора и результата визарда, заглушка иконки типа, два компонента боевой сцены и две функции без вызовов. Для эффектов NPC сверена действующая цепочка от `EncounterStatuses` до общего меню механик. |
| Бэкенд | Для UUIDv4 у HTTP и S3 теперь одна реализация. Четыре функции разбора ID из URL сведены к двум с прежними правилами для чисел со знаком и положительных ID. Удалены четыре приватные функции без вызовов и неиспользуемый метод прямой загрузки объекта карты. Действующая загрузка использует подписанный URL S3 и последующий перенос объекта. |

Новый сценарий Playwright открывает карточку, получает имя связанной записи,
сохраняет ссылку в прежней форме и проверяет блокировку сохранения после очистки.
На исходной production-сборке сценарий воспроизвёл `#[object Object]`.
В изменённом приложении он прошёл. Использовались тестовые ответы HTTP.

## Что ещё заслуживает внимания

- Три браузерные фикстуры оружия напрямую монтируют `DamageRollOptions`.
  Рабочая карточка оружия открывает `WeaponRollSettings` в `CharacterRollDialog`.
  Перенос этих сценариев на открытие броска из карточки позволит проверять
  выбор цели и расход заряда по тому же пути, что проходит игрок.
  [Рабочая карточка](../../frontend/src/features/character-editor/blocks/dnd/components/WeaponCard.vue) · [Фикстура выбора цели](../../frontend/tests/weapon-charges/selected-target.js)
- Обработчики загрузки иконки и обложки предмета повторяют чтение multipart,
  проверку размера, определение MIME, запись в S3 и очистку после ошибки БД.
  При объединении можно вынести этот порядок в одну функцию. Для обложки
  нужно сохранить поддержку JPEG, для каждого маршрута — свои поля ответа
  и операцию привязки в БД. [Обложка](../../internal/web/item_covers.go) · [Иконка](../../internal/web/item_icons.go)

Вне графа приложения также остались тестовые фикстуры и сохранённый по
контракту генератор сокровищ. В Go команды синхронизации изображений оказались
потребителями нескольких методов Store, к которым сам сервер не обращается.
