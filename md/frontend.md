# Frontend

Редакторы объектов справочника используют предметные профили композиции в
`features/items/editor/catalogue`. Общие поля и механики переиспользуют компоненты
редактора способностей и share-ui. Подробности: [редактор справочников](features/catalogue-editor.md).

Актуальная реализация — Vue 3, Composition API, Pinia, vue-router и Vite 8 в
`frontend/`. Старого Vue CLI, webpack, Axios и серверных JSON-шаблонов листа в
проекте нет.

Выбираемые классовые способности используют один `AbilitySelectionPanel` в
повышении уровня и в окне добора существующего листа. Панель переиспользует
`ItemPickerModal`, `FeatChoiceModal`, `LevelUpItemRow` и примитивы share-ui;
условия выбора и сохранение вынесены в чистые функции и composable.
Контракт и проверки описаны в [воззваниях колдуна](features/warlock-invocations.md).

## Запуск и проверка

```bash
cd frontend
npm install
npm run dev
npm test -- --run
npm run build
```

Vite работает на `:5173` и проксирует `/api` и `/mcp` в Go-приложение на
`:8080`. Production-сборка попадает в `frontend/target/dist`; Go-бэкенд вшивает
её в бинарь. Для неизвестного клиентского пути Go возвращает `index.html`, а
`/api/**` и `/mcp` никогда не попадают в SPA fallback.

## Границы кода

`features/maps` содержит библиотеку, редактор, рабочее место сессии и отдельный
экран стола. `MapAvailabilityGate` использует общий `FloatingTooltip` для
подсказки «Скоро будет», блокирует активацию недоступного пункта и сохраняет
фокус с клавиатуры. Меню, сессия и прямые страницы проверяют `ADMIN`; это
доменное ограничение раннего доступа, не новый базовый tooltip-компонент.
PixiJS 8 рисует слои карты через WebGL; Canvas2D используется для
генерации текстур, масок и миниатюр. Движок, редактор и экран импортируются
отложенно. Формы и панели используют `ActionButton`, `AppModalFrame`,
`ConfirmDialog`, `BaseTile`, `MultiToggle`, `ToggleSwitch` и поля share-ui.
Локальные pointer-жесты нужны для координатного рисования, камеры и размещения
жетонов на WebGL canvas, а не для обычной сортировки DOM-списка.
Модель, сохранение и renderer разделены; [контракт и UX карт](features/maps.md).

- `src/app` — router, тема и корневая композиция.
- `src/features/<feature>` — страницы, компоненты, composables и API конкретной
  предметной области.
- `@sylvieshare/share-ui` — общие для DnD Share, HavenShare и TrenchShare
  theme-токены, UI-примитивы и headless interactions. Пакет подключается одним
  публичным import API без deep imports.
- `src/shared/api` — общие HTTP-клиенты. `http.js` основан на `fetch`; любой
  non-2xx ответ является ошибкой.
- `src/shared/ui` — переиспользуемые компоненты уровня DnD Share. Компонент
  остаётся здесь, если знает о router, Pinia, HTTP API или доменной модели.
- `src/shared/composables` — поведение, не привязанное к одной фиче.
- `src/stores` — Pinia-кэши и глобальное состояние.

Новый или изменяемый Vue-компонент пишется через `<script setup>`. Правила
композиции вынесены в `md/composition-api.md`.

В сессии `features/sessions/components/SessionTabWorkspace` задаёт единый фон,
отступ от панели игроков и максимальную ширину 1440px для вторичных
вкладок, включая дневник. Внутри этой области хроника ограничена 980px. Внешний отступ составляет 28px на desktop (в том
числе от видимой панели игроков), 16px на mobile. Он оборачивает слот `primary-workspace` в
`ChapterGraphTab`; сюжет и бой остаются за его пределами. Содержимое вкладок
отвечает только за внутреннюю компоновку и прокрутку, не повторяя safe-area
отступы (подробнее — `md/features/sessions.md`).

## Стандартные компоненты: что и когда использовать

Компоненты ниже — не локальные удобства отдельных экранов, а стандарт проекта.
Перед созданием нового оверлея, поля или drag-and-drop нужно сначала выбрать
подходящий примитив отсюда.

| Задача | Стандарт | Когда использовать |
|---|---|---|
| Низкоуровневое модальное окно | `share-ui/AppModal` | Инфраструктура backdrop, Escape, focus/слоёв, анимации и `role=dialog`. Напрямую используется только специализированными fullscreen-workspace; Escape закрывает только верхнее окно стека. |
| Стандартное окно с шапкой | `share-ui/AppModalFrame` | Единая оболочка формы, просмотра или picker поверх `AppModal`: шапка `--surface`, тело и footer `--bg`, одинаковая рамка, увеличенный заголовок и закреплённые title/крестик/мобильный handle. Тело прокручивается отдельно, footer с действиями также может быть закреплён. |
| Подтверждение | `share-ui/ConfirmDialog` | Удаление, отмена операции, сброс формы и любое решение «подтвердить/отменить». Поддерживает `loading`; не собирать собственный overlay. |
| Ввод одного текста | `share-ui/TextPromptDialog` | Создать/переименовать альбом, сцену, сущность. Заменяет `window.prompt` и локальные формы из одного input. |
| Морф-переход из элемента | `share-ui/MorphSheet` + `share-ui/useContainerMorph` | Только когда окно должно анимированно раскрываться из конкретной плитки/кнопки. На desktop фон размывается, на mobile полноэкранный sheet оставляет фон без blur. Вложенный morph задаёт `zIndex` выше родительского overlay; редакторы листа используют `3100` поверх fullscreen-листа на `3000`. Поля внутри не получают автофокус при открытии; фокус допустим после явного действия пользователя. Обычный диалог строится на `AppModalFrame`. |
| Поле формы | `share-ui/FormField` | Label, hint и горизонтальная/вертикальная раскладка одного поля. |
| Текст/число/select/многострочный текст | `FormTextInput`, `FormNumberInput`, `FormSelect`, `FormTextarea` | Любой универсальный ввод соответствующего типа. Не вводить новые локальные классы input/select без отдельной UX-причины. |
| Удаление записей | `share-ui/RemoveButton` с `icon="trash"` | Корзинка у действий, ресурсов, защит, эффектов, бонусов и других пунктов листа. Обязательный `label` задаёт доступное имя; подтверждение и удаление данных остаются в feature. Крестик используется для закрытия и снятия выбора. |
| Кнопки формы | `share-ui/FormActionButtons` | Стандартная пара отмена/сохранение и loading/disabled состояния. |
| Выбор значения | `share-ui/ValueSelect`, `SuggestPicker`, `SuggestAdd`, `SuggestMultiSelect` | Обычный select либо одиночный/множественный выбор из серверного справочника; компоненты сами отвечают за desktop dropdown и mobile sheet. `ValueSelect` открывается вниз по умолчанию, а внутри ограниченного снизу scroll-контейнера может явно использовать `drop-up`. Серверные suggest-компоненты остаются в приложении. |
| Расширенное описание | `shared/ui/InputDescription.vue` → `share-ui/RichTextEditor` | Тонкий DnD-адаптер задаёт русские подписи и owner-mode; toolbar, редактирование, очистка paste/drop и базовый HTML-контракт принадлежат пакету. |
| Отображение описания | `share-ui/RichContent` | Безопасный единообразный вывод HTML через allowlist sanitizer. Не использовать собственный `v-html` для сохранённого пользовательского контента. |
| Общение игроков из листа | `CharacterInteractionPlayers`, `CharacterInteractionDialog`, `CharacterInteractionInbox` | Меню на `RowActionMenu` с пометкой связанного поповера, отдельные `CharacterChatDialog` и `CharacterRpsDialog` на `AppModalFrame`, ввод на `FormTextarea`. `RpsChoices` использует `ActionButton`, а общий `RpsResult` на `BaseTile` показывает полный и компактный результат. Контроллер хранит переписку и вызовы через API сессии; базовые оболочки не дублируются. |
| Фильтры хроники сессии | `BasePopover` + `MultiToggle` + `FormSelect` | Локальный `SessionEventsPanel` задаёт доменные категории и чипы активного состояния; базовые popover/form controls не дублируются. |
| Аватар субъекта хроники | `SessionEventActorAvatar` | Локальная проекция character/bestiary media и тематический DM fallback относятся только к семантике журнала сессии. |
| Морф-плитка и заголовок | `share-ui/MorphTile`, `MorphTileHeader` | Опциональные title/карандаш и слот `aside` справа. `embedded` для общего представления внутри morph-панели, `padding` для композиции. Заголовки не переопределяются локальным CSS; `SheetBlockTitle` только задаёт русский текст действия. |
| Плитка/карточка контента | `share-ui/BaseTile` | Общая поверхность с фоном, скруглением и тихой рамкой. Поддерживает цветовой акцент, tint, framed- и interactive-состояния; декоративная полоса добавляется отдельным `TileAccentStrip`; не создавать локальный базовый класс плитки. |
| Popover/контекстное меню | `share-ui/BasePopover`, `ActionMenu`, `ActionMenuItem`, `ActionMenuSubmenu` | Неблокирующий контент, привязанный к управляющему элементу. Меню поддерживает стандартный trigger и feature-trigger через slot; программно привязанный action popover выбирает `transitionPreset="action-menu"`; вложенное меню остаётся внутри visual viewport, не закрывает родителя и корректно работает на mobile. Поскольку `BasePopover` телепортируется в `body`, popover внутри модального окна обязан получить `zIndex` выше слоя своего окна; item picker прокидывает это значение через list controls. Локальный `RowActionItem.vue` сопоставляет DnD action names с Lucide-иконками, а `RowActionSeparator.vue` разделяет смысловые группы действий. Карточка-trigger использует slot-параметр `open` и общий класс `action-menu-source--open`, чтобы оставаться слегка подсвеченной всё время, пока её телепортированное меню открыто. |
| Классы персонажа в окне «Персонаж» | `DndClassList` → `ObjectListItem` | Общая строчная оболочка справочника показывает иконку, название, подкласс и уровень персонажа в metric-slot. Отдельная доменная композиция нужна для фактического уровня и выбранного подкласса вместо каталожного описания; редактирование открывается общей кнопкой. |
| Повышение уровня | `LevelUpItemRow` → `HandbookListItem`, `LevelUpHitPoints`, `ClassLevelGains` | Окно 960 px собирает списки умений и заклинаний из существующих отображений справочника. `LevelUpItemRow` объединяет просмотр строки и отдельные действия выбора на `BaseTile`; хиты используют общие контролы и `SystemDie`, прирост ячеек — тот же `SpellSlotSphere`, что в прогрессии класса. |
| Описание при наведении | `features/character-editor/components/ItemTooltip.vue` | Единая телепортированная подсказка терминов, предметов и свойств. | Прибавки характеристик D&D | `shared/ui/AbilityBonusPicker` | Один доменный компонент для расы 2014, предыстории 2024 и повышения уровня: схемы распределения, разные характеристики, ограничения количества и максимума. Режим переключается общим `MultiToggle`; базовые формы не дублируются. |

Дневник использует `JournalInlineForm` для общего черновика записи внутри карточки `BaseTile`
в вертикальной ленте, а не `SessionEditableField`: нужны составные реплики,
участники боя и rich-text, сохранение черновика при ошибке и проверка версии.
`JournalEventFields` редактирует название, описание и составные списки, которые
сохраняются одной операцией. Формы используют общие `Form*`, `FormActionButtons`
и `InputDescription`; `FormField vertical` располагает подписи над полями во всех
типах записей. Числовые поля участников переносятся по доступной ширине, пункты
заданий и награда многострочные. В просмотре отдельных карандашей у строк нет.
`JournalEditButton` задаёт тихий карандаш и увеличенную touch-область.

`JournalWorkspace` / `JournalTimeline` — единые компоненты вкладок персонажа
и сессии. Название, настройки и горизонтальный выбор разделов объединены в
шапку `BaseTile`. Показывается один раздел, карточки имеют естественную высоту;
добавление и действия находятся справа сверху области событий. `useSortable`
из share-ui отвечает за desktop-перестановку за заголовок. На устройствах
с coarse pointer drag отключён: обычная прокрутка и явные кнопки порядка.
ELK, отдельное окно и canvas-preview дневника удалены из frontend.

`features/narrative-graph` остаётся предметной реализацией холста сюжета сессии:
русские действия нарратива, сохранение камеры по ключу workspace, безопасные
отступы сессии, spotlight и редактирование связей. Геометрия узлов, связи и
камера разделены на composables. Оболочки, формы, popover, карточки и модальные
окна принадлежат share-ui. Дневник этот холст не использует.

Категории модальных окон:

- подтверждение — `ConfirmDialog`;
- один текстовый ответ — `TextPromptDialog`;
- сложная предметная форма — feature-компонент, но его оболочка всегда
  `share-ui/AppModalFrame`, если окну нужны заголовок и прокручиваемое содержимое;
- детальная карточка справочника — `features/handbook/components/ItemViewModal`;
  она использует `share-ui/AppModal` без отдельной полосы заголовка, поскольку
  единственной шапкой служит `ItemDetailHeader` внутри содержимого;
- серверный поиск и выбор элемента —
  `features/handbook/components/ItemPickerModal`;
- раскрытие из плитки — `MorphSheet`.

Fullscreen-карточка `AppModal` ограничивает высоту по `visualViewport`, поэтому
фиксированная шапка и поля остаются в видимой области при открытой мобильной
клавиатуре; `dvh` используется как CSS fallback.

Предметные действия не встраиваются в renderer карточки: владелец передаёт их
в footer-slot `ItemViewModal`. Поэтому одно и то же окно описания поддерживает,
например, подготовку/удаление заклинания или количество/удаление предмета, не
получая зависимостей от листа персонажа.

Все типы item используют `features/handbook/components/ItemDetailHeader.vue`.
Компонент владеет общей геометрией имени и действий, показывает панорамный
`coverImageUrl` через центрированный `object-fit: cover` и затемнение под
текстом. Для способностей (типы 3/4) и черт (тип 7), как и для профилей с
summary бестиария и заклинаний, затемняется только компактная подложка названия,
а сама обложка остаётся без общего затемнения. Справа в одной строке для любого типа справочника находятся источник
(крайний справа, полное название доступно через tooltip) и кнопка
«Редактировать» с иконкой карандаша слева от него; renderer не дублирует
источник внутри содержимого. Обложка является единственным изображением шапки:
компактная иконка в ней не дублируется и не используется как missing-cover
fallback. При отсутствии item-level обложки используется
`itemType.coverImageUrl`; production fallback cover назначен 15 системным типам:
прежним 1–13 и новым 16–17.
Ошибка изображения сохраняет cover-компоновку и нейтральный фон, не переключая
геометрию карточки. Item-level обложка всегда имеет приоритет над типовой.
Типы 1/6/12 резервируют `4:3`, типы 2/8/9/11/13/14/16/17 — `3:2`, а типы
3/4/5/7/10 — `5:2` ещё до загрузки файла. Контейнер не ограничивается
по ширине, после загрузки использует фактическое соотношение файла и не имеет
общего ограничения максимальной высоты. `ItemDetailHeader` принимает тип
справочника и хранит расширяемую таблицу CSS-переменных минимальной высоты для
типов, которым требуется другая композиция. Обычная обложка поэтому сохраняет
своё соотношение сторон, а содержимое detail-карточки остаётся доступным через
вертикальную прокрутку. При смене URL обложки старое изображение сразу скрывается:
до загрузки и декодирования нового виден нейтральный фон с индикатором загрузки
по центру. Это же состояние используется при первом открытии. Готовая обложка
проявляется за `160ms`; при ошибке остаётся фон без индикатора. Поздние ответы
для уже сменившихся обложек игнорируются. Системная настройка
`prefers-reduced-motion` отключает анимации.

Заклинание использует отдельный summary-профиль с минимальной
высотой `300px`. Уровень и школа образуют компактный вертикальный блок под
названием. Над нижней зоной справа располагается компактная обычная карточка
компонентов, а под ней время накладывания, дистанция и длительность занимают
три равные колонки. Эти краткие параметры не повторяются в содержимом ниже; для
материального компонента там остаётся только его полное описание. На узком
экране сетка остаётся трёхколоночной и уменьшает внутренние отступы и шрифт.
Для типа заклинаний назначена типовая обложка-заглушка, поэтому все заклинания
используют эту единственную summary-компоновку; персональная обложка только
заменяет изображение. Вещи типа 2 аналогично всегда держат стоимость и вес в
summary-карточках шапки, когда эти значения заданы, и не повторяют их ниже.
Плитки поверх обложек стандартизированы локальными примитивами
`features/items/components/cover`: `CoverStatCard` владеет стеклянной
поверхностью, типографикой, tone/size-вариантами и увеличенным полупрозрачным
декоративным знаком по центру справа; `CoverSummaryLayout` задаёт боковые
колонки и безопасный центр изображения; `CoverSummaryRail` с `CoverSummaryRailItem`
задаёт нижнюю сегментированную полосу и её мобильное складывание. Типовые
summary-компоненты отвечают только за выбор данных, подписей, иконок и
композиционных параметров этих примитивов.
На экранах до 520 px боковые колонки `CoverSummaryLayout` ограничены 124 px,
между ними остаётся свободный центр обложки. `CoverStatCard` уменьшает внутренние
отступы и декоративную иконку; длинные подписи переносятся, размеры значений
сохраняются. Нижняя полоса параметров по-прежнему занимает всю ширину.

Поиск, schema-фильтры и фильтр по публикациям принадлежат левой колонке
`HandbookItemList` и закреплены над её собственной прокручиваемой областью.
Landing справочника сразу занимает итоговую ширину до загрузки систем и
коллекций, поэтому появление данных не меняет геометрию страницы. Карточка
коллекции и вкладка модального picker используют
`itemType.iconImageUrl`; прежний `itemType.svg` не является frontend-контрактом.
`itemType.parentTypeId` связывает специализированные каталоги с родительским:
landing помечает подразделы и перечисляет их у «Вещей», «Рас» и «Классов», а
picker может рекурсивно включить дочерние типы без хардкода их идентификаторов.
Типы 16 «Подрасы» и 17 «Подклассы» используют schema item-поля `race`/`class`;
общие формы и фильтры умеют работать с такими ссылками напрямую.
`ItemIcon` применяет эту растровую эмблему только после отсутствующих item-level
`iconImageUrl` и `svg` в списках, picker и глобальном поиске. Detail-шапка
всегда использует независимый cover-контракт. Полоса
группировки списка отделена левой и нижней границами без правой рамки.
Collection bar страницы содержит название, счётчик и добавление объекта на
всех ширинах; счётчик не дублируется в главной шапке. Landing использует общий
игровой контекст без собственного выбора системы. На ширине до 760 px список
и detail сменяют друг друга на всю доступную ширину; внешних отступов и рамки
у detail нет. Непрерывная цепочка flex-контейнеров с ограниченной высотой и
`min-height: 0` сохраняет независимую прокрутку списка и карточки.
Тот же list-owned паттерн используется в picker-модалках,
поэтому фильтры не меняют положение между справочником и сценариями выбора.
`ItemPickerModal.fixedFilters` задаёт обязательные условия предметного выбора:
они сразу участвуют в серверном запросе, видны в общей панели фильтров и
заблокированы для изменения или сброса пользователем.
`ItemPickerModal.defaultFilters` задаёт изменяемые начальные значения при
открытии или смене типа. Они участвуют в запросе наравне с обычными фильтрами:
сброс снимает их, а варианты сохраняют подсветку и подпись «По умолчанию»,
даже когда не выбраны. Повторное открытие восстанавливает начальные значения.
Ручной поиск заклинаний в листе использует этот режим для класса и кругов.
Бестиарий использует отдельный профиль с нижней границей `440px`. Фактическое
соотношение обложки задаёт предпочтительную геометрию, но портретный файл
ограничивается квадратным окном 1:1: изображение само по себе никогда не делает
шапку выше своей ширины. Production-файл `1536×1152` по-прежнему раскрывает
шапку до 4:3, а более объёмная сводка при необходимости может увеличить её
высоту, чтобы характеристики не обрезались. При смене существа профиль
сразу резервирует 4:3, не меняя соотношение на время загрузки, поэтому
переход между подготовленными обложками не меняет высоту. Формат рассчитан на высокую
композицию и боковое кадрирование на мобильном. У такой шапки нет общего
затемнения изображения: название получает компактную тёмную подложку по
содержимому, а источник, теги, основные боевые параметры, скорости и все шесть
модификаторов характеристик выводятся через summary-slot в собственных
полупрозрачных блоках. На desktop CSS Grid оставляет центральную область
обложки свободной: CR и КД стоят слева, хиты, мастерство и скорости — справа,
мировоззрение остаётся справа над сводкой, а остальные теги
стоят слева между именем и CR. Шесть характеристик образуют нижнюю полосу.
Сводка занимает всю свободную
высоту шапки, поэтому при коротких боковых группах полоса характеристик всегда
прижата к нижнему краю. На экранах до `520px` боковые группы переходят в две
колонки, характеристики — в сетку `3×2`. Навыки и
последующие разделы начинаются уже под изображением. Если содержимое сводки не
помещается на узком экране, шапка растёт по высоте, а не обрезает данные.
Оставшееся содержимое detail-карточки прокручивается по вертикали, в том числе
внутри модального окна и на узких экранах.
Типовые detail renderer получают `showTitle=false` и отвечают только за
содержимое ниже общей шапки. Технический ID объекта не занимает место на
обложке: `HandbookItemDetail` выводит его приглушённой строкой в самом низу
detail-содержимого. Рядом выводится общий `ItemAutomationBadge` — степень
поддержки механик, отдельная отметка взаимодействия с другими игроками и
пояснение через `BasePopover`. Редактирование метаданных всех типов использует
`ItemAutomationEditor`; контракт и критерии описаны в
[поддержке механик](features/item-automation.md).

Полноценные смысловые блоки специализированных detail renderer оформляются
через общий `share-ui/DetailSection`: тематическая иконка, контрастный
uppercase-заголовок и затухающая линия связывают оружие, предметы, способности,
заклинания, существ, черты и доспехи в одну визуальную систему. Боевые блоки
используют `tone="combat"`, а повторяемые карточки с собственным названием и
описанием — `shared/ui/DetailEntryCard`. Специализированные hero/stat-блоки
типов сохраняют собственную композицию.

`window.alert`, `window.confirm`, `window.prompt` и вручную собранные во feature-коде
`position: fixed` backdrop-оверлеи запрещены. Shared picker/reporting primitives
могут владеть специализированным sheet/highlight слоем. Ошибка поля показывается рядом с
полем; ошибка операции — в состоянии формы/экрана. Если требуется новая
повторяемая категория диалога, сначала добавляется обобщённый компонент в
`shared/ui`, затем он используется фичами.

## Навигация приложения

На desktop локальный `shared/ui/DesktopSidebar.vue` является adapter-ом над
`share-ui/AppSidebar` и nav-примитивами. В свёрнутом состоянии rail занимает 64 px,
показывает иконки разделов и оставляет эту полосу в layout страницы.
Раскрытый rail имеет ширину 224 px и показывает подписи, поиск и профиль;
рабочая область синхронно меняет левый отступ с 64 до 224 px, поэтому rail не
перекрывает контент и его визуальная ширина совпадает с зарезервированной в layout.
Групповые маркеры имеют одинаковую высоту в обоих состояниях: раскрытый rail
показывает название категории, а свёрнутый — горизонтальную линию на его месте,
так что позиции следующих иконок не меняются из-за скрытия заголовка. При первом
открытии rail раскрыт; после первого ручного переключения его состояние
сохраняется в local storage внутри общего компонента. Локальный
adapter владеет router,
авторизацией, поиском, account-actions и иконками. Список доступных разделов общий
с мобильным меню и задаётся `shared/lib/appNavigation.js`. «Справочник» остаётся
самостоятельным публичным пунктом без группового заголовка, а публичный пункт
**«Правила игрока»** входит в группу **«Для игрока»**. Гость видит в этой группе
**«Создать персонажа»**. Авторизованный пользователь без персонажей видит тот же
пункт, а после появления первого персонажа он заменяется на **«Персонажи»**. Над поиском расположен
`shared/ui/GameContextSelector`: в раскрытом
rail он показывает логотип и подпись одной строкой: «D&D 5e · 2024» или
«Vampire · V20», без слова «редакция». В свёрнутом
rail и мобильной шапке использует ту же эмблему как кнопку. По нажатию открывается
единый список пар «система — редакция»: одна строка сразу выбирает конкретный
`sourceVersionId`, без промежуточного выбора системы. Текущая строка отмечена
галочкой и акцентным фоном. `GameContextEmblem` использует прозрачные PNG-маски
из `public/static/game-context`: присланный пользователем логотип D&D общий
для 2014/2024, знак анкха — для Vampire. Иконки окрашены через `--accent`, без
подложек, рамок и теней; неизвестные системы получают нейтральную SVG-эмблему
и исходные названия. В строках меню редакция также стоит справа от системы
через точку. Доменный trigger нужен для логотипа и подписи пары, а меню собрано из
общих `BasePopover` и `ActionMenuItem` с ролью `menuitemradio`. Popover переносится
в `body`, помещается в viewport и не обрезается rail. Поддерживаются стрелки,
Home/End, Enter/Space, закрытие по Escape/Tab и возврат фокуса. После успешного
выбора меню закрывается; при ошибке остаётся открытым с прежним выбором и
сообщением. Авторизованный выбор
сохраняется через account API в БД, гостевой — в local storage. Иконка
списка-документа обозначает сессии, а иконка группы людей —
персонажей. Поиск является первым элементом навигации сразу
под игровым контекстом: клик по его иконке в свёрнутом rail раскрывает панель и сразу
переводит фокус в поле с placeholder **«Поиск по справочнику»**, а список найденных вариантов раскрывается справа
от панели без изменения layout страницы. Popover появляется и скрывается плавно;
при уточнении запроса строки и секции анимируют добавление, удаление и смену
позиции. Результаты группируются по конкретному типу предмета или словарной
подсказки; локальные материалы D&D 5e 2014 образуют отдельную группу «Правила»
и ведут прямо к статье. Они появляются до завершения серверного запроса и
остаются доступны при ошибке API справочника. Область поиска ограничена текущей
системой и редакцией; локальные статьи правил подключаются только для D&D 5e
2014. Ссылка «Правила» вычисляется из того же контекста. Для гостя account-блок
в раскрытом rail показывает действия
**«Войти»** и **«Регистрация»**, а в свёрнутом — стандартную иконку входа с
доступным названием и браузерной подсказкой **«Войти»**.

На ширине до 640 px desktop rail скрыт, а сверху используется
`AppHeader`.

Активные сессии мастера доступны через `ActiveSessionShortcuts` в верхней части
sidebar и слева в мобильной шапке. `stores/activeSessions` хранит только активные
сессии текущего владельца, сбрасывается при смене аккаунта и защищает список от
устаревших запросов. Карточки используют `SidebarNavItem` с пунктирной акцентной
рамкой; на узком мобильном экране остаётся иконка с доступным именем.

### Главная

Маршрут `/` является компактной картой продукта, а не заглушкой о разработке.
Первый экран объясняет общий сценарий DnD Share и даёт два быстрых действия:
создание персонажа и переход в справочник. Справа Лиссара используется как
полноразмерная сюжетная иллюстрация-проводник с короткой подсказкой про визард;
она не заменяет знак бренда. Страница переиспользует утверждённую позу
`md/assets/mascots/lissara/knowing-coin.webp`, а публичная копия для frontend
лежит в `frontend/public/static/mascots/lissara-knowing-coin.webp`.

Ниже расположены четыре разные по ширине продуктовые плитки на `BaseTile`:
лист персонажа ведёт к `/chars`, визард — к `/chars/new`, справочник — к
`/handbook`, сессии — к `/sessions`. Каждая плитка содержит короткое описание и
собственную схематичную миниатюру, поэтому разделы различаются не только
иконкой. На средних экранах миниатюры становятся фоновыми, а до 900 px плитки
выстраиваются в одну колонку; до 420 px декоративные миниатюры скрываются,
чтобы не конкурировать с текстом.

Бренд **DnD Share** в desktop rail, мобильной шапке и favicon использует
растровый знак фиолетового зелья из `frontend/public/brand-mark.webp`.
У знака один сильный симметричный силуэт: приземистый флакон с крупными гранями,
мягко напоминающими d20, короткая тёмная пробка, глубокий сливовый контур и
сдержанное фиолетовое содержимое. Мелкий декор, пузырьки, текст, руны, рамка и
фоновая сцена не используются. `favicon-32.png`,
`favicon.ico` и `apple-touch-icon.png` являются уменьшенными производными
мастер-знака и не редактируются как самостоятельные варианты.

### Маскот DnD Share

Канонический образ, неизменяемые признаки, библиотека поз и правила для
сюжетных обложек описаны в [`md/mascot.md`](./mascot.md). Маскот используется в
сюжетных иллюстрациях, но не уменьшается до логотипа или favicon: в компактных
размерах лицо теряет характерные признаки. За системный бренд отвечает отдельный
знак зелья. Его мастер хранится с настоящим прозрачным alpha-каналом и
проверяется на светлом и тёмном фоне в размерах 64, 32 и 16 px.

Действие **«Аккаунт»** находится в меню профиля непосредственно над выходом и
ведёт на `/account`. Страница имеет две доступные keyboard-вкладки: смена пароля
и использование пространства. Вторая вкладка загружает статистику только при
первом открытии, показывает общую `SegmentDonutChart`, счётчики неизвестных
размеров и подробный список личных изображений, SVG, видео и музыки. HTTP и
авторизация остаются в feature-коде; в `share-ui` вынесена только механика
нейтрального графика.

По умолчанию маршрут использует режим `flow`: `AppHeader` находится в обычном
потоке документа и естественно уезжает вместе со страницей без JS-наблюдения за
`window.scrollY`. Полноэкранный workspace с собственным scroll-контейнером может
явно задать `meta.mobileHeader: 'collapsible'`. Такой экран регистрирует активный
DOM `Element` через `shared/composables/useAppHeaderCollapse.js`; контроллер один
владеет scroll/touch listeners и состоянием `ui.headerHidden`. Полноэкранный
экран со своей навигацией может использовать `meta.mobileHeader: 'hidden'`:
тогда `AppHeader` не отображается на ширине до 640 px, а контент занимает всю
высоту viewport.

Feature-компоненты не должны самостоятельно слушать `window` или записывать
`headerHidden`. При смене вложенной вкладки workspace перерегистрирует её scroll
element. Для измерения внутренних toolbar передаётся явный DOM-ref; `$el`
Vue-компонента не является допустимым контрактом, потому что fragment-компонент
может вернуть text/comment anchor вместо `Element`.

Мобильная шапка всегда сохраняет бренд **DnD Share** и его выпадающую навигацию,
но не дублирует title текущей страницы. Кнопка **Назад** показывается только у
вложенного состояния и ведёт к явно заданному родителю, а не по истории browser:
например, сессия → список сессий, создание персонажа → список персонажей. У
корневых списков кнопки нет. В справочнике сначала снимается вложенный `item`,
затем `type`, и только после этого используется родитель маршрута.
До 480 px аккаунт использует компактный trigger: аватар или иконку входа,
чтобы кнопки авторизации и длинный логин не расширяли страницу. Регистрация
остаётся доступна в окне входа.

Страница может уточнить компактный chip через
`ui.setHeaderContext({ chip }, route.name)`: так экран сессии показывает её
статус. Контекст привязан к имени маршрута, поэтому
данные предыдущего экрана не используются как fallback; при размонтировании
владелец вызывает `clearHeaderContext(route.name)`. Title страницы остаётся в
`route.meta` для router и transition semantics, но в мобильной шапке не
выводится. Режим `mobileHeader: 'hidden'` имеет приоритет над содержимым header.

## Drag-and-drop

`useSortable` из `@sylvieshare/share-ui` — единая механика списков сцен, музыки, инвентаря и других
сортируемых коллекций. Feature-компонент отвечает только за идентификатор
группы, отображение placeholder и сохранение результата. Расчёт индексов,
pointer lifecycle и перенос массива не копируются в компонент.

Для простой перестановки после drop используется `reorderByDrop(items,
fromIndex, toIndex)`. Для нескольких контейнеров используются группы
`useSortable`; DOM-контейнер помечается `data-sortable-container`. Элемент с
`data-sortable-key` может находиться внутри нейтральной UI-обёртки, например
`RowActionMenu`: индекс считается по ближайшему sortable-контейнеру, поэтому
вложенные сортируемые списки не смешиваются с родительским.

Свободная раскладка кампании использует отдельную pointer-модель, а не сортировку
списка. `SessionGraphCanvas.vue` держит один постоянный экземпляр
`NarrativeGraphCanvas.vue`, который владеет pan, zoom, перетаскиванием узлов и hit
targets связей. При переходе глава → сценарии → блоки меняются только nodes,
edges, размеры карточек и ключ сохраняемого viewport; второй физический холст не
монтируется. `useChapterGraph.js`, `useSceneGraph.js` и
`useSceneBlockGraph.js` раздельно владеют серверным состоянием уровней и
optimistic preview координат. В local storage сохраняется только viewport,
позиции и связи остаются серверным состоянием.
Справочные предметы для сценария, боя и дневника загружает общий
`features/items/composables/useItemReferenceMap`: один запрос на уникальный набор
id, защита от устаревших ответов и завершения запроса после unmount. Дневник
собирает ссылки всех боёв выбранного раздела, а не загружает каждую строку
отдельно. Отображение картинок и SVG принадлежит общему предметному `ItemIcon`.
После преодоления порога drag-жеста `NarrativeGraphCanvas` один раз эмитит
`drag-start`; владелец уровня закрывает открытые action-menu до начала preview
координат. Pointer-down без фактического перемещения остаётся обычным кликом.

Отдельный workspace state страницы сессии сохраняет режим, уровень вложенности,
главу и выбранный сценарий. Он восстанавливает холст сценария/элементов после
перезагрузки и служит return-context: закрытие боя возвращает пользователя на
тот уровень, откуда бой был открыт. Его переходы представлены одной фазой
`idle/opening/open/closing`; уровень холста и выбранный id сценария вынесены в
`useSessionGraphNavigation`, поэтому компоненты не держат параллельные копии
объекта сценария. Optimistic drag-preview ограничен одним обновлением на кадр,
а запись viewport в local storage выполняется с debounce.

На всех трёх уровнях завершение link-жеста сразу создаёт переход без
промежуточного окна. Клик по линии или уже показанной подписи открывает
`BasePopover` с отдельными действиями изменения необязательной подписи (до 240
символов) и удаления перехода; create/update/delete сразу синхронизируют
соответствующий edge в серверном graph state через `POST`, `PATCH` и `DELETE`
routes. Во время link-жеста наконечник временной стрелки совпадает с курсором,
а линия автоматически выходит из центра ближайшей к нему стороны карточки.
Активное создание связи отменяется через `Esc` или ПКМ; браузерное контекстное
меню подавляется только пока выбран исходный узел.
Готовые переходы также выбирают обращённые друг к другу центры левой, правой,
верхней или нижней стороны. Меню связи на каждом уровне позволяет менять
подпись, переключать одно-/двустороннее направление и разворачивать
одностороннюю связь; для двусторонней связи лишнее действие разворота скрыто.
Первая и последняя части существующей кривой имеют широкую невидимую hit-area:
hover подсвечивает конкретную связь, а drag этой области к другой карточке
переставляет соответствующий конец через тот же PATCH. Поэтому сходящиеся в
один порт линии остаются доступны до общей точки. При создании и перестановке
наведение на допустимую карточку заменяет линию к курсору полноценным preview
будущего соединения между портами; наконечники сохраняют выбранную
направленность.

На третьем уровне `NarrativeGraphCanvas` читает индивидуальную ширину блока и
измеряет фактическую DOM-высоту через `ResizeObserver`, поэтому границы связей
следуют за содержимым. Drag правой границы даёт optimistic preview ширины и
сохраняет её через `useSceneBlockGraph`; эта механика не включается для глав и
сценариев с фиксированным размером.

Выбор фоновых изображений глав, сценариев и локаций использует общий
`SessionImagePicker`: в форме он показывает только текущую картинку и действие
смены. Отдельное окно выбора содержит единый прокручиваемый каталог с секциями
и верхними якорями категорий, а не вкладки с разрозненными списками. Тот же
компонент принимает отдельный NPC-каталог. Оба каталога загружаются API и
кэшируются на клиенте; карточки получают готовый `imageUrl`, поэтому локальных
preset-путей и второго контракта для загруженных файлов нет.
Для сценария picker разрешает не выбирать собственное изображение: редактор
показывает прямую привязку к одной локации и в таком режиме использует её
картинку. Карточка сценария не выводит вычисляемый порядковый номер.

Контекстные действия создания выводятся через `CanvasActionDock.vue` поверх
холста сверху справа и прижимаются к его правому краю. Каждый action —
отдельная стеклянная кнопка без общего tile-контейнера. Командная шапка сессии
является обычным `header` с собственным фоном и нижним разделителем, а не
`BaseTile`: в ней находятся
session/arc/combat controls, статус через меню слева от названия и арки,
крупные иконки с подписями снизу, компактный player справа с прокруткой длинного
названия трека и отдельная вкладка хроники. Экран, таймеры, кубики, сокровища
и инвентарь собраны в правой колонке; все их кнопки без рамки и фона. Формы и
разрушающие действия графа используют `AppModalFrame` и `ConfirmDialog`, обычный
клик по узлу/связи — `BasePopover`.

Контекст входа в бой берётся у постоянного `SessionGraphCanvas`: на уровне
элементов он содержит закреплённые главу и сценарий, передаётся как одним
действием блока «В бой», так и combat-кнопкой командной шапки, а затем хранится
в workspace state. Боевая панель освобождает слева место под одну или две
контекстные карточки, не создавая отдельный breadcrumb или второй холст. Её
desktop-правая граница не зависит от видимости правых tool-панелей.

## Форматированные описания

Пара `share-ui/RichTextEditor` + `share-ui/RichContent` является единым
контрактом расширенного описания. Локальный `InputDescription` только адаптирует
этот контракт к DnD-состоянию. В данных хранится очищенная HTML-строка текущего
формата; allowlist sanitizer применяется при paste/drop, выдаче из редактора и
перед read-only DOM render. Обычные ссылки редактирует сам `RichTextEditor`.
Предметные inline-узлы хранятся атомарным
`span[data-rich-node][data-rich-payload]`: `share-ui` владеет безопасным
HTML-контрактом и selection API, а `DndRichContent` — значениями `dice`, `item`
и `suggest`, их загрузкой и действиями. В блоке действий клик по описанию
открывает меню строки; `dice`-узлы описания автоматически дают пункты бросков
через `richDescriptionRolls`, без отдельных настроек меню в зависимости. `suggest` в расширенном тексте означает
конкретный термин малого справочника (например навык или состояние), а не ссылку
на раздел каталога; при активации он показывает описание термина. `InputDescription` добавляет кнопки этих
трёх типов через toolbar slot: на широкой панели это семантические Lucide-иконки,
рядом с которыми находится нативное действие обычной ссылки; при недостатке
ширины все четыре действия сворачиваются в одну кнопку с подписанным меню.
Область редактирования прозрачная и отделяется от окружающей формы рамкой; клик
по существующему chip открывает действия изменения и удаления. Не добавлять параллельные поля
`desc/description` ради совместимости: у каждой сущности в схеме должен быть
один документированный ключ.

В read-only тексте предметные inline-узлы не имитируют отдельные bordered-chip:
ссылки на `item`/`suggest` используют низкую полупрозрачную подложку и
приглушённый знак, а `dice` — более компактную цветную подложку без рамки и с
увеличенным боковым внешним отступом. Цвет усиливается только при наведении или
keyboard focus, поэтому узлы остаются заметными действиями, но не дробят прозу.

Read-only `DndRichContent` и текстовая область `InputDescription` используют
отдельный книжный шрифт `--font-prose` (Literata в DnD Share). UI-кнопки,
метаданные и короткие подписи остаются в `--font-ui`, а заголовки сущностей — в
`--font-display`. Та же prose-роль применяется к статьям правил, полноценным
описаниям мира и текстовым материалам сессии; короткие карточные excerpts,
ошибки и служебные сообщения не считаются long-form только из-за имени поля
`description`. Технические ключи, формулы, идентификаторы и логи используют
единый `--font-mono`.

Таблицы входят в allowlist rich HTML и в read-only `DndRichContent` получают
отдельную поверхность, контрастную шапку, чередование строк и горизонтальную
прокрутку на узком экране. Импортированный Markdown не является runtime-
форматом: migration переводит такие таблицы в семантические
`table/thead/tbody/tr/th/td`.

`dice` хранит `{formula,label?,average?}` и показывает ручное среднее перед
составом формулы через `SystemDie`; клик отправляет выражение в общий dice store.
Формулы поддерживают сложение, вычитание и умножение, включая редкие
импортированные выражения вида `1к6 × 5`. DnD-адаптер принимает необязательное
имя субъекта: в карточке существа оно передаётся в бросок отдельно от действия и
попадает в `actorName` журнала. Карточка, открытая из encounter, проводит этот
контекст через `ItemViewModal` и добавляет к имени букву экземпляра. `item` хранит `{id,typeId}`,
показывает короткий hover-preview и открывает `ItemViewModal` по клику. `suggest`
хранит `{id,typeId}` и раскрывает описание в `BasePopover`. Legacy custom tags
не являются runtime-контрактом; рекурсивная startup migration переводит их во
всех HTML-строках item data в `dice`, `item`, `suggest` либо безопасную нативную
ссылку и идемпотентно пропускает уже актуальные узлы.

Инлайн-узел `stat` хранит `{stat:"ac"|"hp"}` и подчёркивает упоминания КД и
хитов компактной иконкой щита или сердца без действия по клику. В редакторе оба
варианта доступны из меню вставки; существующий stat-узел можно удалить как
единый атом. Базовые описания вещей и зелий получают эти узлы автоматически
только в одноразовых data migration, а не переписываются при каждом чтении.

## Персонажи и игровые системы

`features/character-editor/settings/index.js` — реестр поддерживаемых систем.
Для каждой системы он задаёт:

- schema/layout листа из кода;
- semantic accessors для имени, аватара, подзаголовка, уровня, HP, AC и
  инициативы;
- создание начального payload, если оно отличается от D&D wizard.

`char_template` хранит только `id` и `name`. Полей `schema`, `createForm` и
`pathValues` нет. Список персонажей, toolbar и сессии используют одни и те же
accessors; чтение путей из БД не допускается. D&D и VTM зарегистрированы в коде.

Канонические D&D-данные читаются только в текущем формате: `lvl` — объект,
`classes` — массив, характеристики имеют `value {base,bonuses}`, `speed` —
`{base,bonuses}`, `hp.hitDice` — массив, `spells` — объект, инвентарь —
`{equipped,sections}`, деньги — `{order,amounts}`. Преобразование старых данных
выполняет startup-схема из `internal/store/schema/*.sql` до начала
HTTP-обслуживания; компоненты не содержат read-time миграций.

Фиксированный каталог кубиков находится в `shared/lib/systemDice.js`, а все
экранные многогранники и выпавшие значения рисует `shared/ui/SystemDie.vue`.
Кубики не зависят от Pinia suggest store.

## Router

Актуальные страницы: `/`, `/sessions`, `/sessions/:uuid`, `/screen/:code`, `/join/:code`,
`/chars`, `/chars/new`, `/char/:uuid`, `/char/:uuid/print`, `/handbook`,
`/handbook/dictionary`, `/handbook/objects`, `/rules`, `/rules/:articleSlug`,
`/admin`. Неизвестный клиентский
маршрут перенаправляется на `/`.

Вкладка `/admin` «Статистика» показывает не только счётчики сущностей, но и
общий объём управляемого файлового хранилища. Общий `SegmentDonutChart` строит
разбивку системных и пользовательских изображений, видео, системной и
пользовательской музыки и SVG; рядом выводятся число объектов и предупреждение
о файлах с неизвестным размером. На узких экранах график и сводка переходят в
одну колонку.

В `/admin?tab=ui-kit` через отдельный `@sylvieshare/share-ui/gallery`
подключается `ComponentGallery`. Это единая интерактивная витрина библиотеки:
она использует DnD-тему и accent приложения. На уровне исходников компонент
запрашивается через `defineAsyncComponent`; production-конфигурация dndShare
намеренно сводит весь JavaScript в один стабильный файл, чтобы открытая вкладка
не получала 404 после deploy, поэтому отдельного runtime chunk здесь нет. Новый
публичный визуальный компонент `share-ui` обязан появиться на этой доске —
полноту проверяет тест самой библиотеки.

`/screen/:code` uses `meta.standaloneView`: like print mode, it removes the
global sidebar, header and diagnostic overlays, but retains the dark application
theme for a public read-only encounter display.

Router prefetch хранится 30 секунд и используется страницами списков. Направление
перехода определяется `meta.section/depth/pageOrder`; навигационные компоненты
не должны вычислять его повторно. На desktop страницы сменяются последовательно.
На ширине до 768 px приложение использует root View Transition: переход вперёд
мягко вводит новый экран справа, а возврат сдвигает верхний экран вправо и
открывает готовый родительский. В единый snapshot входят и страница, и `AppHeader`,
поэтому граница полноэкранного листа персонажа не вызывает отдельной перестройки
шапки. Длительность мобильного перехода — 380 мс. Для браузеров без View
Transition входящая и исходящая страницы перекрываются CSS-анимацией, а исходящая
страница исключается из потока. При `prefers-reduced-motion: reduce` анимация
отключается. View Transition update callback ждёт завершения роутинга через
`afterEach` и следующий Vue `nextTick`; ожидание `requestAnimationFrame` внутри
callback запрещено, поскольку браузер может приостановить кадры до завершения
DOM update и прервать переход по timeout. Все служебные promises View Transition
наблюдаются, поэтому штатная отмена анимации не создаёт глобальную ошибку.

## CSS

`features/master-tools` содержит генератор сокровищ для правой панели сессии. Отдельная страница инструментов, ночлег и странствие удалены. Чистая генерация находится в `lib`, состояние — в `useTreasureGenerator`, форма — в `components`. `SessionToolsRail` сохраняется на всех вкладках; `SessionTreasureControl` держит состояние вне поповера и модальный просмотр предмета. Настройки сессии — отдельная вкладка на общих `BaseTile`, `FormField` и `ToggleSwitch`, центрированная внутри `SessionTabWorkspace` с максимальной шириной 760px. `useSessionSettings` читает разделы `players` и `combat` из сессии и сохраняет отдельные пути через API; браузерного хранения настроек нет. Запуск и копирование используют публичный `share-ui/ActionButton` (0.19.0). Контракт — [инструменты мастера](features/master-tools.md).

Общая палитра и canvas приходят из `@sylvieshare/share-ui/styles.css`, который
импортируется один раз в `main.js`. `src/app/theme.css` задаёт DnD-акцент,
layout, доменные цвета и продуктовые prose/mono/print font stacks. Cormorant
Garamond и Literata подключаются как variable web fonts; display-роль не
запрашивает веса выше поддерживаемого `700`. `npm run check:colors` входит в production build и
запрещает новые прямые hex/RGB/HSL значения. Подробности — `md/css-variables.md`.

## Обновление share-ui

### Cross-repository сопровождение

Задача в DnD Share является разрешением без дополнительного согласования
изменить соседний `../share-ui`, когда существующий общий API содержит баг или
не позволяет корректно завершить задачу. В рамках задачи разрешены изменения
исходников, тестов, галереи и документации библиотеки, release commit/tag/push,
а затем обновление точной версии и lock-файла DnD Share.

Изменение обязано оставаться нейтральным: `share-ui` не получает router, Pinia,
HTTP API, permissions, локализованные DnD-тексты и доменные модели. Такая логика
остаётся в локальном adapter/controller. Нехватку общего API не обходят копией
компонента, deep import, правкой `node_modules` или постоянным переопределением
его базовой геометрии. Если безопасное решение требует незапланированной
breaking-миграции других продуктов, перед выпуском нужно завершить их миграцию
либо запросить решение пользователя.

Канонический порядок работы, матрица проверок, versioning и Definition of Done
описаны в
[share-ui/MAINTAINING.md](https://github.com/SylvieShare/share-ui/blob/main/MAINTAINING.md).

DnD Share использует точный HTTPS-архив release tag; floating branch и локальная
`file:` dependency не допускаются. Обновление выполняется после выпуска новой
версии в `SylvieShare/share-ui`:

```bash
cd frontend
npm install --save-exact \
  "https://github.com/SylvieShare/share-ui/archive/refs/tags/vX.Y.Z.tar.gz"
npm test -- --run
npm run build
```

Изменения межпроектного примитива сначала делаются и документируются в
`share-ui`, затем consumer обновляет tag. Файлы внутри `node_modules` не меняют.

## Политика изменений контракта

Runtime поддерживает только текущий контракт. Если изменение ломает старый
формат, нужно:

1. добавить идемпотентное исправление данных в подходящий
   `internal/store/schema/*.sql`;
2. переключить все producer/consumer на новый формат;
3. удалить старые поля, ветки чтения, aliases и временные admin jobs;
4. обновить `md/` и тесты.

Сохранение двух форматов «на всякий случай» не допускается.

Редактор справочных способностей типов 3/4/18 использует единый доменный профиль
`features/items/editor/abilityEditorProfile` и рекурсивные `AbilityRuleFields` /
`AbilityRuleField` поверх `share-ui` form-controls. Он компонует описание и
механику в две колонки, добавляет каждую запись зависимости отдельной карточкой
через `useAbilityDependencies` и раскрывает
подсказки полей при наведении без кнопок «?» и текста под инпутами.
`ItemMultiSelect` — общий выбор нескольких справочных объектов для простых
массивов ссылок в обоих редакторах схем. Его выбранные записи и результаты
поиска используют `HandbookListItem`, тот же диспетчер строчных представлений,
что и `HandbookItemList`. Поиск, пагинация и черновик выбора вынесены в
`useItemMultiSelect`; применение происходит по «Готово», закрытие отменяет
черновик. `ItemSourcePicker` заменяет длинный перечень книг компактным
действием и вложенным окном только у существующих базовых записей. У личных
объектов источник не запрашивается. Кнопка редактирования карточки расположена
слева от ID; страница, picker и окно просмотра используют общую проверку
`canEditHandbookItem` для администратора или точного автора записи. Слои окон передаются относительно `ItemEditModal.zIndex`,
в том числе при создании объекта из вложенного picker. Подробный контракт —
в `md/features/handbook.md`.


`AbilityActionEditor` задаёт предметную композицию действия: `RuleKeyField`
генерирует незаданный ключ из названия, `AbilityActionMenu` редактирует пункты
меню, `RuleReferencePicker` и `RuleReferenceList` выбирают типизированные связи.
Они получают актуальный черновик и источник через `itemFieldEditorKey`;
ошибки незавершённых настроек регистрируются в `ItemEditModal.editorValidation`
и блокируют сохранение. Набор JSON-полей и массивы способностей не меняются.
Параметры, относящиеся к выключенному расходу ресурса, удаляются из черновика.
Полный контракт описан в [редакторе зависимостей](features/ability-editor.md).

### Редактирование механик и выбор урона

[Манифест редактора способностей](features/ability-editor-manifest.md) задаёт
композицию и условную видимость. `abilityMechanicManifest.js` — метаданные
панелей и условий; progression, weapon damage и связанные эффекты имеют
собственные feature-компоненты на общих `FormField`/`FormSelect`/`ToggleSwitch`.
Прогрессия редактируется одной таблицей. `abilityProgression.js` разделяет расчёт
костей между предпросмотром, листом, панелью и броском, исключая дубли данных.
`DamageRollOptions` компонует общие переключатели в меню оружия, базовых атак
и урона заклинаний. Состояние выбора существует только до закрытия меню.
Стили компоновки оружейного блока вынесены в `DndWeapons.css` и подключаются scoped.

### Группы строк на листе персонажа

`share-ui/SectionList` задаёт общую плитку, заголовок и разделители между строками
оружия, базовых атак и кругов заклинаний. `embedded` используется для категорий
способностей и типов действий внутри существующих плиток. Разделители работают
на корнях слотов, включая обёртки `RowActionMenu`, а не на вложенных карточках.
`footer` содержит добавление оружия до отдельной группы базовых атак;
`listAttrs` передаёт атрибуты сортировки, `transitionName` сохраняет анимацию
строк заклинаний. Табличный вариант оружия передаётся через `body`.
Предметное содержимое строк, меню, права и броски остаются в DnD-компонентах.

## Состояния загрузки

Общий `share-ui/LoadingIndicator` показывает неопределённую загрузку:
тонкое кольцо с вращающимся сегментом использует акцент темы. Consumer задаёт подпись и область
центрирования; `prefers-reduced-motion` отключает движение. Используется до
получения структуры листа персонажа и при загрузке обложки справочника.
`share-ui/SkeletonBlock` применяется только внутри уже известной структуры:
формы повторяют размеры и состав строк, не подменяют неизвестную раскладку.

Полный контракт и карта использования: [состояния загрузки](loading-states.md).

`MagicEquipmentBases` — доменный список допустимых основ магического предмета.
Он оборачивает стандартный `HandbookListItem` в `BaseTile` с рамкой и использует общий контракт
`magicEquipmentBases` и загрузчик `loadMagicBases` для просмотра и выбора.
`MagicEquipmentInstanceModal` проверяет кандидатов до добавления в инвентарь,
оружие или стартовый магазин. Единственный допустимый кандидат выбирается без
вопроса; `AppModalFrame`/`ActionButton` открываются только для неоднозначного
выбора либо ошибки/отсутствия основ. В смешанном предмете фиксированная основа
не повторяется в вопросе о другой основе. `MagicItemDetailSummary` использует существующие
`CoverSummaryLayout`, `CoverStatCard` и `CoverSummaryRail`; остаток заполненной
схемы выводит доменный `MagicRuleFields` со ссылками, словарями и rich content.

`MagicEquipmentAdditions` отделяет магические изменения основы от списка
подходящего оружия/доспехов. `ItemTreasureSummary` показывает участие в случайном
подборе, уровни группы и относительный вес. Оба доменных блока используют
`DetailSection` и `BaseTile`; собственные стили задают композицию и типографику.

`useInventoryEquipmentActions` переносит один экземпляр в профильный раздел,
сохраняя UID. Магическое оружие хранит основу в `item_id`, источник типа 19 —
в `magic_item_id`; `useWeaponEntries` работает с обычными записями `values.weapon`.
`magicWeapons.resolveWeaponItem` объединяет основу, магические свойства и личные
изменения для бросков, инвентаря и печати. `characterMagicItems`
читает и обновляет состояние по UID во всех местах хранения. `useInventoryCatalog`
загружает обе ссылки при изменении инвентаря и показывает ошибку с повтором.
`ItemInstanceNotes` дополняет карточку источника личными бонусами и заметками,
используя общие `DetailSection` и `DamageDice`. `selectedMagicBases` определяет
основы конкретного экземпляра; `MagicItemDetailSummary` показывает их внизу
обложки через `MagicEquipmentBases` в одну колонку с обычным `HandbookListItem`.
Уже загруженная основа используется без повторного запроса. В этом режиме
скрыты соответствующие списки подходящих основ и генератор сокровищ.
`itemInstancePresentation` сохраняет представление магического источника,
применяя только личные изменения; физические характеристики в него не смешиваются. Редактор справочника получает исходный объект,
а не собранное представление экземпляра.

`shared/lib/weaponDamageOptions` проверяет граф выбранных добавок к урону,
сбрасывает зависимые переключатели и определяет способ атаки. Сборщик боевых
эффектов добавляет к ключам связей namespace владельца/экземпляра, исключая
смешивание одинаковых правил разных предметов. `DamageRollOptions` показывает
условия и вложенность, передаёт выбор в броски атаки и урона. Расчёт проверяет
выбор повторно; бросок оружия сохраняет характеристику основы, но получает
контекст дальней атаки для эффектов и исключает хват двумя руками.

Адаптер `weaponDamageMenuOptions` передаёт меню готовые подписи, условия,
доступность и `damageParts`. Кости вычисляются в `weaponDamageActionParts`,
из тех же частей строится формула броска; при крите отображаемое количество
меняется вместе с расчётом. `DamageDice` рисует существующие `SystemDie`: в меню
размер 26 px, в карточках дополнительных режимов — 32 px. Новый параметр
`size` по умолчанию равен прежним 42 px и сохраняет размер остальных бросков.

`DamageRollOptions` хранит общий выбор параметров и открывает два штатных
`RowActionSubmenu`: «Бросить на атаку» и «Бросить на урон». `WeaponRollControls`
показывает настройки выбранного броска и кнопку выполнения; `WeaponRollOption`
рисует отдельный переключатель. Переключение подменю не сбрасывает параметры.

`weaponThrow` добавляет всем оружиям режим «Метнуть» с ключом `weapon:throw`.
Если зависимость уже задаёт метание, используется её ключ и добавочные кости.
Метательное свойство определяется по id 6 или загруженной подписи свойства.
Для неподходящего оружия подготовка броска создаёт временную запись с
Ловкостью и признаком `_improvisedThrow`: 1к4 вместо обычных костей, без
обычного владения, оружейного магического бонуса и ручных дополнительных
атак. Исходная запись не изменяется. Тип урона по умолчанию берётся из основы;
особые владения импровизированным оружием и решения мастера требуют ручного
учёта. Для подходящего оружия сохраняются его кости, характеристика и бонусы.
Режим отключает хват двумя руками и рукопашные эффекты. Импровизированный
предпросмотр показывает замену кости через стрелку, а не добавочные +1к4.

`MagicItemMenuActions` выводит отдельную команду настройки на персонажа для
магических предметов, которым она нужна. Дополнительная форма экземпляра
доступна только для авторских выборов и ручного максимума. `magicItemSettings`
обновляет настройку по UID, не сбрасывая ресурсы, и разрешает только первоначальное
заполнение отсутствующей основы. Выбранная основа не редактируется. Один компонент
используется в инвентаре, карточках оружия и табличном варианте.

### Листовые ссылки на связанные записи

`features/items/components/HandbookReferenceRows.vue` загружает записи разных
справочников, их схемы и подсказки и выводит существующий `HandbookListItem`
в рамке `BaseTile`. Под строкой можно передать условие; строка открывается
клавиатурой или мышью в `ItemViewModal`. Есть состояния загрузки, отсутствующей
записи и ошибки с повтором. `ItemEffectLinks` использует его для эффектов
предмета, `EffectSources` — для обратных ссылок с пагинацией. Вложенные окна
получают следующий `zIndex` от справочного окна.

`share-ui/GuidedTour` + `useGuidedTour` — общий стандарт подсветки и исполнения

### Общие тезисы механик

`shared/ui/MechanicTheses.vue` — единый компонент условий действий, условий
эффектов и панелей способностей: 13 px, межстрочный интервал 1.5, цветные маркеры.
`mechanicTheses` оформляет явно переданные тезисы, убирает одинаковые пункты,
сохраняет rich-ссылки и кости. Предложения автоматически не разделяются.
В `DndActionsView` описание выводится отдельно через `DndRichContent`, а
`MechanicTheses` получает только `requirements`; без условий список отсутствует. `HandbookReferenceRows`
поддерживает две колонки через слоты `info` и `description`; `ItemEffectLinks`
выводит слева применение эффекта, справа его строку и описание.

### Выбор расхода и предпросмотр урона

`WeaponResourceAmount` — предметный компонент выбора 0…N на основе существующего
`SpellSlotSphere`. `weaponDamageAmounts` масштабирует кости и цену одного правила
по выбранным ячейкам; это преобразование используется и меню, и транзакцией
списания. `DamageFormulaPreview` читает итоговую формулу броска через общий
`parseDiceExpression` и показывает группы типов урона компонентом `DamageDice`
в компактной рамке общего `BaseTile`. Подменю бросков не повторяют название
пункта отдельным заголовком; кнопка запуска остаётся после параметров.
Общий блок ресурсов использует `resourceVisibility`: без сохранённого флага
дубли на оружии, действиях и виджетах скрыты; пользователь может включить их
через редактор. Состояние остатка ресурса при этом хранится единожды в источнике.


`ItemLastChargeCheck` — общий предметный блок для оружия и инвентаря, на основе
`ItemUsePanel`, `SystemDie`, `ActionButton` и `ConfirmDialog`. `useLastChargeCheck`
читает актуальный экземпляр по UID, блокирует повторное нажатие и записывает
событие в сохраняемый журнал персонажа через его context. Чистый `itemLastCharge`
отвечает за создание, разрешение и отмену события; `setCharacterResourceAvailable`
вызывает его только при явном `spending=true`. Восстановление и редактирование
остаются обычными изменениями счётчика. `magicItemActive` и адаптер неактивного
инвентаря исключают `params.magic.lost`, включая восстановление на рассвете.
Браузерный сценарий проверки: `npx playwright test --config playwright.weapon-charges.config.js`.


`ItemUsePanel` задаёт единую оболочку применения предмета: иконка, заголовок,
краткое состояние, содержимое и ряд действий поверх `BaseTile`. Её используют
`ItemLastChargeCheck`, `WeaponUsePanel` и справочный `WeaponUseSummary`.
`WeaponUseStep` показывает условия через `MechanicTheses`, кнопку слева от
`DamageFormulaPreview` в режиме `unframed` и результат через `DiceRollResult`.
Каждый отдельный урон имеет одну внешнюю рамку. `DiceRollResult` — композиция
существующих `SystemDie` с выпавшими значениями, знаками и итогом; предназначена
для сохранённого результата внутри механики, без глобального popup и новой
базовой поверхности.
`weaponUsePresentation` собирает одинаковые тезисы области/спасброска для листа
и справочника. Эти компоненты не зависят от ID конкретного предмета.

Чистый `weaponUses` проверяет доступность, создаёт снимок оплаченного применения,
разрешает шаги по ID события и сохраняет их на экземпляре. `useWeaponUses`
получает расчёты обычного оружия от `DndWeapons`, поэтому не дублирует правила
характеристик/бонусов. `useWeaponUseSteps` бросает сохранённые формулы без повторной
оплаты и пишет события через `charCtx`. Оба блокируют повторное нажатие.
Редакторы `WeaponUseEditor`/`WeaponUseStepEditor` управляют зависимыми полями;
`itemResourceOptions` общий для этого редактора и проверки последнего заряда.

`dice.runAction` вызывает необязательный `onReroll` после переброса к20. Особое
применение обновляет по нему сохранённый результат атаки без повторного расхода;
завершённый или заменённый ID применения не изменяется.


`useWeaponDamageRolls` содержит общий расчёт превью/броска урона, вынесенный из
`DndWeapons`. `weaponUseDamageActions` превращает ожидающий шаг попадания в
обычную галочку меню; ключ содержит ID применения и шага. Выбор заменяет базовую
формулу сохранённым уроном этого попадания, затем добавляет другие выбранные
правила. Сама оплаченная добавка не прибавляется второй раз. После броска шаг
разрешается по текущему UID/ID и сохраняется вместе с событием журнала.
Старый ключ, чужой UID и завершённое применение блокируют бросок до списания
ресурсов других галочек. Режимы атаки также используют `WeaponRollOption` вместо
select; одновременно активна одна галочка режима.


`DamageRollOptions` хранит локальный `attackRollMode` (`auto`, `disadvantage`,
`advantage`) и передаёт его в событии атаки. `WeaponRollControls` отображает
две взаимноблокирующие `ToggleSwitch` в одной строке с вертикальным разделителем;
режим по умолчанию — `auto`. `DndWeapons` передаёт ручной выбор общему resolver,
а `useWeaponUses` сохраняет его при запуске особой атаки. Штатный переброс к20
использует тот же режим без повторного расхода. `PresetAttackCard` использует
общие подменю атаки/урона и передаёт параметры атаки без отдельного UI.


`ItemResourcePips` — общий доменный вывод зарядов оружия: используется и
отдельной строкой, и внутри `ConfirmedItemUsePanel`, сохраняя одинаковые
ячейки `SpellSlotSphere`, размеры, доступность и значки восстановления.
`useInitialChargeStocks` объединяет настройку основного/именованных начальных
запасов в окне добавления и параметрах экземпляра. `ItemRuleActivation`
предоставляет единый выбор условий зависимости в редакторе магических предметов.


Хроника использует `SessionEventActorGroup` для последовательных групп
«субъект + автор» и вложенных сущностей, `SessionEventRow` для действий и
`SessionEventIcon` для иконок. Общие `ItemIcon`, `DiceRollResult`,
`SpellSlotSphere` и `ItemViewModal` сохраняют предметное отображение листа.
`sessionEventData` собирает контекст источника и снимки изменений ресурсов;
`dice` передаёт `eventData` также при перебросе. `HandbookItemDetail` предоставляет
ближайший item через `sessionEventItem` для бросков из rich-описаний.

Заголовок `MorphTile` не задаёт нижний отступ. Расстояние у характеристик
сохраняется через верхний padding блока значения. Малые плитки КД, инициативы,
скорости и бонуса умения включают `compactHeader`; их содержимое помещается
в строку сетки высотой 64px.

Плитки редактирования листа используют `MorphTile`; общие faces для статов,
ресурсов, защит, действий, владений, денег, статусов, истощения, счётчиков и
заданий используют его `embedded`-представление с тем же заголовком. HP, уровень
и предметная строка оружия могут оставаться без заголовка. Параметры магии и
ячейки используют заголовок `MorphTile` напрямую. `TileAccentStrip` заменяет
бывший prop `BaseTile.strip` в листе, morph-превью, правилах и NPC боя.

Общие представления сами владеют единственной поверхностью `MorphTile`: это
действия, характеристики, малые статы, защиты, ресурсы, владения, деньги, сводка
статусов, истощение, счётчики, задания, HP и уровень. Контроллеры не оборачивают
их второй плиткой; morph-origin берётся с корневого `$el` представления.
В раскрытом редакторе `panel` (у характеристик `mode="panel"`) переключает
представление в `embedded`. Полоса вставляется через слот `decoration`.
Контейнеры коллекций и самостоятельные компактные варианты сохраняются.

`CampaignBadge` остаётся обычным `BaseTile`: иконка `ScrollText`, как в боковом меню,
и название сессии в одной строке с выравниванием по центру,
две `ActionButton iconOnly quiet` рядом слева следующего ряда. `CharacterTransferDialogs`
открывает игроков/события в `BasePopover`; отправка выбирает получателя
в `RowActionSubmenu` через `ItemTransferAction` с иконками 48 px;
общая начинка находится в `CharacterTransferContent`.

`CharacterReadOnlyNotice` объясняет права просмотра наверху центральной колонки
и мобильных вкладок. `CloneCharacterAction` переиспользуется обоими меню;
права и исходный UUID берутся из `charCtx`, действие выполняется через API.

## Общая очередь уведомлений

`stores/notifications` владеет ограниченной очередью из пяти карточек, таймерами,
паузами при наведении/фокусе, ключами замены, областями очистки и обработчиками
действий. `AppNotifications` монтируется в `App.vue` и строит общую оболочку из
`share-ui/BaseTile` и `ActionButton`: закрытие, свайп, появление и полоса времени.
Карточки живут 6 секунд, передачи — 10; очередь доступна через polite live region.
На узких экранах она учитывает safe area; длинная очередь прокручивается.

`DiceRollNotification` отвечает только за представление броска и перебросы;
`SessionEventNotification` — за автора, действие, изменение значений и статус
передачи. `stores/dice` отправляет результат в общий store, сохраняя доменную
историю последнего d20 для переброса. `stores/sessionEvents` сравнивает игровые
данные и отправляет новые/изменённые события, если зарегистрированный читатель
не показывает хронику. Собственные события отсекаются по `authorUserId` аккаунта.
Мастер определяется по `sessionOwnerUserId`; игроку разрешено уведомление только
об `item_transfer` с его `recipientUserId` и статусом `pending`. Эти поля сервер
вычисляет по сессии и таблице передач, не принимает из пользовательского payload.
Контекст активен и у игрока на странице сессии и в листе.
Свой уже показанный результат дедуплицируется через `clientActionId`, включая
атомарное сохранение события с листом. Новые типы используют `notify` и отдельное
представление, не создавая новую очередь и таймеры.

`features/item-transfers/components/TransferPerson` и `TransferStatus` задают
компактное представление участника и цветного статуса передачи. Хроника
показывает получателя, поповер событий — отправителя. `CharacterTransferContent`
строит строки с разделителями и загружает иконки предметов одним запросом;
`CharacterTransferDialogs` держит справочное окно вне закрываемого поповера.

Список передач `useCharacterTransfers` отправляет входящие предложения через
`sessionEvents.notifyTransferOffers` даже при ошибке истории. Автор, адресат и
владелец сессии берутся из серверного DTO. Начальная история остаётся тихой,
кроме ожидающих предложений текущему игроку; два источника разделяют ключ
дедупликации пользователь/сессия/eventId. Повторный refresh не возвращает закрытую
карточку того же предложения в течение жизни store.
`SessionTransferApproval` показывает мастеру кнопку принятия ожидающей передачи
в хронике. API проверяет владельца сессии и атомарно использует ту же операцию,
что принятие получателем; после запроса перечитывается статус существующей записи.


## Производительность и владение общим UI

Страницы router подключаются динамически; Vite разделяет JS и CSS по графу импортов. `npm run build` проверяет бюджет gzip-размеров начального графа и всей сборки. Не увеличивать бюджет вместо разбора регрессии. Методика и измерения — [frontend performance](frontend-performance.md).

`StatBar`, `IconPicker`, `DetailSection`, `ContentRow`, `OptionList`, `SearchMultiSelect`, `FloatingTooltip` и `useVirtualList` импортируются из share-ui 0.23.0. Каталоги иконок, HTTP, тексты, правила D&D и persistence остаются в приложении. ObjectListItem адаптирует доменные иконки/названия к ContentRow; HandbookItemList использует его корень как строку, без внешней рамки. До 80 строк список обычный; более длинный список рисует видимое окно с запасом и сохраняет строку с фокусом. Виртуализация не сокращает данные и не меняет серверную пагинацию или состав групп.

SuggestDropdown использует BasePopover/OptionList и получает якорь-input; стрелки и Enter управляют выбором, Escape/Tab закрывают. MultiSearchSelect мастера — API-adapter к SearchMultiSelect. ItemTooltip передаёт геометрию FloatingTooltip и сохраняет доменное форматирование/touch-условия.

Индексы suggest построены один раз на реактивный массив и обновляются при изменении состава/идентификаторов. CSS строк инвентаря и skeleton подключается в соответствующих компонентах; полный DndItems.css больше не дублируется тремя scoped-импортами. Summary-компоненты используют корень CoverSummaryLayout без декоративного внешнего div. Поля меню боя и кнопки добавления используют общие form/action primitives.

TemplateBlockInner не передаёт пустые style и неиспользуемые vars каждому блоку. Блоки с несколькими корнями явно передают attrs видимой плитке; скрытие задаётся её display, без неработающего v-show на Fragment. Toolbar также передаёт события свайпа и wheel своему DOM-корню.

У списка заклинаний удалён неработавший TransitionGroup и его пять CSS-правил: корень SpellCard — ActionMenu с Teleport, поэтому Vue не мог применить эти переходы. SectionList сохраняет тот же DOM-контейнер и sortable-атрибуты.


Применение зелий использует общие `DamageFormulaPreview`/`DiceRollResult` и
`HandbookReferenceRows`, а `ApplicationSummary` объединяет формулы, результаты,
эффекты и длительности для входящего запроса, хроники и результата применения.
Выбор варианта и результат открываются через `AppModalFrame`; источник
состояния формы — `usePotionApplications` в контроллере обмена листа.

Применение зелий и связанных эффектов использует `ItemTransferAction` и `ApplicationSummary`. `SessionTransferApproval` открывает выбор конечной цели мастером и сбрасывает сохранение боя перед запросом. `EncounterAppliedEffects` отображает экземпляры NPC и подключает общий `StatusMechanicsMenu` через адаптер `npcApplicationContext`; отдельного меню правил яда для NPC нет. `StatusMechanicsMenu` также используется в меню состояния листа.

Цвет кубиков лечения — `var(--success)` (зелёный), временных хитов — `var(--info)`. Урон сохраняет цвет каждого типа из справочника. `DiceRollResult` берёт цвет части формулы, затем переданный цвет/`result.color`; хроника и уведомления событий передают сохранённый `data.color`. Тот же цвет используется в превью применения и результате, у лечения заклинаниями и костей хитов отдыха.

`NpcMarker` — общая цветная буква NPC (18 px, вес 850, `--font-ui`) для строки боя, хроники, уведомлений и выбора цели. В хронике перед именем используется снимок `data.npcActor {uid,name,letter,color}`; подпись автора под NPC скрыта. Инициатива, проверки/спасброски, броски хитов и броски из карточки/панели хода NPC сохраняют этот снимок в событии; фильтры различают экземпляры по uid. Записи, созданные до сохранения меток, сохраняют исходное текстовое имя: их исторический цвет неизвестен.

`TransferDecisionActions` объединяет кнопки принятия/отказа в хронике, событиях
листа и инвентаре сессии. `sessionEventTime` форматирует время в локальном календаре,
добавляя дату для других дней и год для других лет.
`SessionInventoryControl` — пункт правой колонки мастера и `BasePopover` с
`SessionInventoryRow`, штатными `ItemPickerModal`/`ItemViewModal` и формой своего
предмета на share-ui. Списки предметов и ожидающих передач контролирует
`useSessionInventory`: мутации API, повтор с тем же clientActionId, инвалидация
по SSE журнала, пакетная загрузка иконок, сброс контекста при смене сессии.
Хранение и резервирование находятся на сервере, локальный state не переносит
предметы между листами самостоятельно.

`SessionInventoryRow` использует общий `ObjectListItem`/`ContentRow` для листового
отображения предмета. Колонка имени сжимается с многоточием, кнопки передачи
и удаления имеют отдельную фиксированную область. `RowActionSubmenu` использует
публичный `mobileBreakpoint=0`, чтобы список получателей оставался floating
на телефоне и не растягивал строку.

`SessionTransferApproval` показывает цели одной колонкой quiet-кнопок с
48 px областью иконки персонажа/NPC; цветная буква NPC стоит перед именем. Под именем — текущие/максимальные хиты и временные при наличии. Нет изображения — стандартная иконка персонажа/существа, нет данных о хитах — «ХП: —». `SessionEventRow`
выделяет действия текстом 14 px и фиолетовой точкой: после сущности для одного
действия, в начале каждой строки для нескольких.

В `PotionDetailContent` формула лечения зелёная, временных хитов — синяя.
Описание передаёт предмет в `DndRichContent`: `richDiceColor` сопоставляет
вставную формулу с `usable.healing`/`temporary_hp`, и тот же цвет получают
кубики и уведомление броска. Другие формулы сохраняют свои цвета. Вставки dice,
hp и ac в `DndRichInlineNode` имеют одинаковую высоту 25 px и выравнивание
по середине строки.

`SessionHpBar` — единая строка здоровья для `SessionParticipantCard` и выбора
цели применения: `StatBar size="small"`, цвет по доле здоровья, временные хиты
отдельным сегментом и числа справа. Геометрия, цвета и расчёты общие; состояние
«При смерти» в карточке игрока остаётся отдельным.

Концентрация: `useSpellConcentration` управляет серверным состоянием и применением
эффектов к себе через общий цикл сохранения/обновления листа. `SpellConcentrationBlock`
стоит первым в магии и использует `HandbookReferenceRows`, без отдельного вида карточек.
`ItemTransferAction` объединяет применение на себя и выбор цели для зелий/заклинаний.
Описание в общем `ItemTooltip` и всплывающих rich-ссылках отображается размером 14px
с интерлиньяжем 1.55, в том числе у характеристик и навыков.

### Подменю применения заклинания

`SpellApplicationMenu` объединяет выбор целей, круг и расход ячейки, используя
`RowActionSubmenu`, `SpellCastControls` и общий `FormNumberInput` для числа целей
мастеру. `SpellLevelSlider` — доменный контрол девяти кругов: отметки на оси и крупный круглый бегунок, с перетаскиванием
и клавиатурой; отключённые сектора могут чередоваться с доступными. Число целей
берётся из `application_targets`, отдельной логики по ID заклинания нет.
`SpellCastControls` автоматически предпочитает доступную ячейку короткого отдыха
того же круга. Основное лечение исключено из `SpellRollMenu`: для него используется
`SpellApplicationMenu`, а условные отдельные броски остаются в меню.
`SpellConcentrationBlock` использует `MorphTile` и скрыт без концентрации.
Слот `leading` в `HandbookReferenceRows` предназначен для иконки/портрета цели
слева от строки эффекта. Имя цели показывается в подсказке.

### Бонусные кости в меню d20

`RollBonusOptions` показывает подходящие `roll_bonus` из общих зависимостей
персонажа, включая эффекты. Галочки включены по умолчанию, рядом отображается
формула общими компонентами кубиков. Снятие исключает правило только из текущего
броска; новый экземпляр меню снова включает его. Ключи исключений передаются
через меню атак оружием, заклинанием, проверок и спасбросков к `rollBonus`.
«Благословение» поэтому доступно для атак и спасбросков, но не для проверок.
Режимы применения оружия передают тот же выбор, включая последующий переброс.
`useDiceStore.rollD20` определяет критический результат исключительно по выбранному
основному d20. Единицы и максимумы бонусных костей не меняют критический результат;
преимущество/помеха используют оставленную кость и учитывают порог критического попадания.

### Справочные источники эффекта

`EffectSources` получает `data.application_sources` из уже загруженного эффекта;
отдельного запроса `effect-sources` при открытии нет. Строки отображаются через
`HandbookReferenceRows`. В редакторе типа 15 доступен раздел «Источники применения»;
`item_type` может содержать список типов для общего выбора записи.
Иконка эффекта хранится обычным ID изображения/символа, общим с исходным заклинанием.
`SpellScalingFormula` показывает плюс снаружи пунктирной рамки, а внутри — кости,
а подпись «за круг свыше N-го» расположена под рамкой. При регулярном шаге больше
одного используется «за каждые K круга свыше N-го».

`SessionSavingThrow` отображает характеристику, Сл и результаты в событии хроники.
`SaveTargetName` объединяет иконку, имя и цветную букву NPC; `sessionSaveRoll`
использует общие производные эффекты и правила доспехов. Выбор нескольких целей
доступен мастеру. Контракт: [спасброски заклинаний](features/spell-saving-throws.md).

В `SpellApplicationMenu` условная связь эффекта требует явного подтверждения
«Условия выполнены»; личные заклинания скрывают остальных адресатов. Связанные
эффекты догружаются для отображения их названий. `heal.apply=false` возвращает
обычный бросок формулы вместо непосредственного применения лечения.

### Результат применения урона

`DamageImpact` — общий компонент результата HP и эффектов в хронике, строке спасброска и истории NPC. `SessionImpactModal` выбирает цели/связанный эффект; `useEncounterImpacts` отправляет точечный и массовый урон одним атомарным запросом. Оба пути используют `/sessions/{uuid}/impacts`. Компоненты модального применения и истории загружаются лениво. [Описание](features/session-damage.md).

В выборе целей хроники `SaveTargetName` с `iconSize=56` и `showHp` использует общий `SessionHpBar` из колонки игроков. Строки результатов сохраняют компактное отображение.

`SessionTargetPicker` — единое модальное окно выбора целей для
`SessionImpactModal`, `SessionSavingThrow` и `SessionAttackTargets`.
Оно принимает `targets`, выбранные ключи через `v-model`, блокировки, состояния
загрузки/ошибки и слоты контекста/подписи цели/кнопок. Все три сценария показывают
иконки 56 px и `SessionHpBar`, включая NPC с цветной буквой. Загрузка механик
спасброска и сохранение конкретного действия остаются в соответствующей фиче.
`SessionAttackTargets` сохраняет выбор в событии через API; цели видны в хронике мастера,
права доступа к событиям не расширяются. Сравнения атаки с КД в этом компоненте нет.

`SessionParticipantCard` shows only portrait, name and HP, with 14px right padding.
Its combat strip contains a checkbox with wider side spacing; AC and initiative
are not rendered in that strip. DM menus use lazy `ParticipantMenuStats` for D&D
characters, backed by `participantDefenses`, the shared equipment/derived-effect
calculators, and item hydration including magic armor bases. `EncounterInitiativeMenu`
is shared with creature rows and shown before combat starts.
`handleCtrlSelection` is the shared capture handler for the participant rail,
`EncounterRow` and `SessionTargetPicker`; macOS Ctrl-contextmenu also toggles once.
Drag starts ignore Ctrl and Cmd. Disabled selection and ordinary clicks keep their behavior.

Participant menu indicators are a single row of number/icon pairs with vertical
dividers. Hover and keyboard focus open the shared `ItemTooltip` for the name,
meaning and passive calculation. The player rail uses `--participant-rail-width`
(264px), `--participant-selection-width` (36px) and `--participant-card-gap` (9px).
Combat adds exactly the selection width plus gap; graph safe-area offsets use the
same sum. The checkbox strip has 10px left / 2px right padding, so the original
name/HP area retains its width as the rail expands.

`CompactCheckbox` from share-ui 0.24.0 exposes `size` (default 18px); encounter, participant and target-selection rows pass 20px. Base geometry stays in the library. `ItemTooltip` forwards an optional `zIndex` to FloatingTooltip, retaining 4000 by default; participant menu descriptions use 9500 above the menu and submenus.

`ArmorClassChip` is the shared session AC presentation (number then blue shield). `SessionHpBar.size` defaults to small; target pickers pass medium with decoration. `loadSessionTargets` hydrates the same character/NPC snapshots for attack, impact and saving-throw pickers and calculates AC with shared armor/effect rules. `SaveFormulaPreview` renders d20 mode, fixed bonus and extra dice from `sessionSaveProfile`; no second bonus calculation is maintained. The picker uses CompactCheckbox at 20px, including Ctrl/Cmd row selection. `ActionButton` dashed styling belongs to share-ui 0.25.0.

`SpellMetadata` и `ActionTiming` — предметные компоненты отображения параметров
заклинаний/действий. Редакторы используют общий `ActionTimeEditor` на FormField,
FormSelect и FormTextInput; произвольные значения времени сохраняются явно как
custom. Форматирование времени и дистанции находится в `shared/lib/spellPresentation`.

Короткие таблицы в `DndRichContent` занимают ширину содержимого, без
минимальной ширины внешнего блока: иначе рамка и фон выходят за сетку ячеек.
На узком экране сохраняется горизонтальная прокрутка самой таблицы.

Скалярные поля справочника `type: item` по умолчанию сохраняют числовой ID.
Если runtime требует объект-ссылку, схема задаёт `reference_shape: object`:
`normalizeDataForSave` записывает `{id}` и убирает временные поля выбранной
карточки. Это используется ссылками на эффекты применения, последующий эффект
и связанное заклинание `usable`. Новые схемы должны явно соответствовать
формату серверного обработчика; тест редактора проверяет сохранение формы ссылки.

`StatusRepeatSaveMenu` — общий пункт действий активного эффекта для листа и
НПС. Он использует `D20RollControls` и общий профиль спасброска; `RollOutcomeNote`
показывает одинаковую подпись результата у костей уведомления и хроники.

Меню листа персонажа использует `CharacterMenuPopover` поверх общего
`BasePopover`: локальная часть ограничивает размер содержимого и управляет
фокусом, общая библиотека отвечает за портал, позиционирование и закрытие.
Выбор редакции использует `ActionMenuItem`, `AppModalFrame`, `ConfirmDialog`
и общие эмблемы систем, без отдельного набора базовых контролов.

`RaceAbilityList` — общий предметный список расовых способностей для мастера
создания и справочника. Он объединяет `BaseTile`, существующий `ObjectListItem`
и `ItemViewModal`; показывает уровень получения каждой способности.
`RaceVariantPicker` использует `BaseTile` и `ContentRow` для выбора происхождения
и размера: преимущества, пояснение роста и независимое раскрытие правил.
Это композиция общих примитивов для правил расы, без отдельного базового контрола.
`IllustratedChoiceStage` размещает кнопку возврата справа от заголовка шага
для расы, класса и предыстории; восстановление прокрутки остаётся общим.

`RaceSubracePicker` объединяет существующие `SubraceSelectCard` и
`RaceAbilityList`: карточки подрас находятся внутри выборов расы, под ними —
описание и способности только выбранной подрасы. `RaceAbilityList` поддерживает
подпись секции; описания способностей открываются в справочном окне, без
повторного текста под плиткой. Описание подрасы под карточками показывается
только если отличается от уже видимого краткого текста выбранной карточки. Общие способности и способности подрасы
фильтруются существующей функцией `featuresForBinding`.

`RaceAbilityList.hideChoiceOnly` исключает повторные плитки правил с
`data.choice_only` из визарда; сами источники выборов и их механики сохраняются.
Повышение уровня так же скрывает только строку способности, сохраняя выбор.
`RaceSpellList` строит один список `HandbookReferenceRows` по `granted_spells`,
объединяет одинаковые ID по самому раннему уровню и использует пакетную загрузку
существующего компонента. Описание и заклинания меняются с выбранной подрасой.
Уровень выдачи находится слева от плитки («С n-го уровня»), включая мобильную
версию: используется слот `leading` и `--handbook-reference-leading-width`
общего списка. Подпись под плиткой не дублируется. В шаге расы общий список
заклинаний убран: они доступны в справочном окне способности. Под выбранным
наследием остаётся раскрытый список; три способности магии тифлинга имеют
`choice_only`, поэтому визард не повторяет их отдельными плитками.
Фильтрация landing через `visibleHandbookType` не затрагивает общий store типов,
чтобы подрасы/подклассы оставались доступны в визарде и по прямым ссылкам.

Справочное окно способности также показывает эти плитки заклинаний; вложенное
окно получает `nestedViewZIndex`, чтобы открываться поверх текущего.

`RaceVariantPicker` читает иконку и цвет `damage_type` из общего suggest-store
(тип 12) и использует `SvgIcon`. Выбранное происхождение сохраняет иконку урона;
состояние выбора видно по рамке и подписи. Сопротивления выбранного варианта
копируются движком выдачи в `values.defenses` с устранением одинаковых записей.
