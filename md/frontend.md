Актуальная реализация — Vue 3, Composition API, Pinia, vue-router и Vite 8 в
`frontend/`. Старого Vue CLI, webpack, Axios и серверных JSON-шаблонов листа в
проекте нет.

## Запуск и проверка

```bash
cd frontend
npm install
npm run dev
npm test -- --run
npm run build
```

Vite работает на `:5173` и проксирует `/api` и `/mcp` в Go-приложение на
`:8080`. Production-сборка попадает в `frontend/target/dist`; Go-бэкенд вшивает
её в бинарь. Для неизвестного клиентского пути Go возвращает `index.html`, а
`/api/**` и `/mcp` никогда не попадают в SPA fallback.

Эмблемы коллекций и изображения истощения/вдохновения загружаются по URL из
`storage_image` в S3; frontend их не содержит. Иллюстрации игрового цикла
остаются частью frontend в WebP (качество 85), а маски игровых систем используют
lossless WebP с теми же RGBA-пикселями, что у прежних PNG. Favicon и Apple touch
icon сохраняют PNG/ICO. Обычные JS/CSS и их gzip-копии по-прежнему встраиваются
вместе; разделение страниц отключено.

## Границы кода

- `src/app` — router, тема и корневая композиция.
- `src/features/<feature>` — страницы, компоненты, composables и API конкретной
  предметной области.
- `@sylvieshare/share-ui` — общие для DnD Share, HavenShare и TrenchShare
  theme-токены, UI-примитивы и headless interactions. Пакет подключается одним
  публичным import API без deep imports.
- `src/shared/api` — общие HTTP-клиенты. `http.js` основан на `fetch`; любой
  non-2xx ответ является ошибкой.
- `src/shared/ui` — переиспользуемые компоненты уровня DnD Share. Компонент
  остаётся здесь, если знает о router, Pinia, HTTP API или доменной модели.
- `src/shared/composables` — поведение, не привязанное к одной фиче.
- `src/stores` — Pinia-кэши и глобальное состояние.

Новый или изменяемый Vue-компонент пишется через `<script setup>`. Правила
композиции вынесены в [Composition API](composition-api.md).

## CSS

Общая палитра и canvas приходят из `@sylvieshare/share-ui/styles.css`, который
импортируется один раз в `main.js`. `src/app/theme.css` задаёт DnD-акцент,
layout, доменные цвета и продуктовые prose/mono/print font stacks. Cormorant
Garamond и Literata подключаются как variable web fonts; display-роль не
запрашивает веса выше поддерживаемого `700`. `npm run check:colors` входит в production build и
запрещает новые прямые hex/RGB/HSL значения. Подробности — [CSS-токены](css-variables.md).

## Анимации и переходы

Изменения интерфейса по умолчанию сопровождаются анимациями и плавными
переходами. Появление и закрытие окон, смена выбранного элемента, переключение
вкладок, изменение размеров и перемещение индикаторов не должны выглядеть
резкими скачками. Сохраняем визуальную связь между состояниями: рамка окна
остаётся на месте при смене содержимого, направление движения соответствует
порядку вкладок. Используем существующие компоненты и механизмы переходов.

Анимация должна быть короткой и не задерживать действие, изменение данных
или сохранение. Повторное действие продолжает либо заменяет текущий переход;
быстрые переключения не показывают устаревшее состояние. Исчезающие элементы
сразу перестают принимать ввод. При `prefers-reduced-motion: reduce` движение
и вспышки отключаются, интерфейс сразу показывает итоговое состояние.

## Политика изменений контракта

Runtime поддерживает только текущий контракт. Если изменение ломает старый
формат, нужно:

1. подготовить и явно выполнить преобразование данных через MCP или отдельную
   операцию; в `internal/store/schema/*.sql` добавлять только необходимый DDL;
2. переключить все producer/consumer на новый формат;
3. удалить старые поля, ветки чтения, aliases и временные admin jobs;
4. обновить `md/` и тесты.

Сохранение двух форматов «на всякий случай» не допускается.

## Производительность и владение общим UI

В исходниках router и `defineAsyncComponent` сохраняют динамические импорты,
но production Vite отключает разделение JavaScript (`codeSplitting: false`)
и CSS (`cssCodeSplit: false`). Вся сборка загружается сразу одним JS и одним
CSS с хэшами содержимого, включая страницы, редакторы, галерею UI, Three.js и Meshopt-декодер.
Переходы и открытие компонентов не запрашивают дополнительные чанки: после
deploy открытая вкладка продолжает использовать уже загруженный код.
Первичная загрузка больше, чем при разделении страниц. `npm run build`
проверяет один JS/CSS приложения, отсутствие дополнительных чанков страниц
и лимит 1 355 000 Б gzip. Отдельные Basis worker JS/WASM для KTX2 загружаются
по необходимости; для них действует собственный лимит 270 000 Б gzip. Не увеличивать
бюджет вместо разбора регрессии. Методика и измерения —
[frontend performance](frontend-performance.md).

Предпросмотр параметров моделей карт добавляет к общему frontend около 7 КиБ gzip. GLB-загрузчик и Three.js повторно
используются из редактора карты; OrbitControls и дополнительные runtime chunks
не добавляются. Текущий лимит начального bundle — 1 355 000 байт gzip.

Глобальные карты сессии используют SVG и существующие Vue/UI-примитивы без
новых зависимостей. Замер чистого исходного commit перед фичей: 1 303 195 Б gzip;
добавление рабочего места карт, маршрутов и точек — около 11 КиБ gzip. Лимит
увеличен на 15 000 Б до 1 325 000 Б; правило одного JS/CSS и отдельный бюджет
Basis worker сохраняются.

Превью области на существующем GPU, процедурный туман, кнопка цвета share-ui
v0.34.0 и изменения фокуса добавили около 3,4 КиБ gzip: 1 324 003 → 1 327 434 Б. Новых зависимостей, декодеров и runtime-чанков нет.
После проверки графа импортов бюджет увеличен на 5 000 Б до 1 330 000 Б.

Объёмный туман добавил около 3,3 КиБ gzip: 1 327 434 → 1 330 762 Б.
Использованы существующие Three.js и WebGL2, без новых зависимостей и файлов
моделей. Основной проход цвета/глубины дополнен расчётом плотности в половинном
разрешении и смешиванием; без активного тумана остаётся прежний прямой render.
После проверки графа импортов бюджет увеличен на 5 000 Б до 1 335 000 Б.

Плавные переходы областей/света, общий заголовок инспектора с InlineEdit и удаление
поверхностного тумана изменили сборку с 1 330 762 до 1 332 988 Б gzip (около
2,2 КиБ). Новых зависимостей нет; бюджет 1 335 000 Б сохранён.

Первоначальный прототип анимации огня MT1-016 с экспериментальным ползунком FPS изменил чистую сборку с
1 333 204 до 1 335 371 Б gzip (около 2,1 КиБ). Проверены граф импортов и
сборка без посторонних локальных правок: используются существующие Three.js
и AppSlider, новых зависимостей, текстур и runtime-чанков нет. После этого
бюджет увеличен на 5 000 Б до 1 340 000 Б; бюджет Basis worker сохранён.

Текущая анимация огня фиксирована на 12 FPS. Ползунок и сохраняемая настройка
частоты удалены; камера и свет сохраняют собственные часы обновления.

Промежуточная схема с отдельными флагами и эффектами огня изменила сборку с 1 334 399 до 1 341 322 Б gzip
(около 6,7 КиБ). Проверены граф импортов и сборка относительно чистого исходного
коммита: используются существующие Three.js и share-ui, геометрия огня строится
кодом, новых зависимостей, текстур и runtime-чанков нет. После измерения бюджет
увеличен на 10 000 Б до 1 350 000 Б. Отдельный бюджет Basis worker сохранён.
