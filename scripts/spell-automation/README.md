# Аудит автоматизации заклинаний

Скрипты рассчитаны на полный JSONL-снимок системного каталога: строки
`{"kind":5,"items":[...]}` и `{"kind":15,"items":[...]}`. Загружать справочник
постранично через `handbook_items` (limit 500), включая все страницы.

1. `python3 prepare.py snapshot.jsonl /tmp/spell-plan` — подготовить изменения,
   эффекты и поэлементные ограничения; исходные описания не меняются.
2. Проверить `plan.json`, `effects.json`, `follow-up.json`. `effects.py` содержит
   явные механические определения, `saves.py` — дополнительно проверенные
   спасброски. Автоматический поиск формулировок остаётся консервативным.
3. `python3 apply.py /tmp/spell-plan` — dry-run через MCP: проверка конфликтов
   исходных данных и метаданных. Каталог не изменяется.
4. После выпуска требуемого runtime: `python3 apply.py /tmp/spell-plan --apply`.
   Требуются `MCP_AUTH_TOKEN`, включённая запись и, при необходимости, `MCP_URL`
   (по умолчанию localhost:8080/mcp). Токен никогда не выводить и не сохранять
   в артефактах. Каждый результат записи перечитывается.
5. `python3 report.py /tmp/spell-plan ../../md/data/spell-automation` — таблицы
   статусов и ID эффектов из фактического `applied.json`.

При конфликте изменения не перетирать: обновить снимок и проверить разницу.
План можно повторно применить после частичного выполнения: эффекты ищутся по
стабильному `code`, уже установленные значения принимаются. Во время применения
создаваемые этим планом эффекты не редактировать параллельно.

Проверка границ: `python3 -m unittest discover -s scripts/spell-automation` из
корня репозитория. Отчёт об ограничениях: `md/spell-automation-audit.md`.

`catalogue_design.py SNAPSHOT_DIRECTORY OUTPUT_DIRECTORY` принимает полные
`after-5.json` и `after-15.json`, создаёт поэлементный CSV/JSON для всех редакций
и сводку. Проверяет обязательные поля, характеристики спасбросков, типы урона,
наличие эффектов и обратных ссылок. Направления расширения по текстовым признакам
не меняют статусы и не считаются ручной проверкой правил. Подробное проектирование
отдельно: `reports/spell-automation/architecture-proposal.md`.

Пакеты после первичного аудита применяются через `review/apply.py`, за исключением
рецептов `item_creation.py` и повторных спасбросков `repeat_saves.py`. Перед записью
всегда нужен runtime соответствующей миграции, preflight и независимое перечитывание.
Имена совпадающих предметов разных редакций различаются по native-совместимости,
не по добавлению года в видимое название.
